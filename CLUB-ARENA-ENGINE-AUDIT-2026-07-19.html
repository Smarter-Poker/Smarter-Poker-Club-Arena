Executive summary

The engine is genuinely server-authoritative and, at the per-hand level, close to PokerBros/ClubGG grade: the action timer, betting-round termination, side-pot math, hand evaluation (incl. Omaha and short-deck), rake caps, sit-out/leave sequencing, and the WebSocket transport are all well-built and heavily iterated. The client-side authoritative engine was genuinely removed — the client is a rendering terminal.

The real problems cluster at the boundaries: authentication, funding, a few money-math edges (uncalled bets, all-in-from-blinds, Run-It-Twice, insurance), dealer-button rotation, and the snapshot→UI mapping. Five independent deep-audit passes (betting rules, pot/showdown math, timers/seating/lifecycle, client contract, and a full test baseline) produced ~40 findings; the most severe were personally re-verified against the code before any change.

This session fixed and tested the highest-confidence, well-contained issues — including the two most dangerous security holes — and stopped short of rushing the remaining money-math changes into a live, real-stakes engine. Those are documented below with exact locations and recommended fixes for a careful, deploy-gated follow-up.

What was fixed (this session)

All server changes are on the branch and pass 134/134 server tests + tsc clean + sim green. Deploy status per item.

CriticalFixed + testNeeds Hetzner deployUnsigned-JWT acceptance → full account impersonation
Where: server/src/http/auth.ts

The "local-decode fallback" trusted a JWT's own sub/exp claims without verifying the signature. A forged token header.{"sub":"<victim>","exp":9999999999}.x was accepted on every request (it never entered the cache, so it always took the unverified path) — enabling reading any player's hole cards via GET /state, folding/cashing-out victims, or minting chips. Removed the unsigned path; tokens are now GoTrue-verified before trust, with a 60s cache + single-flight so the hot path stays one round-trip. New auth.test.ts proves a forged token is rejected.

CriticalFixed + applied liveHole-card table hardening (hand_state_snapshots)
Where: supabase/migrations/20260719_hand_state_snapshots_rls.sql — applied to prod DB

The crash-recovery table persists full hand state (incl. every player's hole cards) after each action. Prod already had RLS + a service-role-only policy (the live read-hole-cards hole was already closed), but the repo migration didn't reflect it. Added FORCE ROW LEVEL SECURITY + revoked anon/authenticated grants (defense in depth) and fixed the save_hand_state_snapshot upsert to refresh hand_number on conflict (a stale-void recovery bug). Verified live: relforcerowsecurity=true, anon/auth SELECT = false.

CriticalFixed + testNeeds Hetzner deployUncalled bet was raked
Where: HandController.completeHand → new returnUncalledBet()

The uncalled portion of a final bet stayed in state.pot, so rake and the BBJ fee were charged on the bettor's own returned chips (bet 100 into a 20 pot, all fold → raked 120, not 20), and the payout scaling shaved rake off the refund. Now the uncalled amount is returned to the bettor before pots/rake are computed — the textbook rule — making rake, side pots, and chips-in-front all correct at once. Test asserts rake = 5% of the contested $20 (=$1), not $120.

CriticalFixed + testNeeds Hetzner deployAll-in blind poster auto-folded / everyone-all-in hand hung
Where: HandController.setNextPlayer / start → new nextActionableSeat()

The preflop first-actor branch didn't skip all-in players, so a short all-in SB/BB was handed the turn and then auto-folded on timeout — forfeiting pot equity. And when the blinds put everyone all-in, start() emitted a no-op turn and the hand hung until the 10-minute safety void (blinds effectively refunded). Both now route through a shared next-actionable-seat helper; the all-in-from-blinds case advances straight into the board runout. Tests cover both.

HighFixed + testNeeds World Hub syncClient: blinds invisible, BB shown "Call" instead of "Check", wrong call sizes
Where: src/utils/mapEngineSnapshot.ts

The mapper derived per-seat "chips in front" purely from action_history, which never contains blind/straddle posts, and dropped the authoritative players[].bet the engine publishes. So blind posters showed $0, the BB's toCall math was wrong (Call instead of Check), and call amounts mis-sized. Now mapped from players[].bet. Tests added.

HighFixed + testNeeds World Hub syncClient: raise slider committed more chips than shown
Where: src/pages/TablePage.tsx (ActionPanel wiring)

The engine's min_raise is a raise increment (max(BB,lastRaise)); the ActionPanel treats its minRaise/maxRaise props as raise-to absolute amounts (matching the engine, whose raise floor is currentBet + min_raise). Passing the bare increment made the slider bottom out below the current bet, so confirming silently committed the server-clamped amount — more than the button showed. Now passes raise-to values (floor = currentBet + increment; all-in-to = stack + bet; PLO pot cap matched to the engine).

HighFixed + testNeeds World Hub syncClient: side-pot eligibility never rendered
Where: src/utils/mapEngineSnapshot.ts

pots[].eligible holds user-ids; the client treated them as seat numbers, so the seat lookup always missed and side-pot eligibility rendered empty in multi-way all-ins. Now resolves user-id → seat.

HighFixedNeeds World Hub syncFresh/CI builds shipped a table wired to nothing
Where: src/pages/TablePage.tsx, .env.example

VITE_USE_ENGINE_WS defaulted OFF; any build without the gitignored .env setting it to 1 connected to no game-state source (seats loaded, but no hand state/timers/action echo). Now defaults ON (only =0 opts out) and documented.

Test infraFixed49 uncollectable handler tests + 1 stale assertion
Where: server/src/services/supabase.ts, TableStateHub.test.ts

supabase.ts called process.exit(1) at import when the service-role key was absent, aborting the whole handler suite; now skipped under the test runner with a placeholder key. Corrected the stale TableStateHub no-op-seq assertion to match the deliberate Round-25 reconnect-FSM fix. Server suite went 78 → 134 passing.

Open findings (verified — recommended follow-up)

These are real and located, but are money-math/lifecycle changes on a live real-stakes engine that deserve their own careful, tested, deploy-gated cycle. Ordered by severity. Note: with the JWT hole closed, the exploitable-by-anyone surface is largely shut; most items below require being an authenticated seated player or specific game states.

Critical/addchips mints chips — no wallet debit
Where: handlers/addchips.ts → ServerTableEngine.addChips / _applyAddOnImmediate

Between hands, a seated player can POST /addchips {amount} and the engine adds it straight to the stack and table_seats.stack with no wallet/club-balance debit and no max-buy-in cap on the immediate path. The queued path's "refund" also credits club_members.balance with never-debited chips. Fix: debit via an atomic RPC (atomic_table_rebuy exists) before crediting the stack, enforce stack + amount ≤ max_buy_in on both paths, and only refund amounts actually debited. Highest-priority open item.

CriticalRun It Twice destroys the entire pot
Where: ServerTableEngine.dealAndResolveRIT (~:3451) reads handController.getPots()

getPots() returns [] until completeHand() runs, but RIT resolves before it. The distribution loop iterates zero pots → nobody is credited; the stacks are debited but the pot is never paid. StateVerifier then logs a chip-conservation critical but doesn't repair it. Additionally RIT credits rake to the club without collecting it, and ignores PLO8 low and short-deck rankings. Any table with RIT enabled + an accepted offer confiscates the whole pot today. Fix: compute pots before RIT distribution; deduct rake once from the pot before per-board split; evaluate each board with the table's variant rules.

CriticalInsurance is exploitable / non-functional
Where: ServerTableEngine (~:3689) + InsuranceEngine + MonteCarloEquity

Multiple compounding bugs: only the leader is passed in → numOpponents = 0 → equity computes as 100% and full-pot coverage is offered for a $0 premium; accepting with ≥2 cards to come is silently erased by an unconditional dispose() on the next street; premiums are priced against random opponent hands rather than the known all-in hands; and the "chop = push" check treats an uncalled-bet return as a pot win and voids coverage on exactly the unequal-stack all-in insurance exists for. Fix requires reworking offer lifecycle + equity inputs together; keep insurance disabled on live tables until then.

HighDealer button tracked by array index, not seat
Where: ServerTableEngine ~:2326 (dealerSeatIndex % players.length)

The button is an index into the mutable per-hand roster, so a bust/leave/join can move it backward, skip seats, or make the same players post the BB twice / never. No dead-button handling. Fix: track the button by seat number and advance to the next occupied seat clockwise (PokerBros moving/dead-button rules). Also fix getBBSeatIndex to use the same roster that is actually dealt (wait-for-BB release can fire on the wrong hand).

HighReconnect during disconnect countdown leaves no timer → stall/void exploit
Where: ServerTableEngine.handleTurnChange + DisconnectEngine

A disconnected player whose turn arrives gets no turn timer (only the 30s disconnect countdown); a single heartbeat cancels that countdown without arming a turn timer. The hand then freezes until the 10-minute void, which nulls the controller without settlement — a losing player facing a big river bet can void the hand and reclaim their stack, repeatably. Fix: on reconnect during one's turn, start the normal action timer (or let the countdown keep running until they act).

HighSettlement races player leave → winnings lost / losses refunded
Where: ServerTableEngine leave path vs postHandTasks/syncStacks

At HAND_COMPLETE the controller is nulled while syncStacks runs async. A /leave in that window cashes out the stale pre-hand stack and sets left_at, so the pot vanishes (or a bust is refunded). Fix: await postHandTasksPromise before cashing out, or cash out from the settled in-memory stack.

HighTournament rebalance / chip-race move players & write stacks mid-hand
Where: GameServer.executePlayerMoves (~:2764), chip-race (~:1593)

Table-break moves run before waitForHandComplete; gap rebalance moves never wait at all. A player who wins a pot on the source table arrives at the new table with their pre-pot stack (the winnings evaporate). Chip-race writes stacks mid-hand that the next syncStacks overwrites. Fix: execute seat moves and chip races only between hands on the source table, mutating engine-authoritative stacks.

HighPost-break blind level-up swallowed; no auto-sit-out for AFK players
Where: GameServer.resumeFromBreak (~:982); DisconnectEngine timeout counting

After a synchronized break, the level-up increments the counter without writing new blinds / emitting level_up, and can freeze progression entirely deep in a structure. Separately, a connected-but-AFK player is never auto-sat-out (consecutive timeouts are only counted on the disconnect path), so they're blinded down forever and slow the table; nothing auto-removes a long sit-out either. Fix: reuse the normal level-transition routine on resume; count timeouts on every expiry path → auto-sit-out; auto-stand after N idle minutes.

High10-minute hand-timeout leaks the event listener
Where: ServerTableEngine ~:2469 (timeout path doesn't unsub())

On the safety timeout the controller is nulled but the HAND_COMPLETE listener isn't removed and pending horse timers aren't cancelled; a late completion can null the next live hand's controller, orphaning it. Fix: unsub() + cancel pending timers on the timeout path.

MediumRules/label edges & auto-muck leak
  • Auto-muck defeated: the showdown_cards_revealed event broadcasts every non-folded showdown hand to the whole table, bypassing the winner/voluntary/auto-muck gating used elsewhere. (ServerTableEngine ~:2791)
  • Min-raise over a straddle is 3×BB instead of 4×BB (lastRaise not updated when the straddle is posted). (HandController ~:244)
  • Short all-in BB lowers the whole table's price of entry and min-raise base (currentBet = min(BB, stack)). (HandController ~:190)
  • Betting not re-restricted: after a short all-in that doesn't reopen, a player who already acted may still submit a full re-raise (validator has no reopen check). (ServerActionValidator)
  • 3-handed position labels show SB/BB swapped vs the blinds actually posted. (ServerTableEngine ~:4589)
  • Post-BB-to-enter charges a dead SB on top of the live BB. (ServerTableEngine ~:1474)
MediumClient rendering edges
  • Dealer button double-rotated: renders at the wrong seat when the hero isn't physical seat 1. (DealerButton / TablePage seat mapping)
  • POT_WIN animation off-by-one: winner particles/chips fly to the seat next to the actual winner. (TablePage ~:4174)
  • Stale hero hole cards can persist across hands if a realtime insert is dropped (poll stops after first success; HAND_STARTED doesn't clear hero cards). (TablePage)
  • Optimistic call flicker: records the full bet level rather than the incremental call, so the chip count jumps after the echo. (TablePage ~:4838)
LowMinor / hardening
  • Duplicate-action suppression is defeated (dedup key includes a server timestamp) — relies on the 250ms rate limit.
  • Deck.shuffle uses modulo-biased indices (~2⁻³²) while an unbiased secureRandomInt exists in CryptoRandom.ts — negligible but should use the unbiased path.
  • AtomicStackService versioned settle results are computed but only logged, not enforced.
  • Crash recovery marks incomplete hands complete and starts fresh (no true resume); DeadlineScheduler.rehydrate has no callers.
  • The old server test-engine-math.mjs expects rake truncation; the engine intentionally rounds (documented). Stale test, not a bug.
  • ~33 client unit tests fail on pre-existing deleted-service imports / emoji-removal assertions (e.g. tableService.subscribeToHand) — test debt unrelated to gameplay.
