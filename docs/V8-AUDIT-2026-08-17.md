## 3. Card security — fixed and verified

### 3.1 `hand_history` stored mucked hole cards (FIXED — PR #88 + #89)

`currentHandShowdownResults` is built on the `SHOWDOWN` event from **every**
participant, before winners are known. It is a full evaluation set, not a reveal
set. `logHandHistory` fanned it into three columns of one row — `hole_cards`,
`dispute_review.showdown_results`, `player_summaries`.

RLS policy `hand_history_authenticated_select` lets any authenticated user SELECT
any row where their own id appears in `players`. So **any player could mine every
opponent's mucked holdings for any hand they were dealt into.**

Measured before fix: **2,706 rows carrying 3,953 losing players' hole cards in one hour.**

The broadcast path already had the correct gate (`AUDIT FIX 2026-07-19`).
`handHistory.ts` even documented the correct policy above its own loop
("Mucked cards are deliberately never stored") and did not implement it.

**Fix:** apply the same gate — winner ∨ voluntarily showed ∨ `auto_muck_enabled === false` —
to the array passed to `logHandHistory`.

**Regression (PR #89):** the first fix read `currentHandWinnerIds`, which
`postHandTasks` (fired **without await**) guarantees is `[]` by the time the write
runs — the very next synchronous line is `this.currentHandWinnerIds = []`. It
filtered out everything, including winners. Corrected to read
`currentHandWinners`, which survives to that point.

|            | non-winner holdings | winner holdings    |
| ---------- | ------------------- | ------------------ |
| Before #88 | 3,953 /hr           | stored             |
| After #88  | 0                   | **0** ← regression |
| After #89  | **0**               | **100** ✓          |

### 3.2 Investigated and NOT defects

- **`getObserverState()`** — gates on `tableInfo.observer_show_cards`, which is
  **not a column on `tables`**. Permanently undefined; the path never fires.
- **`hand_state_snapshots.state_json`** — does carry every seated player's live
  hole cards (1,558/1,558 rows in 10 min). Contained: RLS enabled **and forced**,
  service_role-only policy. Crash recovery legitimately needs full state.
  **Do not "fix" this** — stripping the cards breaks mid-hand restore.
- **`seven_deuce_bounty`** reveals hole cards on fold-around wins. Intentional
  game rule; should be recorded as a sanctioned exception rather than left implicit.
- **`bbj_hit`** broadcasts raw `EvaluatedHand` objects (which carry `cards`).
  Low severity — a BBJ requires a showdown — but it is an ungated card payload.
  **Open.**

## 4. Engine lease — fixed and verified (PR #90)

`conflicts` in `tableLease.ts` was only ever written; there was no
`conflicts.delete` anywhere in the file. A table refused a lease once stayed
refused for the life of the process, because with enforcement off `claimTable()`
still returns `true`, the table starts, enters `tableEngines`, and the discovery
loop skips it forever.

Observed after the #74 cutover: **4 tables dealing with no lease, `conflictCount`
pinned at 4** — corrupting the exact signal used to decide whether
`ENGINE_LEASE_ENFORCE` can be turned on.

**Fix:** `retryRefusedClaims()` re-attempts refused claims each discovery tick and
retires the conflict record when the lease is held. Grant is detected by side
effect (claimTable rewrites the entry's `at` on refusal, leaves it untouched on grant).

**Verified:** 63 tables dealing / 63 leases held / **0 dealing without a lease.**

`ENGINE_LEASE_ENFORCE` remains **off**. The telemetry is now honest enough to
make that decision on real numbers.

## 5. OPEN — needs a product decision (1.2.3 / 1.2.4)

The Bible says the broadcast is awaited before the turn timer arms. The code
deliberately inverted this ("Arm first, deliver after") **and**
`broadcastCurrentState()` returns `Promise.resolve()` over a synchronous
`hub.publish` — so FIX-217's "Supabase acknowledged" guarantee is void. The
`await` yields one microtask and confirms nothing.

This is code-versus-spec on live turn timing at a real-money table. Two options:

1. **Amend the Bible** to match the code, and delete the misleading `await` and
   the FIX-217 comments so nobody trusts a guarantee that does not exist.
2. **Restore the ordering** and make `broadcastCurrentState()` genuinely await
   delivery.

Recommendation: (1), because the inversion was deliberate and has been running in
production, and because the fiction in the code is the more dangerous half. But
this is Dan's call, not the agent's.

## 6. PARTLY FIXED — reconnect grace (1.7.5, PR #95)

`reconnectedAt` is re-stamped on every heartbeat-driven reconnect with no
per-turn flag, and the rearm restarts the clock at full `actionTime + 5` while
also resetting `timeBankActivatedThisTurn`.

Go stale ~30s, reconnect, get a fresh ~22s clock plus a re-armed time bank,
repeat. One turn stretches to ~45–55s, bounded only by the unrelated stall
watchdog.

**Fixed (PR #95):** `timeBankActivatedThisTurn` is now preserved across the
re-arm, so a reconnect no longer hands back the time bank.

**Deliberately NOT changed:** the action clock still re-arms. AUDIT FIX
2026-07-19 added that re-arm to close a griefing bug where a reconnecting player
had _no timer at all_ and the hand hung to the 10-minute void. Suppressing it
would be a worse failure than a stretched turn.

**Residual, still open:** a player can still refresh the action clock by
reconnecting. Fully bounding it needs a per-turn identity (hand + seat +
betting-round instance) that does not exist in the engine today; adding one
touches the core turn loop and should not be done speculatively.

## 8. FIXED — the schema manifest now refreshes itself (PR #92/#93/#94)

`scripts/ci/supabase-schema-manifest.json` went stale **three separate times in
one session**, each blocking CI:

1. `claim_table_lease`, `heartbeat_table_leases`, `release_table_leases` (PR #74)
2. `engine_recovery_events` (PR #88)
3. `vip_feature_usage_monthly`, `fn_use_throwable` (PR #90)

Each was hand-patched to unblock. Drift at that point: **9 tables and 46
functions behind live** (762/1688 in the manifest vs 771/1734 live).

`fn_schema_manifest()` **already exists in production**, so
`scripts/ci/gen-schema-manifest.mjs` was runnable all along. It was simply never run.

**Fixed (PR #92, hardened in #94):** `Schema Manifest Refresh` runs the existing
generator daily and opens a PR on drift. `SUPABASE_URL` and
`SUPABASE_SERVICE_ROLE_KEY` were **already** repo secrets, so no new config was
needed.

Its first run found **57 genuinely missing names** — the whole accumulated drift,
closed in one pass (PR #93) instead of one name at a time.

That run also surfaced a real constraint: `gh pr create` fails because
**Settings → Actions → General → "Allow GitHub Actions to create and approve
pull requests"** is disabled. PR #94 makes the job fall back to a job-summary
link and exit 0, so it works either way — a scheduled job that goes red daily is
a job people learn to ignore.

Related: adding `vip_feature_usage_monthly` to the manifest surfaced a
stranded-writer failure, because its writer is the SECURITY DEFINER function
`fn_increment_vip_usage` — i.e. it lives in the database, where a repo-scanning
check cannot see it. Allowlisted with that reason.

## 9. FIXED — the auto-muck gate is now tested (PR #91)

Both the original leak (§3.1) and the #89 regression reached production without
CI noticing, because nothing asserted what `hand_history` stores.

The predicate is now `server/src/engine/revealedShowdown.ts` — a pure exported
function — with 8 cases in `revealedShowdown.test.ts`:

- winner's holding **is** stored
- mucked loser's holding is **not** stored
- voluntarily-shown holding **is** stored
- `auto_muck_enabled === false` stores all
- split pots keep every winner
- the input array is not mutated

The decisive case: _whatever the winner set contains, a winner present in it must
never be dropped._ That is the assertion #89 would have failed.
