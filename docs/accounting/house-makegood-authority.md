# Audited house make-good authority

This is a permanent, one-item financial authority for the operative Revision 6 D8 request. Migration `20260911164014` requires the reviewed private accepted-settlement validator from `20260911163920`; its preflight pins the exact body, owner, ACL and configuration. The migration creates no production funding, proposals, payments, schedules or cohort imports. Application and production cohort execution are separate operations.

A server registers an existing posted receipt into a club treasury as the bounded funding source. The receipt must represent funded house custody, excluding prize/bounty liabilities and settlement suspense; registration does not create money. A proposal names an authoritative source and asserts the expected **net** correction. The database derives the beneficiary, receiving wallet, stable debt identity, total entitlement and applicable ordinary receipts. Only its positive unpaid difference becomes an immutable item linked to `ca_manual_adjustments` in `proposed` status. A preexisting proposal may be imported only when every recorded dimension and its net amount agree. The original manual row stays immutable; the append-only item receipt records payment state. There is no invented human approver or new approval queue.

The payer takes the existing settlement lane before the tournament row, shared debt and item; locks the exact recipient member wallet before the shared treasury; rechecks source facts, ordinary receipts, prior make-goods and funding; then debits the bank and credits that wallet in one transaction. It uses the installed bank transfer's ledger-declaration/treasury-autoskip contract and the existing receiving-wallet ledger trigger. An insufficient bank or receipt allocation aborts all effects. Exact repeats return the same stored receipt. Changed source facts reject the old item; upward corrections create linked incremental items and downward corrections create no clawback.

For example, an ordinary payment of 20, validated entitlement of 35 and imported net proposal of 15 pays 15. If 10 was paid through this authority and the validated total becomes 12, a later linked item pays 2. Reservations in `tournament_obligations` are never treated as payments, and house money does not forge original escrow-paid counters or exact-refund tranches.

New ordinary bounty payments now retain exact source provenance around the two existing canonical payer calls. A private transaction context binds the individual knockout/award to its actual keyed receiving-wallet ledger receipt. A house disposition blocks that source; a different canonical source remains payable. An unclassified legacy aggregate call cannot guess which compensated source it intends. Ordinary exact-credit replays retain their existing no-transfer semantics.

Historical place qualification is a separate adapter, with a fixed installation cutoff. It requires a unique payout/claimed-key/wallet/receiving-ledger tuple with identical transaction timestamps, event, beneficiary, exact amount and payment class. It records the actual receiving ledger club, which can differ from today's entry club. It never rewrites an old NULL ledger key or infers payment merely from an obligation or a report total. Missing and ambiguous tuples refuse. The ordinary credit writer also propagates its existing idempotency key into the receiving-wallet journal context for future credits, restoring the ambient key on success and transaction failure.

Evidence is serialized in UTC so a change in the caller's timezone does not invalidate a legitimate immutable item.

## Terminal records and privileges

The existing terminal guards ordinarily prohibit any new tournament-linked journal or wallet record. Their exact source hashes are pinned before adding the narrow house case. The payer alone creates a private permit tied to its transaction ID, backend, immutable item, bank, recipient, amount, expected wallet transaction and original tournament/escrow/terminal snapshots. A private early journal trigger stamps only the matching item key before the existing terminal guards run. The guard requires the exact balanced bank/wallet result; a deferred constraint requires the consumed permit and complete durable receipt, with the original terminal state unchanged.

No service/client role can insert permits or call the private settlement helper. PUBLIC, anon and authenticated cannot execute the public APIs. Only the existing service role receives execution; fixed qualified search paths and SQL role identity are used, not caller-supplied JWT text. Frozen payouts still refuse.

## Policy mapping

`check-no-new-band-aids` and its allowlist are unchanged. This authority is the user-authorized permanent single-item accounting door, not a detector, scheduled repair, cohort loop, nominal-pool payment or report-named bypass. The ordinary writer changes fix receipt provenance and individual-source satisfaction where normal money moves. No repair function or schedule is added, no old repair is reactivated, and no existing gate is weakened. Native owner-only fixture seeding is outside the production migration and is identified as synthetic funding in every receipt.
