# Scoped financial record exports

SOURCE CANDIDATE / UNRUN. Prepared from reviewed CA35 d6ca0b0ef92428ca537441dae40daa54da480034. No financial or monitoring writer, RLS policy, accounting component, stored amount, commercial rate or historical record is changed by this export boundary. This is not a complete immutable export snapshot or a new financial-export UI.

The seven existing discriminants remain. The six nonweekly modes now require an explicit representation, expected current actor and view predicate; ambiguous legacy calls refuse before queries. The weekly mode retains its existing canonical reader, 50-row view default and 1000-row export limit. Every exported page checks account generation after awaits and before download. Existing UUID aliases normalize once; returned identities and scope are checked independently. A caller cannot replace a failed agent lookup with the agent PK as a user ID.

| Existing mode | Representation and scope |
| --- | --- |
| settlement_club | club_weekly_summaries: only canonical issued club aggregate summaries; received funding, paid by club and retained are distinct. |
| settlement_agent | own_agent_accrual_records: exact own account and recorded club, original IDs/source types; no payment/entitlement assertion. |
| agent_commissions | own_agent_page_subtotals: explicit opt-in to exact decimal sums of this bounded source page only, contributing IDs included; never complete day/week totals. |
| wallet_transactions | own_wallet_records: own user only; a club filter refuses because the table has no club. |

| settlement_invoices | own_agent_credit_invoice_records: actually credit_invoices; exact own agent-profile identity. Historical club filters refuse because no invoice club is recorded. |

Wallet rows retain nullable related-entity, table and hand references. Raw rake rows retain the typed tournament flag/ID, source and rake method alongside exact amounts; arbitrary metadata and participant-contribution JSON are excluded. These are explicit record projections, not full-row archives.

Agent profile IDs and account IDs are different. agent_commissions.user_id and cashout_requests.agent_id are account IDs. credit_invoices.agent_id is agents.id. Commission queries always constrain actual actor+recorded club; the selected agent profile is current context, not historical identity attribution. Credit invoice queries additionally join the exact current own-agent identity in the same statement. Current profile ownership does not prove historical invoice ownership, club, agreement or liability. A missing/deleted/invisible profile remains unavailable; no historical mapping is invented.

All money/rates are selected as text. Weekly amounts retain the existing numeric(12,2) parser and funding conservation. Wallet/cashout amounts preserve numeric(15,2); raw pot/rake/BBJ preserve numeric(18,4), including four-place values. Unconstrained commission/credit numerics retain their decimal text, without cent rounding. Null optional fields remain null and are listed in Source Fields Recorded Null; required absent/nonfinite/malformed money refuses. The 128-character decimal and 65536-character free-text bounds bound parsing/serialization work, not the business-valid financial domain. Larger values refuse rather than truncate. No name is invented from an ID.

Cutoff provenance distinguishes caller_supplied_cutoff from client_requested_cutoff and is retained in every continuation cursor and CSV. Neither is a server as-of snapshot. A read requests 1–1000 rows; nonweekly default100, existing weekly export default1000. It fixes an inclusive created_at window/cutoff and orders exact (created_at DESC,id DESC). Date-only input keeps UTC-midnight meaning, not end-of-day. Cursors retain microseconds and bind actor, subject, scope, window, representation and page size. The weekly reader adds only optional validated cursor filtering/strict tuple progress to its existing canonical parser; existing view consumers keep their defaults. All export modes probe their exact source scope for visible undated rows and refuse if a window cannot be placed; the weekly probe uses only club+canonical-summary type and exposes no private detail.

Every nonempty page says continuation is possible even if the provider returns fewer rows than requested. A later empty result means range_empty_at_read, not complete history. The CSV repeats scope, requested cutoff, source count, page size and limitations. An empty export returns no_visible_export_records with coverage and creates no file. A fixed cutoff is a query bound, not a server snapshot: mutable rows, backdated inserts, permissions/profile changes and multi-statement reads remain possible. Separate native/PostgREST/RLS and history/snapshot qualification remains required. No role or RLS expansion is introduced.

CSV uses validated ordered key/label/type descriptors rather than object-key order. Decimal descriptor bounds are checked before formatting, scale zero emits an integer, and prototype-named source keys retain their own data. It rejects malformed row shapes and emits exact numeric strings. Free text starting with a formula marker, whitespace/control or apostrophe gets one leading apostrophe before ordinary CSV quoting. Escaping original apostrophes too distinguishes original text from escaped formula text; a corresponding importer removes exactly one escape prefix. Numeric fields never use spreadsheet formulas. CSV bytes preserve decimals, but spreadsheet automatic numeric conversion can round them: import decimal columns as text. Supported spreadsheet behavior must be qualified separately.

The only identified production service consumer is FinancialAlertsPage's serializer/downloader. The page preserves all-loaded export behavior irrespective of severity filter, with exact original IDs and explicit columns. It clears unexportable old-account/failed-read data, fences late UI/download emissions and says No Loaded Alerts rather than global all-clear. The capped critical list is labelled loaded-versus-separately-reported, with no complete-critical claim. Root's adjacent FinancialAlertService change only propagates read errors and rejects unavailable shape/count evidence; existing alert log/resolve authority is unchanged. The page uses the reviewed useCashoutScopeKey and useCashoutScope helpers integrated in a0692ff91700845fe324f80b308c8c9f3faa8450. It introduces no separate auth counter. Remounting retires local data and callbacks; it does not cancel remote operations.

Authored source tests use actual readers, parser, serializer, account guard and mounted alert page with synthetic remote responses. They cover seven representations, ambiguous/mismatched identity, failed lookup, exact scales, invalid/null money, raw versus canonical documents, missing dates, own private versus club scope, lower provider caps, timestamp ties and cursor drift, account/view ABA and final download fences, explicit CSV field mapping and formula text.
