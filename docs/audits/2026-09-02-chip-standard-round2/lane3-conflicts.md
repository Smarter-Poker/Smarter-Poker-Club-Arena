### 1. Cap vs Lane G satellite pool transfer

Live `fn_settle_tournament_obligation` (oid 18980545):

- `v_pool_kinds = {place, late_reg_adjustment, bubble_protection, final_table_deal, satellite_remainder, seat}`
- `v_not_pool = {satellite_seat, bounty, mystery_bounty, bounty_residual, own_bounty, mystery_bounty_residual}`
- cap: `SUM(tournament_payouts.amount WHERE source NOT IN v_not_pool) + v_pay > prize_pool + 0.05` -> `escrow_short`.

Live `fn_award_satellite_seat`: moves `LEAST(sat.prize_pool, ticket)` out of the satellite's `prize_pool`, writes one `chip_ledger` row (`tourney:<sat>:seat:<uid>:pool_transfer`), writes `tournament_payouts` with `source='satellite_seat'` (excluded from the cap sum). Never refuses, never unseats.

Engine `processSatelliteAwards` (origin/main TournamentManager.ts:627-1000): `pool` snapshot before the loop; `planSatelliteAwards` gives `seats = max(configuredSeats, floor(pool/ticket))`, `remainder = pool - awardCount*ticket` (0 when negative). `satelliteTicketCost = buy_in + fee` (satelliteTargetOpen.ts:104-111) == the DB's `v_value`.

Arithmetic, successful seats: after N awards satellite pool = P - N*T (or 0 when short); remainder paid as `satellite_remainder` = P - N*T; cap sum excludes the seat rows; `0 + R <= R + 0.05` passes. Consistent. Real example of the healthy shape: open "$10" satellite, pool 207.00, 1 seat at 200 -> remainder 7.00 after transfer leaves 7.00.

Arithmetic, failure paths: `regErr` (real error) or `held_from_this_satellite === false` -> `payCash(ticketCost)` as `place`. No pool transfer happened, so the cap compares `ticket` against the untouched pool. When `configuredSeats > floor(pool/ticket)` that is `ticket > pool` -> refused.
