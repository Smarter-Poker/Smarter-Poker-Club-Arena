# Prospective atomic-clock duration and due-time contract

This is executable proposal code outside migrations. The service clock RPC, full maintenance composition and actual manager/client adoption are still pending. No production clock was activated.

Admission requires at least one duration term. Every present durationMinutes, duration_minutes or duration term must be a finite positive JSON number; minutes and seconds must describe the same duration at database microsecond precision. Missing, null, boolean, string, negative, zero, object, array and contradictory terms refuse. They cannot silently select a fallback or another alias. Positive rounding to microseconds is explicit and identical in SQL and TypeScript, including half boundaries. Durations that round to zero or exceed exact Number microsecond precision refuse.

The raw advertised duration continues after the stored ladder. The old generic overflow's two-minute minimum has no booked-rule authority and is removed from this prospective contract; its one-minute-to-two-minute counterexample remains executable. Acceleration applies once using ceil(minutes / 2), with a one-minute minimum. Actual source producers admit 22 configurations: four MTT presets, a generic SNG preset, the canonical HU ladder and all 16 funded Spin tier/stack configurations. Fractional terms are tested without requiring their intermediate binary float products to be integers.

The current manager's actual generic overflow composes two effective-duration calls. Executed counterexamples include a ten-minute accelerated tail becoming three minutes and a five-minute tail becoming two. The prospective contract produces five and three minutes. The actual current client omits acceleration and grants a fresh full countdown after an anchor is at least four durations old; the latter remains an executed regression witness.

The database due function samples clock_timestamp itself. It refuses early or missing canonical time and uses the accepted prior deadline as the next anchor. Exact boolean break rows consume no level time. An integer microsecond duration is constructed as integer day, second and microsecond components, avoiding a second floating-point rounding at interval conversion. It never resets overdue time to request arrival. Typed finite timestamps normalize to epoch microseconds for immutable request equality; infinity refuses and intentional NULL remains NULL. Credits clip at the epoch's original start, including a future first-deal anchor.
