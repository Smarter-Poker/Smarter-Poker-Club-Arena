# Held qualification UI auth freshness

Terminal-result reads and queued exits capture an opaque scope that changes on the existing `AUTH_STATE_CHANGED` bus event. The scope is never rewritten from rendered identity, so a sign-out or new-account event immediately rejects pending old-account output even before React's user state catches up. Each result read checks the scope after awaits; each queued exit checks before publication and source-tab closure. A stale result resets only pending presentation guards and uses the existing durable retry. Tables remain mounted and ordinary token refresh can recover with a fresh read.

The five new race cases execute the actual registered auth callback and terminal functions. They cover same-account replacement during a receipt read, a different account arriving before the old callback user changes, and queued exits interrupted by same-account replacement, another account or sign-out. Same-account recovery reads a fresh delivery and closes only the source tab. The two focused files pass all 67 cases, including existing ranked completion controls; application typecheck exits zero with no diagnostics.

This extends the held qualification UI. It adds no RPC or database migration, but depends on the existing held UI/core and therefore remains excluded from publication until the Stage-B/DTO and rolling-client acceptance gates are met.
