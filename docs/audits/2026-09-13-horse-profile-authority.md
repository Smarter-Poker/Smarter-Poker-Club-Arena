# Horse identity and control fields belong to the server

The complete horse-trigger audit found an authority gap in `profiles`. Ordinary authenticated accounts had column UPDATE grants for `is_horse`, `horse_profile` and `horse_status`, and owner RLS permitted changing their own row. Existing privileged-profile guards protected other fields. Setting `is_horse` also enters the horse-socialization trigger chain. A local PostgreSQL 17 reproduction proves self-promotion and its AFTER-trigger side effect before the fix. The live census found 1,000 horses and no horse stamp mismatch among 1,080 active seats; this finding does not claim existing corruption.

The migration revokes those three browser UPDATE grants and installs one final BEFORE INSERT/UPDATE guard. Browser signup keeps its table INSERT permission, but can supply only ordinary control-field defaults. The guard also rejects changes through older privileged RPCs. Review reproduced an additional bypass in the first candidate: the shared service-context helper falls back to `current_user` when JWT context is absent, and a SECURITY DEFINER RPC changes that identity. The final guard checks the originating SET ROLE value as well, which survives nested definers. The existing shared helper is unchanged and its reviewed definition is hash checked before installation.

The guard preserves ordinary profile editing, signup defaults and nullable legacy defaults; service-role engine/import/tuner writes; and trusted direct maintenance. The active client ProfileService maps edits to display_name, bio and avatar_url, and AuthPage signup omits horse control fields. Legacy browser HorseOrchestrator/Hydra status writers cannot legitimately control another player's horse under existing owner RLS and are not granted an exception. The three live lane/stake-band functions writing horse controls are service-only. No chips, seats, ranks, horse strategy values or social identities were changed by this migration.

All 43 isolated PostgreSQL cases pass, including baseline exploits, direct and nested writes, stale grant restoration, absent/blank/null/malformed JWT context, browser-origin service claims, rollback and concurrent browser/service writes. The native test runs in the existing required accounting job. Production migration 20260913172658 was applied at 17:26 UTC. A rollback-only temporary-table probe invoked the installed guard: four forbidden writes were rejected, ordinary signup/edit passed, browser control grants are absent, and service permission remains. No real production profile was modified by a probe.

This closes one proven defect. The wider audit still includes 139 captured trigger records and 221 captured functions; inventory is not a completed line-by-line audit. Individual source/caller review and runtime/failure testing remain tracked in the owning operational-alert task.
