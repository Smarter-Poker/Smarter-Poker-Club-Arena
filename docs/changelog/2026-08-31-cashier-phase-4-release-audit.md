# Cashier Phase 4 Release Audit And Recovery Hardening

## Scope

This is the required closeout audit for Cashier continuation Phase 4 of 10. It
does not begin Phase 5. The review was performed against the protected branch
after the Phase 4 squash merge, not against the older feature branch.

## Defects Closed

- A failed `agents.agent_wallet_balance` read left the wallet unknown but still
  allowed `loadClub` to return complete and advance `Balances Verified`. Wallet
  read failures now make the verification incomplete and reach monitoring.
- `Reconcile Now` awaited the club load but ignored failures from both queue
  counts, announced success before Trade or Settlement records reloaded, and
  could not detect request or ticket profile degradation. Every promised data
  surface now returns an explicit result and the success toast requires all of
  them to be true.
- Partial-batch recovery was described as durable but lived only in component
  memory. Refreshing, closing the tab, or switching clubs destroyed its batch
  nonce and per-recipient operation identifiers. Unresolved intents are now
  validated, user-and-club scoped, persisted for 24 hours, restored after a
  refresh, and cleared only by success or a genuinely changed intent.
- The unresolved intent is written before the first server round trip, including
  every per-target key. A refresh in the uncertain interval after a server
  commit but before its response therefore replays safely instead of minting a
  second charge.
- Recovery now refuses to reopen if any original recipient is no longer in the
  viewer's current server-authorized Cashier roster. It restores the exact
  amount, recipients, submission identifier, and per-target identifiers when
  the roster still agrees.
- Switching clubs now closes club-scoped money modals and clears the displayed
  amount instead of carrying the previous club's interaction into the next
  route.
- Copying a receipt with a malformed historical timestamp no longer throws;
  the receipt explicitly reports the recorded time as unavailable.
- The repository-wide verification sweep also found a stale table-creation
  source pin that still required writes to two columns now generated by
  Postgres. The test and its adjacent source comment now enforce the canonical
  chip buy-in pair and prohibit explicit writes to the generated BB mirrors.
- A satellite regression pin merged during the audit with a fixed 2,600-byte
  source window, immediately tripping the repository's structural-window gate.
  It now isolates the enclosing award branch by syntax, so comments cannot move
  the protected conditions outside the assertion window.
- The live-customization transport test dynamically imported the production
  `MasterBus` inside each five-second test. Under full-suite transform pressure,
  that import could time out and cache an incomplete module with an undefined
  singleton. The suite now hoists the real module and its stores during
  collection, removing the false red while preserving the production-bus
  assertions.
- The final authenticated production sweep exposed a 375px Club lobby seam
  outside the Cashier route: the Share artwork owned only 8px of reliable
  vertical reach, while collapsed Diamond and Player wallet controls remained
  discoverable inside a zero-height clipped disclosure. Share now owns a real
  44px coarse-pointer hit area, collapsed wallet content is removed from hit,
  focus, and accessibility visibility, and a self-contained Chromium geometry
  beat blocks both regressions before merge.
- The first complete post-deploy rerun found that Daily Missions certification
  still selected the pre-release lowercase reroll accessibility names. The page
  object and confirmation assertion now target the enforced title-case contract,
  with a source-level pin joining the application and both selectors.
- That rerun also exposed three independent false-red paths in the mobile chrome
  audit: a route could replace its document during measurement, smooth scrolling
  could leave the probe mid-animation, and virtualized rows clipped by an inner
  scrollport were counted as painted content. The audit now retries only transient
  document replacement, proves the real scroll boundary synchronously, intersects
  leaf geometry with every clipping ancestor, and still fails closed when an
  Arena document never stabilizes or a visible pixel crosses fixed chrome.

## Evidence Contract

- The Phase 4 resilience test exercises receipt hardening and local recovery
  round trips, expiry, scope isolation, invalid payload rejection, cleanup, and
  the page wiring that consumes the helpers.
- Focused Cashier tests, client typecheck and lint, the full client and server
  suites, production build, protected CI, publication, live SHA provenance,
  and authenticated production Cashier checks remain required before this
  closeout can be marked complete or Phase 5 can start.

Real-time law remains unchanged: connectivity uses browser online/offline
events and balance freshness uses named `MasterBus` events. Recovery persistence
does not poll and does not create a second server money path.
