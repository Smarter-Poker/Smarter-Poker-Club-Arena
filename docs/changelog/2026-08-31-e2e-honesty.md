## Caught by an existing law test, and it was right

`tests/stats-experience-contract.test.ts` requires `tests/e2e/stats-deep.spec.ts`
to appear in the workflow **exactly once**. The first draft of the presence
guard named it four times (the `-e` test, the invocation, a warning, a fallback),
and CI turned red. The rule is a good one - a path repeated across a guard and
its invocation is a path that can be updated in one place and not the other - so
the fix was to hoist the presence check into a `run_suite` shell function that
takes spec paths as arguments. Each path now appears once.

Worth recording for the next agent: **`npx vitest run tests/unit` is not the
suite.** This failure lives in `tests/*.test.ts`, one level up, and a green
`tests/unit` run said nothing about it.
