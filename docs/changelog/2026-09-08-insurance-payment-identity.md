# Insurance Payment Scope and Journal Identity, 2026-09-08

record_insurance_transaction selected its bank from club membership even for a private table, accepted any payload reusing (table, hand number, player), and did not declare a ledger category or counterparty before changing the bank. Its auto-journal consequently defaulted to adjustment against settlement suspense. The receipt rounded premium and payout separately, but its bank delta was computed before rounding, so a fractional-cent request could disagree with the receipt arithmetic.

Migration 20260908052322 validates the payment and table/club relationship, routes by the table's private/union scope, normalizes values to the receipt's two-decimal precision before computing the delta, and compares the complete normalized replay payload. The existing unique receipt constraint serializes concurrent requests. Insurance bank changes explicitly journal against the table stack with a stable settlement reference; the caller's previous ledger context is restored. Journal failure aborts receipt and bank together. Execution is restricted to service_role and the owner; the repository's only production caller is the engine helper.

The engine now normalizes its request cents once and requires a matching receipt, including on the confirmation read. An old receipt with different amounts is no longer accepted as confirmation. Failure wording describes an unconfirmed outcome instead of claiming that a response failure proves no commit happened.

Validation: 41 PostgreSQL cases cover private, public union and standalone routes, journal faults, changed-payload replays, canonical cents, debit/credit, invalid values and two-session contention. All 246 database probes pass. Fourteen engine insurance tests pass, including two new receipt/rounding cases. A bounded production receipt query returned three receipts, zero arithmetic mismatches and zero private-table receipts routed to a union bank; this is not evidence that the newly identified defects caused a particular live incident.

Database migration applied; engine adoption follows the Hetzner pipeline. Insurance still needs to be included in the same transaction as the hand's stack, rake and BBJ changes. The current engine caller still ignores a failed insurance result, which is part of that outstanding settlement-barrier work. No historical balances or incident states were changed and no watcher or reconciler was added.
