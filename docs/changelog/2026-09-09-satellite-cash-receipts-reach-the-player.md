# Satellite cash receipts reach the player

The approved satellite policy treats funded target entry value as ordinary money for eligible unregisters. An isolated run of the installed database code returned a 200-chip ticket and no wallet credit. The draft correction returned exactly 200 chips through the original source wallet, immutable entitlement, one-use refund authority and real escrow writer.

The client also rejected every positive satellite cash amount, even with a valid request-keyed receipt. It now accepts a finite nonnegative satellite cash component no greater than the total refunded cash. Request identity, registration identity and the other amount checks remain required. Existing cash and historical ticket receipts retain their response shape and confirmation text. Lost responses still retry only the same request.

This client change publishes before the database correction. It changes no wallet balance or refund policy by itself. The database draft, remaining refund cases and full Phase 3 controls are still in progress.

Verification: 120 tests in the four affected client suites passed, including the same-request replay after response loss and refusal of overstated or invalid satellite cash. TypeScript build-mode checking passed.
