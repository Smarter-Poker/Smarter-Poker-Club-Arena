# Cash Entry Close Uses The Reserved Result Ladder

The tournament engine recorded and broadcast 300 chips for second place from a 1,000-chip 50/30/20 pool with a 100-chip Bubble Promise. The installed terminal authority reserves that promise first and pays 270. The same full-pool error occurred when late-registration closure repriced unpaid finishers. The existing server reserve helper had no callers.

Both actual manager methods now use that helper after the final field is known. Elimination reads the persisted bubble and buy-in fields, records the reserved amount and broadcasts that same amount. Repricing uses the finalized field and preserves the satellite path. Before the field closes, existing provisional pricing remains unchanged. Invalid or unfunded finalized promises do not produce a made-up result amount.

The installed entry-close verifier had a second root defect. It compared the old full-pool amount and required a matching cash payout before accepting repricing. Current cash repricing intentionally moves no money; the terminal authority pays the full event atomically. Thus even a correctly repriced ordinary cash finisher could leave the entry-close receipt pending indefinitely. The migration makes cash acceptance derive expected values from the actual canonical amount authority and compare exact result facts. It writes only the entry-close completion timestamp. The separate terminal receipt continues to own all payment proof. Satellite acceptance is unchanged.

The exact installed verifier body (MD5 51c598a2fdb9a805485dec239eb70169) reproduced that unpaid-result refusal in isolated PostgreSQL 17. Fourteen local database groups pass after correction, including reservation, no money write, replay, drift, missing place, malformed ladder, fractional cents and the unchanged satellite branch. The amount authority body matches the installed 8f6cde5f5b799949506259f3064568b9. Initial actual-method regressions failed five of eight cases before correction; the expanded fixed suite also includes provisional-field and sparse-ladder behavior. Source assertions were updated in the same change to name the reserved pool.

This is partial T07/T09/T10 evidence, not Phase 3 completion. No production SQL was changed by this lane. Migration application, source integration and deployed behavior remain release work. ## External Comparison

Rule 12 describes an optional early-payment format that first pays the minimum cash and later only the extra earned amount. Rule 2.2 ranks simultaneous busts by starting stacks, including synchronized hands across tables, and splits tied prizes when those stacks match. Source: https://www.pokerstars.com/poker/tournaments/rules/ (retrieved September 10, 2026).

These public behaviors are comparison points, not evidence of another operator's internal accounting architecture. This correction adopts no new early-payment or cancellation policy.
