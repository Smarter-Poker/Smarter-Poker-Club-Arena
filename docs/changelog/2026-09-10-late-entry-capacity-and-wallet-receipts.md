# Late entry creates canonical capacity and records the charged wallet

The retained late seater created a table without a tournament format or stakes. On the current schema the first or overflow table failed `tables_game_type_is_format`, rolling back registration. It now calls the existing capacity owner, which uses the persisted current blinds, the legal seat cap and a durable manager receipt. Deleted tables are excluded from seat selection.

The entry debit resolves a union member club, but the wallet receipt read the host club balance. The receipt now uses the same resolver and preferred ledger club as the debit. Missing entry wallet evidence refuses the whole transaction. Other receipt categories retain their behavior; historical rows and balances are not rewritten.

The native PostgreSQL acceptance installs the exact live seater before testing. That source reproduces the table refusal. The old logger independently fails the union wallet receipt assertion after capacity is corrected. The candidate passes 21 checks: standalone and union funding, the first table, overflow, current blinds and manager receipts, exact escrow and refund entitlements, committed response replay, a closed entry window, and a fault at the final response that rolls every charge and seat back. All observed data and all eight catalog snapshots restore exactly. Production application and whole Phase 3 acceptance remain separate gates.

The migration checks both current dependency bodies, both changed function bodies, and preservation of all function metadata including execution privileges. It executes in one transaction.
