# The Seat-First Pre-Check Verifies a Skip Before It Takes It

Follow-up to #4112 (`fix/horse-seat-first-skips-a-seat-it-already-has`, merged 05:50 UTC), from a line-by-line review of that change against CLAUDE.md 10.5. #4112 was already squash-merged when the review finished, so this is a new branch off `origin/main` (10.82), not a second push.

## What the review found

`topUpWithHorses` builds its ledger from the seat rows it read for the shortfall. Those rows are read before `unseatedRegistrantHorses` and `pickFreeHorses` run and before every `fn_seat_horse_in_seat_first_game` call ahead of the current candidate, and each of those calls spends a mean 590 ms in the lock queue (#4112's measurement). By the third candidate the ledger is about a second old. Three things could then read as a skip that the RPC would have seated:

1. A horse the rows show seated that stood up in that second. The pre-check said `already_seated`; the next candidate took the seat, so no seat stayed empty, but that horse waited for the next five-second pass where before #4112 it would have been seated on this one. #4112's changelog names this as "the one difference a horse can observe". Horses are players; a difference a horse can observe is the thing 10.5 forbids.
2. A seat that opened after the RPC itself answered `table_full`. `rpcSaidFull` skipped every spare candidate for the rest of the pass, so that seat stayed empty until the next pass. Before #4112 the next spare candidate filled it.
3. A table the rows show full at 1..capacity. This cannot fire on production today (every open seat-first table's capacity equals its tournament's, so a full table has no shortfall and the pass returns before the loop; verified again 2026-09-10: 266 open games, 0 with a differing capacity, 0 live seats outside 1..capacity), but the code allowed it and it has the same staleness.

Everything else held. Checked against `pg_get_functiondef` of all three layers in production: the outer `fn_seat_horse_in_seat_first_game` and `fn_seat_horse_in_seat_first_game_before_terminal_seat_gate` add only the locks and the freeze gate; `fn_seat_horse_in_seat_first_game_before_maintenance_gate` checks `table_seats (table_id = primary, user_id, left_at IS NULL)` for `already_seated` and searches `generate_series(1, COALESCE(NULLIF(tables.max_players,0), tournaments.max_players, 3))` for a free seat, in that order. The ledger copies both expressions and the order. "Seated at another table of the same tournament" does not arise: the RPC looks only at `fn_tournament_primary_table`, the ledger reads only that table, and no open seat-first game has more than one non-closed table (269 games, max 1). No `is_horse` anywhere on the path. The log line carries the first eight characters of the tournament id and counts, nothing else.

`already_seated` no longer counting as `added` was also checked against every consumer. GameServer's `topUpPartialSeatFirst` clears `seatFirstFillMisses` on `added >= shortfall` and otherwise counts a miss, which doubles the window-closed retry interval (12 s up to 10 min; a board with a human keeps 12 s). Before #4112 a pass that drew a seated horse first reported `added = 1` for a seat it did not fill, which cleared the miss counter and hid the miss. After #4112 that pass seats the next candidate instead, so it reports a real seat. The only board that reports more misses now is one where nobody could be seated, which is the board the backoff was written for on 2026-09-02; the discovery loop's past-start top-up, the scheduler and the overlay guard do not back off at all, and a board with a human in a seat never does. No seating is delayed by the count becoming honest.

## What changed

A skip is never taken on the rows the ledger was built from. When `seatFirstSeatPrecheck` answers `already_seated` or `table_full`, the loop re-reads the same rows (`table_seats` by `table_id`, `left_at IS NULL`, the same index, no advisory lock), folds them in with `seatFirstLedgerRefresh`, and asks again. Only that second answer can skip. A stale row therefore falls through to the RPC on this pass, exactly as before #4112; the cost is one indexed read of at most a handful of rows in place of one locked call. A failed re-read verifies nothing, so it skips nothing: the RPC decides. A fresh read that shows a free seat in 1..capacity overrides the RPC's earlier `table_full`, because it is newer; with the capacity unknown the rows cannot judge fullness and the RPC's word stands.

The per-pass tally is folded into `/metrics` as `poker_seat_first_precheck_total{outcome=...}` (`rpc_called`, `skipped_already_seated`, `skipped_table_full`, `verify_reads`, `seated`, `rpc_already_seated`, `rpc_table_full`, `rpc_refused`, `rpc_other_noop`), process-wide because three services drive the same top-up, present at zero from the first scrape, rendered from `GameServer.getPrometheusMetrics` beside the tournament and spin gauges. `seated / rpc_called` is the ratio #4112 said to watch; it is now a PromQL division rather than a grep. The log line gains `verify_reads=N`.

No migration. No env var. No filter on `is_horse`.

## How verified

`server/src/services/seatFirstSeatPrecheck.test.ts` (37 tests): the five new pure cases for `seatFirstLedgerRefresh`; against the mocked client, a horse that left its seat between the read and its turn goes to the RPC on this pass and is seated there, a seat that opens after the RPC said `table_full` is filled on this pass by the next spare candidate, a failed re-read sends the candidate to the RPC, and the existing skip cases still skip with the re-read agreeing (one shortfall read plus one verifying read per skip, counted). The metrics module is pinned for every outcome at zero, accumulation across passes, and its splice into `GameServer.getPrometheusMetrics`. Source pins hold the re-read between the pre-check and the skip, `precheck = 'call'` on a failed re-read, and no RPC inside the verify block. Neighbouring specs (`seatFirstFillOrder`, `seatFirstCountSync`, `aClubBoardFillsFromItsOwnMembers`, `theFreezeIsTotal.law`, `oneSeriesPerMetricName.law`, `theClientIsHeard.law`, `aRevokedSessionIsRefusedOutLoud.law`, `health`, `router`, `engineLiveness`, `pickFreeHorsesLimits`, `seatFirstHoldRotates`, `seatFirstStartStall`) pass; `tsc --noEmit` is clean.
