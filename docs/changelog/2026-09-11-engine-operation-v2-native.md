# Native acceptance and restart safety for engine operation v2

An intake reply could previously depend on a transient service-start request after writing its intent. The v2 intake now installs and verifies immutable per-operation service/path units, persists their boot edges, and publishes the native acceptance event only after that ownership is in place. Every accepted operation retains its original bundle, configuration, request and unit digests across default upgrades.

The native entrypoint checks its real unit PID/InvocationID, takes the existing engine lock, and consumes the exact one-use database maintenance step before a candidate trial. Persisted invocation counts and recovery deadlines survive restart. Lost consume responses recover only the prior sealed desired image. Unknown native command outcomes keep the release barrier. Exact terminal cleanup can finish after a lost disable response without granting another trial or extending an expired recovery budget.

The additive installer provides a compare-and-swap configuration upgrade and a fixed immutable router. Its receipt is explicitly inactive. Frozen v1 files, existing publishers and the legacy `:55` lane are unchanged. It creates no account, credential, grant, activation receipt or production installation.

Validation: 51 existing Node/PostgreSQL regressions passed; 45 Python native tests passed, with the Linux-only actual systemd parser case unrun on macOS; the required Vitest bridge passed both v2 suites. Six additional PG17 composition cases exercised the production actuator helper and native transaction against the real journal/provider/maintenance migrations with fixture container/seal actions. This caught missing version-function permissions; the independently owned authority migration now grants only those two read-only functions to the actuator role. The real provider adapter also resumes interrupted native installation and reconciles a lost acceptance reply without sending a second request. Independent review also caught the host's trusted lock alias and degraded sealed-source HTTP status handling; actual filesystem and local HTTP fixtures cover both fixes while retaining strict candidate checks.
