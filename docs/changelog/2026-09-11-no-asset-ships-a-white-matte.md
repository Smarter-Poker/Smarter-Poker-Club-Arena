# No Asset Ships A White Matte

Before: a painted shell is cut out against transparency, and several were exported with their glow rendered as WHITE instead — a smooth neutral ramp at full alpha sitting outside the frame, with a torn dashed edge where the export clipped it. Because the art is cropped flush at the top of a plate, the top looked correct and only the bottom and sides carried the matte, which is how it reached production. Four plates were cleaned by hand on 2026-09-10: club-nav-shell (12.7% of its opaque pixels were matte), wallet-row-shell (3.0%), club-utility-shell (2.8%) and wallet-agent-wallet-square-v1 (0.6%). Nothing in the build would have noticed the next export putting it back.

Correction: scripts/art/check-asset-matte.mjs runs on every pull request, over public/assets/\*\*. It is a Node port of scripts/art/clean-shell-matte.py; the Python stays the authority and is still what cleans a plate. The port exists because the gate has to run on a CI runner, and a runner has node and sharp (already a devDependency) but no numpy and no Pillow. Two implementation swaps, both exact: the 3x3 local range is computed separably, because the maximum over a 3x3 box is the maximum of its row maxima; and the flood is a breadth-first queue rather than dilate-until-fixpoint, which is the same reachable set by definition. Together they take a 1829x313 plate from minutes to 0.2 seconds, which is the only reason a port is worth having. Both implementations were run side by side over all 148 assets and disagreed nowhere.

It records a baseline rather than applying a threshold, and that decision came from measurement rather than taste. The obvious gate — fail any asset the detector wants to cut — was tried against the corpus first. Of 148 assets, 115 read exactly 0.0% and 142 read below 0.5%, and every one of the six above that floor turned out to be the detector eating artwork, each confirmed by opening the before and after: club-identity-icon-club-v1 (7.8%) loses the left end of its pediment, a column face and the plinth, and re-reads 12.0% after cleaning, so it diverges; spade-console-v1/mid (4.2%) loses 5 complete columns of a 1000x8 tiling rail, which tiles as five transparent slits; club-identity-icon-player-v1 (2.8%) converges to 0.1% and still has its head outline and shoulder bevel chewed away, which is why convergence is necessary and not sufficient; live-dot (0.7%) gives up 23 pixels of mean luminance 20, dark glow rather than white matte; wallet-union-bank-v1 mobile (0.6%) gives up 3780 bright silver pixels of which none lie within 4px of the border, so they are frame highlights and not a matte, which by definition hugs the edge; wallet-promo-wallet-square-v1 (0.5%) sits on the floor and under the cleaner's own threshold, so the cleaner writes nothing for it.

So the reading is not a verdict, but a reading that RISES is. docs/art/matte-baseline.json records each of those six with the reason it was looked at and kept, and the build fails when any asset reads higher than what is recorded. An asset with no entry has never read at or above the floor and is judged against the floor. The consequences are deliberate: no false failures on the corpus as it stands, the regression that shipped cannot return silently, and a legitimate re-export has to run `npm run art:matte -- --update`, which puts the change in the diff where a person reads it. The --update path refuses to finish while any entry still carries its placeholder reason.

Scope is public/assets/\*\* and not public/ — public/cards is the clearest argument against widening it, since a card face is a large smooth neutral white rectangle and the detector reads the seven of diamonds at 81.6%. Those 681 files are a different pipeline and about ninety seconds of scanning, and the gate is not for them.

Wiring: the check and its law test are steps in the ungated source_windows job. That placement is the point — an asset change touches neither src/ nor tests/, so every changes-gated job skips precisely the pull request that needs this one, and a pull request that edits only docs/art/ runs no other vitest, which is exactly when an unread excuse would slip into the baseline.

Verification: the gate reports 148 assets scanned and exits 0 on the tree as it stands. Swapping in the real pre-clean club-nav-shell.png from 70e20e7ab4 — the file that actually shipped the fault — produces `club-nav-shell.png reads 12.7% matte, above its recorded 0.4%` with a GitHub error annotation on the file and exit 1; the tree was then restored byte-identical. tests/an-asset-never-ships-a-white-matte.law.test.ts is 16 assertions in 300ms covering the detector's four decisions (dark art is never matte; a plate that is nothing but matte goes to nothing; the flood stops at the first structured pixel, which is the premise the whole method rests on; a blue bevel is never neutral), the gate's arithmetic including that 12.7% case, that every baseline entry names a file that exists and carries a reason, and that the Node port and the Python agree on three real assets. The law was mutation-checked rather than assumed: widening STRUCT from 22 to 999 turns 4 assertions red, and making the comparison permissive turns 3 red; restoring the file returns 16 green. tsc --noEmit is clean.
