# Provider operation boundary: executable locally, production inactive

An accepted deployment request can outlive its caller or lose its response. This change adds an installed provider runner that commits the exact qualified intent and a unique submit authorization before acting, then retains the active global release until exact provider readback establishes a terminal result. Restarted or stale owners cannot resend an uncertain request. The original PostgreSQL journal migration and frozen engine v1 files are unchanged.

The Vercel adapter promotes only an already staged production artifact, verifies the complete production-domain inventory and exact promotion/current-deployment readback, and never creates a replacement build. The engine adapter delegates to the existing intake/observer only after pinned control/image/lease and loaded-unit verification. Native install/upgrade artifacts verify bundle contents, retain immutable recovery intent, resume interrupted installation, and restore the prior compatible version on startup failure.

Default mode remains OBSERVE. No production database migration, new identity or grant, host installation, workflow dispatch, Vercel setting change or provider action was performed. Dedicated existing identity, authority isolation, verified host and installed native prerequisites remain blockers. The engine-only source coordinator and isolated candidate workflow now implement admission, exact qualification, merge and build orchestration; actual installed staging/static publication/certification execution, other target source builders and controller-upgrade dispatch remain unavailable; native upgrade completion still requires fresh journal reconciliation.

The installed entrypoint uses the source coordinator and signed event-admission endpoint. The isolated workflow pins trusted controls, runs candidate tests without runner/production authority, and preserves exact image and receipt artifacts. A second PR stays queued through the first item's served certification.

Validation covers native PostgreSQL commit/ownership/UNKNOWN behavior, loopback HTTP response loss and redirect refusal, fixed subprocess transport, exact file manifests, and native filesystem upgrade interruption/recovery. Systemd/SSH/provider interfaces use explicit test fixtures on this macOS host; loaded Linux service execution is not certified here. See [provider boundary contract](../operations/provider-boundary.md) and [validation manifest](evidence/2026-09-11-provider-operation-boundary.json) for exact scope and evidence.
