# Prize finalization respects an explicitly closed entry window

A two-player no-rebuy tournament created through `fn_create_seat_first_game_atomic`, paid through `fn_take_seat_and_buy_in`, launched through the lease-fenced launch RPCs and finished through an accepted knockout could not settle before level 4. The creator persists `late_reg_levels=0` and inherits the unused `rebuy_levels=4` default. Registration correctly considers zero closed, but the prize-finalization trigger converted zero to NULL and borrowed the rebuy value. Native rehearsal reproduced the refusal; a read-only production inspection on 2026-09-12 confirmed the same trigger body, `60b8d3004e7db4e0e89a783d77cc0f71`.

The guarded migration replaces only that late-registration cutoff expression with `COALESCE(NEW.late_reg_levels, NEW.rebuy_levels, 0)`, matching `fn_tournament_late_registration_open`. NULL still uses the legacy fallback. The separate rebuy/re-entry, timed-entry and add-on checks remain intact, and a finalized pool still cannot reopen. The migration changes no existing row, payment, rake, seat or standing. It authenticates the original body, ownership, execution permissions, configuration and enabled trigger, then verifies the replacement body and unchanged function metadata. Exact replay is accepted only with the same authority checks.

Nineteen real PostgreSQL checks pass, including the original failure, explicit zero, NULL fallback, level and timed cutoffs, rebuy/re-entry, add-on promises, finalized-pool refusal, exact migration replay and metadata drift refusal. Each refused UPDATE preserves the complete row. The existing required CI PostgreSQL job runs the same probe using its own pinned runtime. The Mac probe uses an existing PG17 binary, starts one private socket-only cluster and verifies shutdown and cleanup; it installs no packages.

Production application and a full release certificate are not claimed. The funded full-schema terminal rehearsal is a separate integration requirement.
