# Validate engine image exports before host import

The production host has refused bounded engine builds because available memory is below the builder limit plus reserve. Moving compilation to CI requires an exact, reviewable image artifact. This change supplies the archive validation component and its CI proof; it does not enable a host import or change the publisher.

`server/scripts/engine-image-archive.py` accepts a Docker-save archive and independently supplied source commit, server tree and image ID. It verifies Linux amd64, the existing clean-server build contract, source labels, the baked revision, the original config digest and every uncompressed layer digest. It writes a single canonical Docker manifest, the unchanged config and the ordered layers. Alternative OCI indexes, legacy metadata and foreign layer hints do not enter the result.

Input is a bounded regular file opened without following its final symlink. Fixed-size tar headers are checked before any extended-header payload can be consumed. Links, devices, extended headers, duplicate members or JSON keys, ambiguous tags, missing layers, corrupt bytes, nonzero trailing data and changed source bytes refuse. Reads and layer copies use bounded buffers. Publication uses an atomic no-replace link from a private temporary file. Callers must supply an owned output directory. The receipt records input/output digests and size; it explicitly leaves producer authentication and host import qualification false.

The existing disposable Linux resource proof reuses its one successful, exact engine build. After comparison with the full typechecked runtime, it performs a real Docker image save and normalizes that archive. Only the receipt is retained; both archives remain temporary. The existing real OOM, failure, cancellation, neighboring-process and cleanup checks remain required. Local tests use real archive bytes and filesystem operations, without Docker or dependency installation.

Remaining work includes authenticating the CI producer and artifact identities, testing native loading, bounding the actual importer/daemon's resource use, and integrating with the existing request, lock, lease, release-window and recovery controls. A limit on the Docker client alone would not bound the daemon. Successful archive normalization is not release approval or evidence of served engine behavior.
