# Cash rake keeps the club and accounting week where it was earned

The cash settler previously read only the per-player amount from `rake_attributions`. It then passed the table's `rake_records.club_id` into commissions, player statistics and weekly period recomputation. At union tables that ID identifies the house club, while the stored attribution identifies each player's earning club. The same consumer grouped weeks at Monday UTC rather than the existing Pacific accounting boundary.

The consumer now preserves the exact source record, hand, player, earning club and whole-cent allocation together. It validates the entire page before making a financial call. Missing or mismatched source evidence keeps the cursor on the outstanding page. Every cash downstream input uses its stored earning club. Pacific date bucketing keeps early UTC Monday earnings in the correct prior week and follows daylight saving changes. Tournament commission and statistics remain owned by tournament settlement. An empty, malformed or blocked period-recompute response cannot advance the source cursor.

The new service-only history readers return agreements observed at the earning timestamp, including explicit deletion evidence. The historical agent reader resolves the exact club and user, closes moved identities, and refuses multiple active identities. Neither reader uses current terms when old history is unavailable.

`fn_cash_rakeback_period_basis` is a read-only cash preview. It reads the exact Pacific interval and stored weighted attribution, reports missing source/contract evidence and conflicts with old pending or paid periods, and always returns `payable: false` and `written: 0`. It does not calculate or post a new liability. Existing periods lack the required source/contract provenance, even if their displayed amount matches the preview, and remain explicit conflicts.

The companion period writer replaces the raw-club UTC daily-cache path. It validates a complete source set in both directions, checks captured agreements against immutable historical records, and calculates exact numeric per-source entitlements. It rounds once per player and week, preserving the existing deal, agent offer, volume ladder and ten-percentage-point cap rules. Its append-only calculation certificates preserve the historical payer, coordinator union, each actual game union, input source receipts and issued figures. It refuses mixed historical payers/coordinators, unsupported tournament evidence, legacy periods, paid periods and unverified changes to existing certified figures.

A durable club/week recompute request separates source accrual from an unfinished book. A blocked historical week no longer traps the source cursor before later hands. The engine can advance past a deferred calculation only after independently reading its exact stored request ID, scope, creation time, status and reason. Partial-user calculations leave the whole-club request pending; the single weekly coordinator must call the full-scope writer and require a complete request before closing the week. No incomplete request is counted as a settled week or a paid player. Caller batches respect the server's 2,000-user request bound.

Integration boundary: the source consumer, canonical source receipts, guarded period writer and coordinator queue drain must be released together. The observed-source cutover cannot establish earlier agreements. No old pending or paid liability is silently rewritten. Tournament source certification, coordinator queue draining, live installation, full CI and production close proof remain separate work owned by the parent accounting integration.

Validation: 36 native PostgreSQL assertions cover the three read-only historical/source functions. The period writer has 45 native assertions covering exact rounding, deal changes, cap/ladder, immutable revisions, private/union game scope, historical payer/coordinator changes, source and agreement tampering, unexpected storage rollback and durable request recovery. The server suite has 180 focused passing tests, including cursor preservation and independent deferred-request verification. An optional local PostgreSQL fixture processed 20,000 small source credits in 0.895568 seconds including the durable request wrapper; this is local scalability evidence, not a production latency guarantee.
