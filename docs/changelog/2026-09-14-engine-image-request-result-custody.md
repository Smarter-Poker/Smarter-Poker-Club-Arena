# Bind off-host image requests and terminal history

The off-host image bundle already identifies a producer and immutable archive, but the existing release request cannot carry that identity through intake and completion. Add a separate versioned request format that binds the exact CI run/attempt, source and control commits, image ID, archive and descriptor hashes, immutable artifact ID/digest, custody receipt, actor and original deadline. Its preparer calls the existing production bundle verifier, then writes only inert prepared evidence. It does not dispatch a unit or authorize image import.

Release requests bind the exact parent intake and control-generation path. An independent request digest is required for later validation. Terminal history binds the same authority and actual recorded runtime identity; successful history requires the attempted source/image. A failed result cannot use the retryable exit status. A completed record grants no new operation, cleanup permission or live-runtime attestation. Calendar-invalid timestamps and completion before runtime startup are refused while preserving Docker nanosecond timestamps.

The host preparation helper now checks every installed generation file against the exact protected Git commit before deriving a release request. It reads the manifest from that commit's literal installer declaration, requires complete dependency closure, holds regular non-writable file inodes through verification, and refuses source changes, unexpected files, symlinks, directory replacement and expired proof deadlines. It exports only inert prepared evidence. This point-in-time readback grants no execution lease; the future owning launcher must revalidate before execution.

The installer packages the five image request/result/generation dependencies from its existing authenticated Git archive and syntax-checks the Python files. The request schema is installed as data, and validation does not write Python caches into immutable generations. The original bundle admission statements and receipt remain unchanged in the extracted reusable function. Frozen v1 protocol, wrapper and unit bytes are unchanged. Existing intake, launcher, transaction, recovery and seal behavior remains in place. Versioned lifecycle integration and qualification of import against the shared production Docker daemon are still required before off-host delivery can replace the on-host build.

Validation covers 97 Python tests: 29 bundle, 26 request, 21 result and 21 generation tests. GitHub metadata uses controlled fixtures; generation tests use actual local Git objects and filesystem faults. Another 71 existing controller/source-window tests pass without skips. The unfinished result code failed four examples for invalid chronology/calendar values before the fix. All four Python suites run in the existing source-windows CI job before dependency setup. Workflow lint, installer syntax and Python compilation pass. No production operation, image build/load or dependency install is performed by these tests; actual systemd installation and native host lifecycle qualification remain open.
