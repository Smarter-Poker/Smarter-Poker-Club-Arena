# Bind off-host image requests and terminal history

The off-host image bundle already identifies a producer and immutable archive, but the existing release request cannot carry that identity through intake and completion. Add a separate versioned request format that binds the exact CI run/attempt, source and control commits, image ID, archive and descriptor hashes, immutable artifact ID/digest, custody receipt, actor and original deadline. Its preparer calls the existing production bundle verifier, then writes only inert prepared evidence. It does not dispatch a unit or authorize image import.

Release requests bind the exact parent intake and control-generation path. An independent request digest is required for later validation. Terminal history binds the same authority and actual recorded runtime identity; successful history requires the attempted source/image. A failed result cannot use the retryable exit status. A completed record grants no new operation, cleanup permission or live-runtime attestation. Calendar-invalid timestamps and completion before runtime startup are refused while preserving Docker nanosecond timestamps.

The original bundle admission statements and receipt remain unchanged in the extracted reusable function. All existing v1 intake, installation, launcher, transaction, recovery and seal contracts remain in place. Integration of the versioned requests with those owning lifecycle boundaries, and qualification of import against the shared production Docker daemon, are still required before off-host delivery can replace the on-host build.

Validation covers the existing 29 bundle tests, 26 request tests, and 21 result tests using bounded files and mocked GitHub metadata. The unfinished result code failed four examples for invalid chronology/calendar values before the fix. All three suites run in the existing source-windows CI job before dependency setup. No production operation, image build/load or dependency install is performed by these tests.
