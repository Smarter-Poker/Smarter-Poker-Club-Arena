# PKO heads follow accepted knockout dependencies

When B eliminated A and later lost to C before A's bounty was processed, the
claim door could snapshot B's original head. It paid C too little and then
placed A without creating B's rightful bounty obligation. A second defect
discarded the correctly ordered successor when a destination table had
reserved a lower hand number before B moved there.

The Club Arena database claim now proves incoming head dependencies before
changing player status or capturing a new head. It validates the accepted
candidate, atomic hand, successful stack settlement and complete participant
map, then requires every relevant prior or same-hand bounty's exact complete
marker. A candidate's eliminated/rebought label alone proves no payment.
Unknown or incomplete evidence returns a visible refusal, with bounded exact
predecessor identities for recovery.

The collector repeats the proof for pending obligations after its immutable
settled-replay exit. An unrelated pending head no longer serializes another
table's payout. Shared heads can pass a larger numerical watermark only when
complete accepted evidence proves the larger-numbered hand was chronologically
earlier. The watermark never rewinds. Existing unit, payout, custody, original
generation and head-snapshot checks remain; no historical financial row is
rewritten and no caller receives a new money authority.

Validation: 111 native assertions in the exact migration runner, plus five
function drift guards, metadata drift, three direct-role refusals and migration
replay. The runner is included in the existing required PostgreSQL accounting
job. Two old-source counterexamples remain reproducible. The fixture uses
synthetic accepted records and the inherited pool-bounded wallet stand-in;
full Diamond/rebuy/provider, legal-hand and deployed qualification are open.

The bound is 10,000 candidate identities; overflow refuses rather than claiming
a complete read. At a 13:39 UTC read, seven running/completing PKO events had
at most 103 candidates. A local nearly-10,000-row indexed proof took about half
a second. Larger-history performance and a durable dependency index remain
explicit work; this is not a platform-wide performance certificate.

Historical missing claims, old stale snapshots, ordinary/mystery residual
finalization, versioned Hi-Lo eligibility and full MTT acceptance remain open.
Installation, protected CI and exact served recovery are recorded separately
from these source tests.

body/owner/ACL/security/path/volatility postimages at 13:47:07 UTC. The exact

a read-only evaluation of all 38 candidates in the affected Brunch Special
PKO PLO8 event found 26 clear proofs and 12 waiting on unsettled incoming
heads, with zero unknown proofs. This validates current accepted evidence and
dependency classification; it does not establish that the engine has retried
and paid those claims or that historical recipients have been reconciled.

The follow-up privilege migration repeats the original private claim and
service-only collector revocations under exact source/metadata guards. This
lets the unchanged static authorization checks see privileges that PostgreSQL
already preserved during replacement. The installed R37 migration bytes stay
unchanged. Native replay and five direct caller-role refusals passed; no new
caller receives execution and no financial row changes.
