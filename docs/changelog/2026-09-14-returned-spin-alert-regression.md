# A returned Spin draw must not become another unpaid prize

A received historical critical alert said a cancelled Spin owed its whole 3-chip draw. Its actual reserve journal shows the entire draw returned at cancellation, and all three entrants have matching completed one-chip refund obligations and wallet credits. The detector in use when that alert fired did not subtract reserve returns. Later September 8 and 9 migrations corrected this view. The current database returns no unpaid row for this exact event, despite its stale escrow counter still showing 0.24.

The new required PostgreSQL 17 test runs the actual old repository view and reproduces the false 3-chip shortage. It then runs the latest direct view declaration from the repository and checks that its canonical definition matches the captured production hash. Twenty-four checks cover full and partial returns, stale and missing escrow, unpaid funded prizes, partial credits, exact event and ledger-kind identity, running-event exclusion, terminal grace, and real concurrent commit/rollback visibility. The fixture uses synthetic identities and invokes no financial writer.

The test reads the actual migration declarations rather than a separate copy of the repaired query. A future replacement requires explicit review of its identity and the regression checks. It extracts only the view declaration; it never runs surrounding historical repair statements. No production migration or accounting mutation is added by this change.

Qualification is limited to the positive unpaid-prize predicate used by the existing checker. The existing missing-escrow fallback can also return a negative summary after netting both a draw return and entrant refunds; that observed output is preserved in the test evidence. This suite does not certify that separate overpayment summary, broader escrow cleanup or payout execution. Original historical source flags remain untouched; the operational investigation closes only after normal CI and source publication are verified.
