# Prize audit recognizes a funded Spin correction

The received seven-day backlog contained 27 prize-disbursement alerts for one Spin. Its original 10-chip drawn prize had been compared with the 3-chip entry pool. That comparison was corrected on September 7. A separately authorized September 9 correction then funded another 1.40 through the house ledger and escrow, bringing actual prize credits to 11.40. The current audit still reported that funded 1.40 as an excess because its allowance only included the drawn prize.

The audit now recognizes a positive finite Spin overlay only when the escrow amount exactly matches posted house-to-prize-liability journal funding for that tournament and destination. A missing or mismatched record leaves the discrepancy visible. The comparison uses the larger of the displayed pool and the drawn prize plus proven overlay, so a pool already showing the correction does not count it twice. Existing non-Spin rules, historical acknowledgments, reporting windows and service-only access remain unchanged.

Forty real PostgreSQL 17 checks include the unchanged-function counterexample, a genuine excess above the funded correction, incorrect funding identities, non-finite values, concurrent uncommitted versus committed funding, read-only execution, ACLs, migration replay and drift refusal. The required accounting CI job runs this suite. The engine keeps its existing FeeReconciler RPC caller and durable alert writer.

This changes the detection function only. It does not pay, claw back, relabel or mutate any financial record or historical alert. Source checks, normal publication, installed definition and live historical readback require separate evidence; broader payout and operational-backlog completion are not established by this repair.
