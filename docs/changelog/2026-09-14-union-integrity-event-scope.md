# Union integrity reports observe their own events

The authenticated union-operations report selected direct chip transfers across every union. The real PostgreSQL function returned Union B's sender, recipient and amount to Union A's authorized owner. It also wrote a warning for A and then suppressed B's warning because the incident window matched only the source name.

The report now scopes direct transfers by the transaction's club, wallet results by their table or tournament, and rake by its event or club. The union's host club remains eligible. Repeated membership under the same agent no longer multiplies a player's result, and being an agent elsewhere does not hide an ordinary transfer here. Incident suppression uses the exact union identity and a transaction-level union claim, preserving separate warnings under concurrent reporters.

The existing caller authorization and response keys are retained. This change reads financial events and writes operational findings; it does not transfer funds or change settlement outcomes. The migration refuses unknown report or caller-authority definitions and preserves authenticated-overseer/service execution with anonymous execution closed.

Validation: three original native counterexamples, 43 PostgreSQL 17 checks, real concurrent reports, rollback, actual trigger rejection, cross-union and own-union cases, anonymous and unrelated-owner refusal, and migration replay/drift tests. Required accounting CI runs the native fixture. Installation and live scope verification remain separate release steps.
