# Tournament break release carries its resumed clock

A synchronized tournament break previously cleared `on_break` before a separate, detached write saved the credited level anchor. A fresh reader could therefore see play resumed with the pre-break clock. The manager now writes both values together, verifies the returned event/status/level/anchor, and arms its existing timer from that exact acknowledged anchor without another write. An uncertain response retains the same proposed anchor for the existing retry.

Replacement managers use the same release path for expired recorded breaks. They restore the durable pause before admitting either existing-table or rebuilt dealers, and those dealers require the existing explicit resume signal. A countdown expiring cannot authorize cards before the release acknowledgement. Future booked starts, outstanding blind transitions, add-on pauses, terminal cleanup, maintenance thaw, lifecycle fences, and hand-for-hand ownership retain their separate rules.

Validation on the composed booked-start and protected-main source: 184 tests across 13 focused server files, 20 existing booked-start law checks, and the server compiler passed. The original clear/write sequence failed four new clock-result controls; both original replacement paths dealt a hand while acknowledgement was withheld and now pass. These are isolated source counterexamples and regression evidence, not a claim that this change has been deployed or that any particular live hand was caused by the replacement ordering. No SQL, financial, maintenance, engine-base, or release-path change is included.
