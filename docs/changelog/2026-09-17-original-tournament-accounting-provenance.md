# Original tournament accounting provenance

Original tournament charges already retained an immutable refund entitlement and exact journal row, but ordinary entry, rebuy, re-entry and add-on charges did not bind that entitlement to the registration lifecycle that actually received the entry. The original money owners now retain that binding before returning success. There is no historical reconstruction and no new payer.

`tournament_participant_funding_receipts` retains the actual registration, original entitlement, debit ledger and wallet receipt, funding club, asset, operation and original row snapshots. The original charge trigger returns its inserted entitlement ID to its immediate private caller; the caller clears the transaction-local slot before charging. Zero-charge admission records explicit zero without a fabricated journal row. Diamond custody results are retained separately and never certified as chip-wallet funding.

`tournament_accounting_credit_receipts` retains the original accepted key, actual credit ledger, wallet transaction and payout ID from `fn_credit_and_log`. Its credited club comes from the actual ledger write. Original payout routing and its historical fallback behavior are unchanged. A legacy wallet receipt can contain a balance from a different home club; that receipt balance is not used as actual credited-club evidence.

`tournament_obligation_events` retains original insert/update/delete transitions, instrument, owed and paid amounts, registration context, exact original credit receipt for the cumulative payment, and immutable refund-tranche references. All three tables carry the original `xid8` transaction identity for the separately owned weekly boundary capture. Event time is not represented as commit time. No legacy rows are seeded; first observed updates do not certify an earlier opening balance.

Evidence tables refuse update, delete and truncate, allow private original owners to insert, and expose service-role reads only. Existing original function identities, security configurations and ACLs are preserved and checked against exact installed preimages before replacement. New money-table triggers declare themselves in the existing registry.

The existing PostgreSQL registration/refund/Heads-Up payout runner exercises the candidate owners in its normal `--with-heads-up-payout` path. It retains existing entry, purchase, refund, launch, late-failure, concurrent replay, pool conservation and wrong-recipient checks, plus exact evidence links, immutability, horse/cross-club provenance, zero-charge admission, original-source red proof and missing-reference rollback. The final transaction check requires the obligation event and original credit receipt to have the same transaction identity. Captured functions are checked byte-for-byte against the candidate; auth, maintenance and winner inputs remain controlled native-fixture inputs rather than live gameplay or HTTP proof.

These are prospective financial facts, not a certification of beneficial P&L ownership or open tournament equity. The approved chip standard specifies prize/bounty liabilities and fee revenue but does not define an active player's share of an unallocated pool as original cost, refundable value or ICM. An attributed obligation has a factual outstanding amount of owed minus paid in its original instrument; unallocated open-entry equity and legacy coverage remain uncertified. This source package has no production application or publication authority of its own.
