# The tournament overview keeps its recorded break

The running tournament overview previously derived its countdown only from the blind level and `level_started_at`. A synchronized break leaves that level in place, so the overview advertised a level ending even with `on_break=true`. The table lobby modal embeds the same page and inherited the defect.

`DetailOverviewTab` now renders the persisted event pause and the existing `useMaintenanceBreak` presentation as separate authorities. The recorded event pause replaces the level countdown with an expected resume countdown or an explicit waiting state. Missing, invalid, or expired deadlines cannot resume it. Maintenance last-hand, finalizing, and resuming messages come from the existing hook; an unpaused event retains its clock during the last-hand announcement. The committed level and blind amounts remain unchanged, and the decorative level progress meter is hidden while paused. No new scheduler, poller, or authoritative game-state writer is added.

The current engine clears the persisted break flag before asynchronously persisting the credited level anchor. An overview that observed the pause keeps showing it across that gap until a newer committed anchor or level arrives. A missing or invalid old anchor is represented as unknown; after the pause clears, its first valid persisted anchor can resume the same level. Global maintenance idle alone cannot release that observed hold. The hold is scoped to the event and does not carry into another event or completed results. **A cold mount during the engine's separate clear/anchor writes cannot recover the earlier anchor identity.** This client change does not close that engine atomicity gap or claim full resume certification.
