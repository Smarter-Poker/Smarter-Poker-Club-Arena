# External terminal receipts retire the entry-window owner

Breakfast Turbo completed through its retained original-witness transaction on September 18, but its live manager still held an entry-reprice wake. The entry authority correctly returned `tournament_not_running`; the sweep returned before reaching its durable-winner finish stage. The stale clock and manager consequently remained live although the database had already closed every table and seat.

The exact entry-window refusal now asks the existing immutable terminal receipt owner for its stored mode and winner. The existing serialized outcome resolver verifies that receipt, including version 3 player finality with unresolved fee custody. Only that verified result enters the existing non-money cleanup: retire the blind clock, stop and unregister the receipt's exact dealers, then stop the manager. Deal receipts use their existing presentation tail. There is no settlement/payment request, new migration, timer, or added read on ordinary entry ticks. Missing, unreadable, malformed or uncommitted evidence cannot retire an owner; lifecycle replacement is checked again after the read. A partial cleanup keeps its receipt for the existing cleanup-only continuation.

Validation: the actual sweep and entry consumer reproduced three failures on the unchanged source, then passed with the repair. Seven affected suites passed 220 tests; the final connected suite adds version 3 and deal-tail coverage and passes 13 tests. The server TypeScript compiler passed. The native database authorities are unchanged; existing SQL qualification is retained. Protected checks, engine publication and live manager-retirement proof remain separate delivery requirements.
