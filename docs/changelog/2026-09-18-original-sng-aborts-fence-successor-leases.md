# Interrupted originals retain their identity after lease takeover

Two original heads-up SNG hands retained reserved permits, pre-manifest parks and uncommitted snapshots after their events acquired new lease generations. Their stored seats and registrations still held 1,000 chips per player. The existing same-generation abort correctly refused these objects because their original leases no longer existed.

The forward migration adds `fn_f06_abort_successor_unsettled_hand`. It keeps the original permit, hand, lifecycle and park custody unchanged, separately requires the current lease generation, instance and engine identity, and drains that current lease before arbitrating with the existing global, tournament, hand and player lanes. A concurrent takeover makes the supplied identity stale and refuses the abort. A dispatched or accepted hand still wins over abort.

The immutable abort receipt records both the original generation and the current generation being retired. The existing lease, heartbeat, request-admission and resurrection guards consult both. Original-hand dispatch, atomic settlement and history remain permanently fenced by the original receipt. Only the original pre-manifest park is withdrawn and its snapshot marked complete. Wallets, seats, registrations, prizes, prior hands and played statistics are untouched. The same-generation abort contract remains available unchanged.

The existing required native F06 runner now verifies the successor path too: the original refusal, real admitted-writer drainage, queued takeover, both generations' resurrection attempts, settlement competition, exact replay, unchanged 4,000 chips, preserved original identity and fresh-generation admission. Migration admission acquires the complete two-relation lock set within one three-second transaction-local budget. The first lease gate queues within the remaining budget while owning no application relation locks, draining short lease-to-receipt readers. Receipt admission never waits while holding that gate. Contention rolls back partial locks before yielding, and no schema work starts before complete admission. Installation and live execution require exact predecessor catalog checks and actual freeze restrictions. Database fencing is separate from certified engine replacement and live resumption.
