# Smaller tournament reads and valid banks through long outages

Every tournament hand refreshed blinds by loading the complete table configuration and its club relationship, then consuming only small blind, big blind and ante. The existing refresh now reads those three fields under the exact table and tournament identity. It still reads before each deal, keeps lifecycle/owner fencing and bounded transient retries, rejects delayed replies or retries after a tournament reassignment, and emits the same table metadata event only on a change. Initial table admission and its arena checks retain their complete configuration read.

A maintenance outage exceeding twenty minutes discarded a valid parked time bank even when its completed hand and seat occupancy had not changed. Bank restoration now uses those authoritative identities instead of the presence TTL. Startup still proves completed history, excludes active crash recovery, rejects unreadable state, validates the snapshot and its timestamps, and binds the balance to the same occupancy before restoring it. Existing live banks win. Standalone presence keeps its existing freshness rule because it lacks the bank's hand/occupancy proof. No stored timestamp, balance or player history is rewritten.

The new prolonged-outage tests fail on the previous implementation in all four formats (cash, MTT, Spin and Sit & Go). The repaired focused suite passes 78 cases, including unchanged-bank round trips, replacement occupants, later hands, failed reads, duplicate debit protection, preserved entitlements, owner replacement, late replies and current blind values. Both client and server compilers pass. Two additional regressions fail without the tournament-identity continuation guard and pass with it. A real startup rehearsal also preserves the saved balance after a 48-hour outage. Protected CI, merge, certified engine activation and production behavior remain separate evidence.
