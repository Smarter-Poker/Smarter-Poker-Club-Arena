# Accepted zero proof follows the stopped original table

The retained-hand authority counted zero-stack registrations across a tournament
but accepted their sealed outcomes only on the interrupted table. Noon retained
a valid accepted zero on a different original table, so even the full stopped
owner witness could not classify the complete registration set.

The forward migration extends only the exact retired-owner snapshot. Its existing
complete physical owner proof must include the zero's table, which must belong to
the same event. The original generic retained snapshot keeps its selected-table
rule and delegates only its existing absent-lease, immutable-witness branch.

Every zero requires its accepted atomic hand, sealed payload, exact vacated seat,
independent succeeded stack key and exactly one final `hand_stacks` settlement.
The canonical receipt retains both financial rows. A later hand involving other
players is allowed; a later accepted write to this player anywhere in the event
refuses the proof. Original permit disposition still credits zero and does not
change registration, occupancy, rank, financial or mixed movement records.

The maintained native PostgreSQL qualification reproduces the original refusal,
then tests successful zero-credit disposition and exact replay, unchanged business
rows, the generic refusal, missing or changed receipts, duplicate/nonfinal
settlements, seat-generation drift, incomplete stopped-owner evidence and later
player writes. The existing accounting runner invokes it through the retired-owner
qualification. Source tests verify this connection and generated migration bytes.

This source change does not attest production retirement or execute either
original operation. Fresh physical evidence, immutable original operation IDs,
installation and the root-owned operational probe remain required.
