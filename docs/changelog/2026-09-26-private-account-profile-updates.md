# Private account changes reach every mounted route

The unpublished `profiles` row listener could not deliver metadata, interface preferences, or diamond balance changes from another device. The app now owns one private `profile-account:<user id>` channel. Its database trigger emits only the account id and changed domain names, with one signal for a mixed update. The client coalesces affected reads and routes authoritative results into the existing profile, settings, and diamond consumers.

The source predicate watches displayed profile metadata, `theme`, `achievementNotifications`, `settlementAlerts`, and canonical `profiles.diamonds`. Existing table controls and artwork keep their existing carriers. Per-hand statistics, horse state, presence, unchanged values, and internal/obsolete settings do not trigger messages. The signal has no financial values or table fan-out, and it grants no client producer or function execution. The established diamond mirror remains unchanged.

Account identity and request revisions fence stale reads and same-browser events, including A-to-B-to-A transitions. Hidden tabs defer reads; initial mount, visibility, online recovery, and channel rejoin reread authoritative values without a polling loop. Failed or invalid reads preserve known state. Notification failure cannot roll back a source edit.

Auto interface mode remains the persisted preference while each device resolves its current system choice and follows media changes. Explicit Light/Dark can leave Auto even when its effective color is the same. The Settings page preserves unsaved controls during a remote update; old-account mode-save failures cannot roll back the new account. Existing appearance signals also notify mounted profile views through the established bus.

Qualification includes isolated PostgreSQL 17 execution of the actual migration with owner/other-account/anonymous policy checks, forbidden client signal insertion, actual authenticated edits, atomic rollback, send outage, and concurrent canonical diamond changes. The baseline fails the missing-signal assertion. Client regressions cover scoped domains, coalescing, local edits versus delayed reads, identity changes, timeout, unmount, malformed cache, invalid balances, reconnect/visibility, and Auto persistence. Four added cross-account/Auto tests fail on the predecessor and pass on the candidate. The existing production customization journey adds real two-device private metadata/preferences delivery, rendered profile names, independent system themes, durable readback, and another player's isolation using its disposable identities.

No engine behavior, money mutation function, profile publication, production player balance, or historical financial record changes. SQL installation, protected checks/merge, publication, both public build identities, and the actual live journey remain separate evidence in the audit task.
