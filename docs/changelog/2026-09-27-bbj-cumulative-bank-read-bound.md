# BBJ meter cumulative bank reads

After the first scoped indexes were installed, the existing hourly audit completed once in 114.56 seconds, then failed eight consecutive runs at its unchanged 120-second ceiling. Three samples of the natural 13:38 run showed I/O waits without lock blockers. Those samples are not a complete wait history. The earlier 04:38 run had completed in 40.96 seconds before the indexes; neither one success nor these independent measurements establish a causal billing reduction.

The meter needs cumulative journal totals from the opening balance, but category-based flow counters only need rows after the previous reading. Reading every historical row's category, types and unbounded labels forced wide heap access. The new statement keeps both calculations and the bank balances in one PostgreSQL snapshot. A covering partial index stores only UUID/time, numeric(15,2) amount and one of the three canonical incoming bank labels, with an explicit 64-byte label bound. A complementary narrow index retains every exceptional incoming label. Outgoing legs use the existing narrow index, with NULL-safe exclusion of rows already included on the incoming side. Recent flow counters retain the original predicates, opening/previous timestamp intersection and arithmetic.

Only the read statement changes. Authorization, opening balances, snapshot timestamps and writes, rounding, basis version, failure counting, caller behavior, financial records and the existing schedule/time limits remain intact. No financial action is invoked in production for qualification. The exact exception count could not be measured within a single authorized 30-second read-only scan; the exception path is unconditional and its correctness never depends on exceptions being absent.

The maintained native PostgreSQL 17 check compares complete returned rows with the captured predecessor and independent golden cases. It covers arbitrary/oversized and NULL labels, old unvalidated enum values, self/cross-pool legs, generated selector combinations, timestamp boundaries, concurrency, authority/type/index drift and real interrupted concurrent-index recovery. Its resource regression compares actual buffer work under custom and generic plans on the same wide synthetic ledger. Production performance and natural audit completion require separate installed/live evidence.

Build the two online indexes from `scripts/ops/build-bbj-cumulative-bank-indexes-concurrently.sql` as separate, owned top-level statements with the existing 180-second lock and six-minute statement budgets and full maintenance runway. The short migration refuses missing, invalid or wrong definitions and changes only its exact financial preimage. Recover unknown operations before any retry. The original indexes remain because they serve the recent interval and outgoing paths.
