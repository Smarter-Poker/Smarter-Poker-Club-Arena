# Retained movement refusals remain inspectable

The existing authenticated tournament diagnostic could show a stopped original
engine while omitting the local permit and claimed movement boundary that can
prevent its release. The bounded original-engine selection now reads those two
existing synchronous getters and the manager's last named quarantine clause.
It exports only the permit phase, never its custody binding. A missing, malformed
or throwing getter remains unavailable, distinct from an observed absent permit
or unclaimed boundary. A null last refusal means unobserved or cleared, not proof
that a release certificate ran successfully.

The regression exercises the actual engine getters and hand permit, verifies no
authority callback or RPC runs, preserves the physical original across stop and
replacement, and checks unknown/error states and immutable response objects.
All original selection bounds, authentication, lifecycle and custody behavior
are unchanged. This is diagnostic evidence, not a repair of a stuck tournament
or permission to release a retained owner. It cannot retrospectively inspect a
prior process after replacement; a production restart must never be used merely
to acquire this missing observation.

The local full client suite also exposed a five-second source-law timeout in
the notification finding guard. It now loads the existing complete, ordered
migration corpus once, preserving the latest-definition selection, every
assertion and the existing timeout. The prior failing run remains recorded;
the changed candidate requires a fresh full result.
