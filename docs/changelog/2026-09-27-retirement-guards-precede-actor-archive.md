# Retirement guards precede actor archival

A later certification cleanup migration placed actor archival and detachment before the existing retained-identity decision. With the combined installed function, a frozen request returned `success: false` after its actor pointer changed, and opening-grant actors no longer reached the custody checks. The correction relocates that exact existing decision before the archive block. Ledger actors remain attached and use the established Auth soft retirement. The archive table, immutable triggers, financial records, and non-ledger disposable cleanup remain unchanged.

The migration refuses an unexpected function definition and preserves the function's OID, owner, privileges and settings. The existing required PG17 qualification now loads the captured combined cleanup and actual actor/freeze triggers. It reproduces the old frozen-refusal mutation and passes after the correction, including original role, identity, nullable membership role, custody, partial outcome, duplicate, lock and terminal-state cases. An unrelated production financial trigger is not simulated, and no production fixture was written. Installation and provider/Auth acceptance are separate evidence.

An automatic verification using the superseding cleanup had already archived two original certification actor rows and detached their live pointers at 03:52:59 UTC. Readback verified the other ledger columns match the archive. That historical operation is recorded separately; this schema correction does not recreate an Auth identity or rewrite those records.
