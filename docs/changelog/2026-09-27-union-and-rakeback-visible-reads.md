# Union and rakeback views read their actual current state

Unpublished table listeners could never refresh the union dashboard or external rakeback availability. The applications listener refreshed dashboard metadata without reloading the application list. The raw administrator table exposes only the caller under RLS, so a union owner could see an empty roster.

These mounted views now use the existing visible-read helper every sixty seconds and on rejoin/manual refresh. Hidden and offline views stop; reads do not overlap and retain the existing fifteen-second abort budget. Account, union and application-filter generations reject late responses. Successful empty reads remain empty; malformed or failed reads retain known data and show an error. Existing command bodies, operation identities, registration, rewards and financial writes are unchanged.

A narrow `fn_union_admin_directory(uuid)` binds `auth.uid()` to the requested union owner or current valid administrator. It returns only same-union roster identity, role/date, pseudonym and Arena avatar. It preserves raw table policies/grants and all financial authority. Native PostgreSQL qualifies actual owner/admin/foreign/anonymous/null/service identities, committed and concurrent revocation, rollback, dependency drift and replay refusal. The existing required accounting shard 4 runs these inputs.

Mounted regressions cover external lists/balances, delayed account/route/filter replies, revocation, failures, malformed amounts, hidden/offline pause and reconnect. The actual Supabase SDK talks to a local HTTP peer to prove external rakeback availability reaches the mounted page without a bus event or money command. That fixture is protocol/UI proof, not a production payout or RLS certificate. The predecessor renders zero after the external period appears; the regression fails before and passes after.

Existing reserved-account production route checks now require both bounded owner rakeback reads while remaining on the page, and exact authenticated BBJ ledger facts rendered from both union and standalone club pool requests. They do not create roles, funds, games, payouts or financial fixtures. Live results remain separate from source qualification. Production union-operator cross-device financial actions are not fabricated for proof. The World Hub leave-list error path is a separately delivered prerequisite for truthful upstream failures.
