# XMTT Reads And Renders The Requested Events

The XMTT lobby rendered the first 1,000 database rows as full consoles and read each legacy waitlist position individually. Its mobile-fit case exceeded the existing 30-second budget. The lobby now initially renders 50 events, offers explicit Load More, and reads exact scoped counts independently of the displayed array. Filters keep case-insensitive status matching and the original start-time order, with an ID tie breaker. Expanded lists are refreshed only to the depth the player requested.

Legacy waitlist exits use authenticated owner-scoped batches of up to 50 displayed event IDs. Failed or malformed reads remain unknown and retain previously known exits. Account, club, filter, cancellation and delayed-detail guards keep old responses out of the current view. Existing registration, refund and waitlist commands and approved artwork are preserved. The existing 30-second observation runs only while the view is visible and online; no database publication or financial writer was added.

Mounted component regressions cover 1,000 events, expansion, filter reset, account and club changes, delayed reads and failure retention. Query tests verify exact count, union/type/filter scope, stable order and batch bounds. The existing production routes suite adds a read-only reserved-account case; the original 30-second mobile-fit gate remains unchanged. Local Chromium reproduction uses the actual component and console artwork with instant fixture reads, so its timing isolates client work and is not a production latency or billing claim.
