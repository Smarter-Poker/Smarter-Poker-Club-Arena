# Held fee operations admit both shared projections before writing

The uncommitted 18-event held-fee operation met a production deadlock with the live commission batch on September 30. Both outer transactions retained earlier commission-rollup row locks while requesting the opposite rows. A separate observed cash/projector deadlock involved player_stats. Sorting one trigger statement would not fix the transaction-wide ordering.

The forward migration changes only fn_ca_recognize_held_tournament_fees_by_owner_basis. It preserves operation replay and the deterministic existing event-member lanes, then freezes the exact tournament routing and admits its existing host club-wallet and non-private union-wallet rows in deterministic order with NOWAIT. Only after those bank rows are held does it admit agent_commissions and player_stats together with SHARE ROW EXCLUSIVE NOWAIT before any financial write. A busy ordinary writer refuses the whole call immediately. The error must escape and roll back the admission; callers must not retain an open explicit transaction. The cash post-commit projector can retain bank-row locks before entering player_stats, so taking the projection relations first would introduce another waiting cycle. Its actual bank-before-stat path is preserved; a busy selected bank refuses before any projection relation is acquired. Existing source union IDs must match the locked event route and every required wallet must exist, so the payer cannot fall back to an unadmitted bank. The live read-only predicate passed for all 18 events, covering two host club-wallet rows and one union-wallet row. Common financial writers, shared accounting-week locks, amounts, terms, prize records and existing exact journal/conservation checks are unchanged.

The supported caller first issues SET statement_timeout='5s' as a separate top-level statement, then ends its single autocommit financial request with one DO or SELECT. No subsequent read belongs in that same request: durable readback uses another call. The function removes its old 120-second setting and refuses a disabled or longer configured caller budget. PostgreSQL does not expose its armed statement timer to ordinary SQL; this configuration check does not prove an arbitrary internal-only SET armed a timer. The maintained native qualification explicitly demonstrates that distinction and verifies cancellation through the real nested payer with its existing 30-second configuration.

Regression qualification stays inside the existing required held-fee native phase. Two backends reproduce controlled opposite-row cycles on the actual commission/stat projection relations. Real owner calls prove immediate refusal without effects when either ordinary DML relation is busy, event-lane admission preceding bank and relation admission, a concurrent bank owner retaining access to player_stats after the fee call refuses, predecessor drift refusal, and rollback at the outer deadline after reaching the canonical journal path. Existing two-event union/standalone, shared-G cash concurrency, journal shape, replay, context restoration, immutable prize and owner-basis assertions run against the new function. Controlled row ordering is not represented as a replay of the entire historical cash batch or as proof that every common writer is universally deadlock-free.

This migration installs source only. The fixed production operation remains ba59496d-9291-4df3-bdaa-a2721b054e81, 18 events and 741.86 held fees. Its qualified self-aborting probe, committed execution and separate exact reconciliation belong to the existing operation owner.

Native qualification records the measured outer cancellation, rollback snapshot, internal-only SET negative control, existing 34 owner assertions and 13 member-lane assertions, and concurrent admission checks. Publication and financial execution remain separate evidence layers.
