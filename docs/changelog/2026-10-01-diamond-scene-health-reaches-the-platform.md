# Diamond scene health reaches the platform (2026-10-01)

Found in the verification pass after the mobile graphics programme.

Phase 2 gave every Crash, Plinko and Donkey Cross visit (and, in Phase 4, every wheel spin) a one-line summary of how the device drew it, and a report whenever a scene could not draw. Those went only to `src/lib/analytics.ts`, which sends nothing unless `VITE_POSTHOG_KEY` is set, and no build of this platform has ever set it: the live bundle carries no key. Every summary was being dropped, so the question the phase existed to answer had no answer.

The same numbers now also go to the platform's own database. `fn_record_diamond_scene` adds each visit to `diamond_scene_daily`, a daily rollup per game, kind of device, renderer and final quality tier with no user in it (migration `20261001214213`). It clamps every value and refuses unknown games, devices and failure reasons, and it is fire and forget in the client, so a lost report never touches the game. A visit that ends by closing the tab now sends its summary on `pagehide` instead of never. Platform admins read it on the admin dashboard as **Diamond Scene Health**, beside Card Slide: frames a second while moving, the share of slow frames, how often a scene dropped to a lighter tier or was drawn by the CPU, and how many could not draw, per game and per iPhone or Android browser, app, or computer (`fn_diamond_scene_health`, empty for anyone else). The app runbook now points there.

Tests: `tests/unit/sceneTelemetry.test.ts` (the rollup gets the same numbers once, with no user; a failure is recorded with its reason; the tab closing sends it once; a refused write never throws), `tests/components/DiamondSceneHealth.test.tsx` (the panel per game and device, silence when it is not yours, a plain message when the read fails). The SQL was exercised on `pg_temp` copies before the migration: clamping, the unknown-input refusals, failures without a session, and the read's shares.
