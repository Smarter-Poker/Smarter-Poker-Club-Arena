# Final-table cleanup commits bounded pages

The historical 20261005111523 cleanup updated roughly 310,000 estimated invalid final-table flags in one transaction. Its interrupted transaction held locks and coincided with live settlement timeouts; the transaction later aborted, while its independently recorded migration ledger row remained. The expected constraint and legacy privilege revocations were absent. Preserve that ledger and do not replay the historical file.

Forward migration 20261005230204 installs a manual, postgres-owned continuation. Each request visits at most 200 primary-key rows, keeps normal triggers, refuses locked rows without skipping, and commits its request receipt and cursor atomically. It requires the original exact client/engine seal and current matching heartbeats, refuses maintenance, and requires a top-level statement timeout of at most five seconds. Ordinary roles cannot execute it. No hot-table foreign keys or scheduled callers are introduced.

The existing dispatch-only Apply Merged Migration installer accepts `final_table_pages` (1 through 3000) and `final_table_operation` (UUID) only for that exact already-installed helper migration with matching recorded bytes. Each page is a separate autocommit query with a five-second statement and six-second transaction deadline; every durable receipt is reread before advancing. The finite operation stops at completion, its page limit, 240 seconds, or the first failure/unknown result. It never retries, applies the finalizer, or initiates a release. Retain the logged request identity and read its durable outcome before any subsequent operation.

After pages complete, explicitly install forward finalizer 20261005230230 through the same installer. It refuses any remaining invalid row, retains original prerequisite/seal/heartbeat checks, legacy permission retirement, MTT transition receipts/events, constraint validation and final invariants. Its entire transaction is capped at ten seconds (production PostgreSQL 17.6 supports this), with five-second statements and 500ms lock admission. A refusal rolls back; it is not completion. Original ledger 20261005111523 stays unchanged.

Native PostgreSQL 17 coverage extends the existing customization harness with 450 independently generated invalid rows: 200/200/58 visited pages including eight valid predecessor rows, duplicate identity without repeat triggers, role refusals, missing timeout, freeze, locked row without cursor movement, finalizer refusal before completion and for late invalid rows behind the cursor, current-engine mismatch, and the original final invariants. Installer tests cover exact-file/count/identity admission, autocommit/readback order, missing/unknown outcomes with no retry, and dry run. This is transaction correctness qualification, not a production-scale trigger benchmark. Installation and refreshed cutover seal remain separately required.
