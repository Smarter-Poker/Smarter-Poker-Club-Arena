# An operator pause survives engine replacement

The operator pause endpoint changed only an in-memory engine flag. Reconstructing an engine defaulted that flag to false, allowing an operator-held table to resume. The new service-only native authority binds each authenticated command to its original identity, current lease generation and expected version. The engine awaits durable acknowledgment, restores the authority before readiness or dealing, and releases only the operator's hold on resume. Unknown writes remain unknown and fail closed; definitive refusals restore the known authority without leaving an unauthorized pause.

Management reads expose an additive `operator_paused` value and the original command emits one existing scoped management event. Raw table status and structural editing protections remain unchanged. The separately dependent client consumes that field and requires the matching durable command response.

The existing release transaction requires the exact installed native contract before new release work. First upgrade captures the complete original live fleet inside the certified maintenance boundary, fences operator setters and future admission, and imports one original immutable handoff. Interrupted acknowledgment can read that same handoff without importing again. A reconstructed predecessor requires the fixed pre-index compatibility preload and readonly bundle; rollback restores the latest native holds before any table starts and temporarily refuses only old operator pause/resume requests. The unchanged original process is retained without a healthy restart. Missing or partial recovery material refuses recovery rather than selecting ordinary old boot.

Qualification remains component-specific: isolated real PostgreSQL and engine cases, pure legacy-boundary tests and source/run-spec checks do not prove the full original boot, installed production schema, actual cutover, or live operator acceptance. Those remain prerequisites to claiming delivery. This change does not modify financial settlement, table status, independent maintenance/hand-for-hand holds, player clocks or the release reserve.

The closed predecessor recipe is derived from the actual current 6b1 runtime's Node, immutable image and fourteen compiled file pins, with the same fourteen source files independently compared. This is provenance, not full boot qualification. Before capture, the original transaction marks the recovery requirement durably and disables automatic restart for the exact old container and existing autoheal container. The supervisor checks the run specification before a start and keeps the unchanged captured old process fenced. Original restart-policy receipts restore autoheal only after a compatible replacement. Added fence work and observer work share the original forty-second allowance and preserve the 245-second recovery reserve.
