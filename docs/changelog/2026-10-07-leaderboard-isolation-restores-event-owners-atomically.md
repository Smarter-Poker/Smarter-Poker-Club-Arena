# Leaderboard Isolation Restores Event Owners Atomically

The current-schema preflight reached the remaining archive restore but failed with a destination permission error. Its private error was removed by owning cleanup, so the first failed statement is unknown. Independent read-only catalog evidence nevertheless establishes a concrete PostgreSQL 17 restore hazard: eleven event triggers belong to the non-superuser `postgres` role, and PostgreSQL refuses an event-trigger ownership transfer to a non-superuser.

The harness now reads distinct non-superuser event-trigger owners as metadata only. In the disposable database, it renders the unchanged remaining archive with the same official PostgreSQL client, then uses one `psql --single-transaction` connection to temporarily elevate those owners, restore every selected archive statement including ownership and ACLs, and restore the original `NOSUPERUSER` attributes before commit. `ON_ERROR_STOP` rolls back the combined transaction on failure. No source role, production financial behavior, archive owner or grant is changed or omitted.

A fail-closed lexical guard checks the rendered native archive for top-level transaction boundaries and unexpected psql commands while preserving quoted routine bodies and nested comments. It accepts paired native restrict commands only. This is a guard for the trusted native archive, not a general untrusted-SQL sandbox. SQL-standard unquoted `BEGIN ATOMIC` routine bodies remain unsupported and fail closed; a current source metadata read found none. Exact source/destination catalog comparison and verified owning cleanup remain required before any qualification.

Safe failure evidence now retains fixed permission categories, numeric known-file line ordinals, and numeric archive entry/static object-kind context where available, without printing private SQL, names, role attributes or raw errors. Regression contracts cover transaction/connection escapes, comment and identifier token boundaries, owner-statement agreement, private-output refusal and inherited Auth preparation. Source checks do not qualify the actual database restore, Auth authorization or payouts; those still require their protected runtime results.
