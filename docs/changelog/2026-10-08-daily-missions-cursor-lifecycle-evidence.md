# Daily Missions cursor certification follows the actual lifecycle

The original production run 37782381046 failed its zero-cursor assertion while its own socket counter advanced from 10 to 11. A socket created during the observation interval contradicts the assumption that no transport lifecycle changed. The retained report has no request or join timeline, so it cannot establish the exact cause of the single read or demonstrate a product polling defect. The dashboard catch-up and broadcast hooks are unchanged across the tested 82c56, aab0 and 68fa releases.

Certification now observes outgoing mission joins and their correlated successful private-channel replies, plus visible-tab resume events. New socket creation, another channel, failed replies, unmatched references and duplicate replies never authorize a cursor read. During the same 20-second interval, every cursor read must have a lifecycle wake; a healthy interval with no wakes still requires exactly zero reads. The existing forced interruption, degraded/live UI checks, one-or-two catch-up read bound, reward settlement and strict cleanup remain unchanged. A bounded privacy-safe timeline is attached even on failure. No runtime, engine, database, financial or dashboard behavior changed.

Focused regression coverage includes the original 10-to-11 socket scenario with a genuine mission rejoin, unauthorized repeated reads, unrelated/failed/duplicate joins, both Phoenix frame formats and resume coalescing. Local checks qualify the observation helper and preserved contracts; only a natural deployed certification run can prove the connected production behavior.
