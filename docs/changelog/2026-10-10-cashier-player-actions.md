# Cashier Player Management And Transfer Actions

Cashier player names open the existing player management page. Select opens that player's transfer dialog immediately with Send Out, Claim Back, Send Ticket and Send Diamonds. Claim Back preserves the existing ten-minute reversal authority and scopes the list to the selected player. Diamond transfers prefill the recipient and preserve accepted-friend checks, review, durable intent and receipt recovery. Pending transfers prevent switching transfer types.

The shared server eligibility predicate now excludes profiles whose authoritative status is deleted, across cashier lists and transfer authority. Names are never used to decide deletion. The October 10 owner instruction requires their cash chips to return to the main club bank. The account lifecycle writer locks member, agent and club custody, preserves held and locked chips, refuses platform freeze and browser execution, journals each source movement and writes bank receipts. Account deletion, later wallet credits and hold releases invoke it within the original transaction. Live seats and all game stacks remain untouched.

Native PostgreSQL qualification covers deletion, active-name preservation, permissions, freeze, concurrent calls, repeat calls, conservation, later credits, protected holds and caller ledger context. Required accounting CI runs this qualification. Production installation, rolled-back financial proof, the exact historical settlement and publication evidence are recorded separately in the task checkpoint.
