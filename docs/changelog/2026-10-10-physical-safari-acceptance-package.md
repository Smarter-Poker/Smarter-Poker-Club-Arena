# Physical Safari acceptance package

The launch acceptance process lacked an iPhoneOS XCTest package for a genuine Safari device run. This change adds a standalone host and system Safari UI tests, a deterministic Xcode project generator, and a test-only GitHub macOS build. It does not publish the client or replace the game engine.

The package validator requires actual arm64 iOS products, exact XCTest host and test paths, valid signatures, bounded archives, and no symlinks or embedded private fixture. The build runs the package refusal tests before compiling and signing. Firebase package admission and physical Safari execution require separate actual provider results; a package build does not certify funded acceptance.

The funded test requires the original isolated fixture and completed upgrade, rollback, cleanup, and ingress admission. It uses ordinary Safari controls and a single device-start request, preserves unknown action outcomes, and requires an independent financial reconciliation afterward. Hosted builds receive no player credentials.
