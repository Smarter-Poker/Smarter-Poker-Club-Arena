# Player Command Workspace Continuity

Previously only the search term survived within its account-and-club tab session. Column choices reset on remount; filters and sorting could follow a different account or club; opening Player Record and returning reset the virtual directory to its first rows.

The roster now hydrates a versioned, validated workspace for the signed-in account and resolved club before its first live query. Search, filter, sort and optional columns remain in session storage, preserving the existing tab-only search privacy. An explicit URL view or sort overrides its corresponding saved field. Missing fields retain their saved choice, and URLs generated for a previous account do not become another account's preferences. Previously stored searches are adopted on the first upgraded visit. Unsupported, malformed, oversized or unavailable storage falls back to the existing defaults.

Opening Player Record saves only the current roster history entry, its query and two numeric scroll offsets. Returning to that same history entry restores the inner virtual directory and document position after a matching successful live read. When necessary, a finite chain of normal cursor pages supplies the required row depth. Query changes, account/club changes, user scrolling, failed reads, empty/nonadvancing pages and the saved depth bound terminate restoration. No member rows, selections, wallet amounts, permissions, notes, export operations or dialog actions are added to workspace storage. Fresh server permissions continue to control available views and columns.

Focused real-component regression reproduced four failures before the implementation. Final focused workspace checks passed 16 cases, including account/club isolation, explicit and invalid URLs, malformed/unavailable storage, legacy and private search, record Back with virtualized rows, deferred pagination and stale-answer cancellation. Connected roster checks also passed unchanged structural invalidation/debounce ownership assertions. An initial hydration shortcut incorrectly skipped the debounce when a later typed query matched the hydrated value; the first input edit now clears that shortcut at its original event. Production build and compiler passed; protected provider checks and actual live publication remain separate evidence in the owning task checkpoint. No database or engine changes are part of this phase.
