# Settled horse cash keys retain compact replay certificates

After eight full days, the existing hand-history retention transaction removes the duplicated request from certified horse-only cash settlement keys. It retains the permanent natural dedupe key and an immutable certificate containing original request/result hashes, compact response, accounting evidence digest and completion identity. Human, mixed, unknown, young, reported, incomplete and uncertified hands retain their full key payloads. Original horse classification comes from the dealt funding manifest; history must explicitly record no humans.

The replay and P&L consumers resolve the exact original response from unchanged immutable cash provenance, validating its hashes and compact response. Identical replay returns the original response; a different request remains rejected. Compacted keys refuse subsequent identity/status/result edits, deletion and truncation; a conflicting completion status also refuses before the retry path. This phase therefore depends on retained original cash provenance and does not remove that separate payload. Future provenance compaction must first replace this resolver dependency with equally qualified compact financial evidence.

The migration pins exact current stack, accounting-reader and post-classification prune definitions, preserves owner/ACL/security/search path, installs once and adds no scheduler or monetary write. The native PostgreSQL17 harness exercises real replay, financial evidence, the existing retention transaction, rollback and replay/compaction locking. Its existing accounting CI shard retains results. Production installation and backlog/physical reclamation are separate evidence owned by the root delivery.
