# Player Command Recorded Change History

The existing administrative audit consumers directly select raw journal state and provenance. They do not provide a dedicated player-scoped, sanitized, cursor-paginated contract. Existing role changes can contain commission rates and credit terms. The note producer records only presence and length; exports record club-level scope/count metadata and never identify individual exported players.

Added `ca_club_player_history` and `PlayerHistoryService.getPlayerHistory`. The reader permits club owners, current active/approved owner/co-owner/admin memberships, platform administrators and the existing guarded union overseer authorities. Child-club staff receive only clubs they actually staff within the selected union. Agents gain no new permission. Permission denial raises 42501; historical targets do not need an active membership, so suspension/removal does not erase staff history.

The endpoint returns at most 50 records plus one lookahead, ordered by created timestamp and UUID. UTC date filters and explicit action categories apply before the page limit. Member requests exclude club export records. The projection contains actor alias/reference, timestamp/action, role/status transitions, note presence/length and club export counts/scope flags. It excludes note content, operator reasons, IP/provenance, private rates, credit limits and chips. Existing journal policies and producers remain unchanged. Separate legacy trigger and RPC records remain separate records; history does not claim completeness where historical producers could fail with a warning.

The service validates the scope echo, authorized child IDs, member/type/date scope, known action/category correspondence, required metadata, stable ordering (including PostgreSQL microseconds), cursor continuation and duplicate IDs. Malformed responses are errors, not an invented empty history. One eight-second abortable attempt owns each request; timeouts are not replayed.

Verification: isolated PostgreSQL 17 demonstrates the reader is absent before installation and works after applying the exact new migration. Fixtures cover authenticated-only execution/raw-table denial, club/union/platform/current-staff authorization, revoked staff, nonstaff/anonymous/cross-club denial, inactive targets, redaction, UTC dates/categories, equal-timestamp pagination and migration replay refusal. The real Supabase fetch/deadline decoder harness has 30 passing cases including malformed envelopes, private fields, wrong scope/action/category/order, count strings, cancellation and single-attempt timeout. The initial private server startup failed because the socket path exceeded its platform limit; shortening the task-owned scratch prefix resolved it. Two initial test failures came from returning a mock from beforeEach (interpreted as cleanup), corrected with an explicit block. These were fixture defects, not passing behavior evidence.

A dedicated private `history_changed` signal is emitted after recorded audit inserts. Its payload contains only club, target and action identifiers plus the framework message reference. The same active staff predicate owns both the scoped read and private topic policy, including platform and union staff. Raw audit row subscriptions are not used for this feature. A delivery failure cannot roll back the original transaction; explicit refresh retrieves the authoritative journal. No migration has been installed in production yet. Protected integration, provider publication, final query-plan qualification and authenticated production behavior remain pending with the root owner. No financial/member/note mutations or engine changes were performed.
