# Protected certification ledger actors reach Auth retirement

The published Create Club certificate passed its five current Cashier cases,
but its reserved zero-chip account could not close: the protected membership
gate rejected five immutable ledger rows from its own retired welcome club
before the existing retained-actor branch could run.

The new guarded migration removes only the performed-by refusal. Direct
from/to wallet references, rake evidence, real identities, owners, seats,
entries, agent links and unknown/nonzero held, locked or credit balances stay
refused. The membership advisory lane precedes identity row locks, with wallet
rows before ordered member rows. Protected club triggers, grants, owner,
configuration, the downstream retirement predicate and ledger bytes stay intact.

A cleanup-only manual mode in the existing Create Club workflow accepts one
exact reserved UUID/email through environment variables and invokes the existing
supported Auth soft-retirement/readback module. It creates no fixture and scans
no other identity. Installation and this explicit cleanup are separate delivery
steps; source qualification does not claim production retirement.

The maintained PostgreSQL 17 retirement qualification reproduces the old
refusal and covers the repaired retained-actor path, immutable ledger hashes,
custody/identity negatives, row/advisory locking, rollback, replay, source drift,
ACLs and unchanged protected triggers. Focused source/module checks cover the
new manual mode without rerunning unrelated browser journeys.
