# A no-jackpot verdict preserves tournament hand settlement

The accepted-hand jackpot trigger rejected Diamond tournament hands with `kind=none` because it tested cash-only scope first. The 02:05–02:10 UTC cohort contains eighteen retained hands; seven initial jackpot refusals and eleven lease-expired refusals later encountered the same successor scope refusal. This change moves only the validated no-hit return before positive-jackpot cash eligibility. All positive payout code is unchanged.

The exact installed trigger preimage, postgres-only ACL, search path, enabled trigger and freeze are checked before replacement; the exact postimage and authority are checked afterward. No switch activation, historical mutation, payment or retained-submission recovery is performed by this migration. The separate original resume correction is required for spent successor claims; this source fix alone cannot recover those eighteen hands.

The existing isolated PostgreSQL17 jackpot runner reproduces the old tournament-none failure, installs this exact migration, proves none/replay/no extra jackpot ledger/hit, positive out-of-cash refusal, invalid verdict/version, authority, rollback, real freeze refusal and migration replay refusal. Its existing real Main/Mini cash, rake, wallet/supply and late-failure cases then pass on the corrected trigger. Native results are isolated qualification, not live recovery. Initial fixture runs exposed missing freeze/auth dependencies and one regression SQL syntax issue; corrected fixture loads the retained actual definitions and preserves the failed logs.
