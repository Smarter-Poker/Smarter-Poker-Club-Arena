# Cashier Recent Players And Stable Forms

Cashier directories now lead with the signed-in operator's recent sends and claims from the existing role-protected transaction history. Search ranking and the complete authorized roster remain intact. Account and club changes discard late history replies. Confirmed actions update their own recent counterparty ordering.

The Trade selection dock is compact on desktop, retaining mobile action targets. Amount entry groups thousands without rounding, uses the decimal keypad, retains invalid spelling for validation, and prints crisp silver text. Cashier-owned yellow text is replaced with blue or silver. Routine access preparation and server verification copy no longer fills the confirmation dialog.

Cashier pages no longer poll or reload their working forms/history on focus, visibility, reconnect, balance events or other background financial notifications. Initial navigation, explicit refresh and confirmed user commands still read authoritative results. Role and authentication revocation retain immediate authority invalidation. Cashout submission and high-value confirmation silently recheck the current club balance after an exact absent receipt; an existing receipt still wins over new-payment gates.

The browser wallet and batch journals now accept valid nonzero PostgreSQL entity UUIDs such as Club JAQK's seeded ID. They retain strict operation UUID checks, Web Locks, durable storage verification, corrupt-journal refusal and original retry keys. The prior RFC-only entity check incorrectly reported unavailable storage before sending to KingFish.

Success toasts accept a receipt-specific deduplication key. Separate confirmed Cashier sends, claims and ticket batches therefore each notify even when their text is identical; replaying the same confirmed receipt remains deduplicated. No success is displayed before authoritative confirmation.

A visible Request Cash Out button opens the existing request/status dialog from the Cashier header for player-wallet holders, including players and agents. The existing escrow, approval, cancellation and invoice path is preserved. It does not assert an external payment occurred.

Verification and publication evidence is retained in the task checkpoint. Local isolated renders measured the desktop dock at 92px versus 174px before, with no horizontal overflow at 393px and 1325px. The KingFish UUID, manual read and distinct-receipt toast regressions fail against their original sources. No production chips were moved to test the change.

The follow-up verification found a remaining classic Cashier chip-transaction subscription and automatic reads in its embedded wallet and promo panels. Cashier now opts those shared readers into manual mode, removes the page subscription and inaccurate live-connection badge, and offers explicit balance/promo refresh. Confirmed own commands still request a wallet readback. Other wallet and promo consumers retain their existing default behavior. Deferred cached reads also respect manual mode. Mounted regressions cover idle time, browser wake, balance signals, explicit refresh and command revision readback. Simple Cashier entry is covered for both player and agent roles.

Manual Cashier readers attempt their initial navigation read even when the tab starts hidden or the browser reports offline. A skipped initial read otherwise left the manual surface on its loading skeleton because wake/reconnect reads are intentionally disabled. Initial failures reach the existing Retry state; subsequent wake/reconnect events still perform no refresh. Hidden/offline initial-navigation regressions fail before this correction and pass after it; other visible-reader consumers keep their existing policy.
