## Additional confirmed defect: DA-16, P1, own Hand History refused

The published Diamond footer opened the correctly scoped archive but the server answered `not authorized for hand-history club`. Production `ca_own_hand_history_by_club` required an active/approved `club_members` row. The Arena grants automatic membership through `fn_poker_arena_context`; the old check therefore refused legitimate Arena players.

Migration `20261015213440_diamond_hand_history_admits_automatic_arena_membership.sql` replaces that one membership predicate with the existing canonical context's member result. It preserves `auth.uid()`, the own-player `ca_hand_facts` filter, projection, table filter, ordering, limits, owner, SECURITY DEFINER and fixed search path. Native PostgreSQL reproduced the pre-fix refusal and passed thirteen checks including unauthorized chip club, pending member, retired/malformed arena, stranger hands, anonymous denial and migration replay refusal.

## Fix design

`ClubHomePage` supplies no chip-club campaign when automatic Arena membership is active. `ClubLobbyCommandTop` omits the absent campaign well, so the removal leaves no empty interactive plate. Its game controls, actual Diamond jackpot/Spin adverts, player navigation, wallet, and approved artwork are unchanged. Chip clubs still render their existing campaign and announcements action. This is client-only behavior using existing APIs; it has no new engine dependency.
