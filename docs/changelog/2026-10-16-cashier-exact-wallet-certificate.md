# Cashier certificate follows exact wallet balances

The authenticated Cashier certificate now checks the actual Trade, Advanced and Agent Wallet dialog balance nodes against the owner's October 16 wallet format: grouped values with exactly two decimal places below one million, and M/B abbreviations for larger wallets. It rejects malformed grouping, missing or excess decimal places, float noise, K abbreviations and unavailable balances. The Agent Wallet dialog separately retains its documented successful empty-float state, “No Agent Float Yet”; that state is never accepted as a numeric balance elsewhere. Diamond wallet counts remain whole numbers, and statement aggregate checks retain their separate no-cents contract.

The stale compact-wallet assertion rejected approved exact balances in the focused regression before repair (11 failures, 17 passes). The corrected contract passes 45 focused cases covering chip wallets, malformed values, compact boundaries and whole Diamond counts. Accessibility, phone geometry, amount validation, previews, funding verdicts and keyboard behavior remain in the maintained hosted certificate. Hosted verification remains required; this test-only repair does not change product code or financial data.

The focused live Trade journey also exposed its funding parser rejecting an approved `0.00` balance. Strictly grouped exact two-decimal values now decide coverage from their exact amount; compact figures retain their existing interval bounds and ambiguous verdicts. The added exact-funding regression failed eight cases before repair and passes all twenty afterward. Malformed grouping, excess precision and unknown balances still cannot produce a funding verdict.
