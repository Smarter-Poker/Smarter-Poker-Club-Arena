# Natural observers share one setup deadline

The passive two-run and three-run mobile observer has one original 120-second setup budget for six pages, followed by its unchanged twenty-minute observation. A separate per-page twelve-second limit was imported into this new observer from the baseline connection certificate. In run 38965906037, the third document committed after about ten seconds, leaving too little time for its valid application session to subscribe. The natural observation never began and earned no coverage.

Allocate each observer only the remaining original shared setup time. Every page must still subscribe, receive the authoritative snapshot, render its table, load the actual felt, and clear the connection banner before that same deadline. Startup remains sequential and all six pages remain open together. No page is replaced, retried or skipped, and neither total setup nor observation time increases.

This intentionally removes the additional per-page startup latency constraint from the natural behavior observer. It does not improve or certify production cold-start latency. The independent four-case live-table baseline retains its twelve-second navigation checks and passed all four cases in the same production run. Natural behavior still requires both run counts, every river before its award, every positive engine recipient landing within two pixels, and unchanged exact client and engine identities.

Regression protection covers sequential cumulative budget consumption, a startup longer than twelve seconds within the original total, and refusal once that total is exhausted. Production proof must be repeated from the protected corrected source; the failed run is not a certificate.
