# Retained club retirement uses the current membership key

The broader Diamond audit browser run passed its page cases but refused fixture cleanup. An empty scheduled fixture tournament had been cancelled naturally and retained an immutable zero-value escrow receipt. The destructive pristine-fixture cleanup correctly refuses that history.

Qualifying the existing retained-record club retirement route in a self-aborting transaction then reproduced SQLSTATE42703: its private core orders club memberships by an `id` column absent from the current compound-key schema. The correction orders the same locked club memberships by `user_id`. Parent-first lock order, all ownership, union, balance and obligation refusals, the retained club and financial history, permissions and configuration remain intact. Installation and actual fixture retirement are separate evidence; neither is claimed by this source change.

The current full core is captured in an isolated PostgreSQL17 fixture whose membership table has the actual compound key. It reproduces the preimage error, applies the exact guarded migration, verifies permission and financial refusals, successful retained retirement, one audit/event and idempotent replay. The required certification-retirement job invokes that scene. This source correction moves no production funds and deletes no receipt.
