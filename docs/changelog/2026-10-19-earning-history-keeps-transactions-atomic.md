# Earning history keeps transactions atomic

The historical terms reader selected individual observations by wall clock, allowing a retroactive read to combine a suspended super-agent with downlines that the same transaction had not yet reassigned. The 2026-10-17 SHARK hand earning 5.00 at 00:16:58.723653 fell inside a 472-observation account-deletion transaction that continued until 00:17:03.084875. That transaction could not have committed by the earning instant.

The maintained reader excludes an external transaction when another observation in it is later than the requested instant. Identity discovery applies the same predicate. Own-transaction observations retain normal read-your-writes behavior. An index on transaction/time keeps that exact check bounded. Existing recorded contracts, history rows, rates, hierarchy validation and private ACLs remain intact. This does not invent historical commit timestamps; commit tracking is unavailable. The rule removes provably unfinished transaction observations, while preserving the existing observation-time model elsewhere. Union membership discovery in the separate earning-contract function requires a corresponding change against its other active owner's final postimage; this migration owns only these two historical readers.

Native PostgreSQL 17 runs the captured installed historical earning contract against the actual reader components: the old reader refuses the intermediate hierarchy; the correction derives 0.02 direct, 0.03 upline and 0.01 residual from the 0.06 player share. Completed suspension, newly introduced identities, same-transaction visibility, missing/invalid requests, private ACLs and migration replay refusal are covered. The existing required accounting shard invokes the fixture unconditionally. No production accrual or payout has been executed by this qualification.
