# Bounded recovery diagnostics and wire observations

The actual two-pool recovery run 39484901328 stopped in `touch` before recording
any selection; its browser and local sessions closed. Its generic error did
not retain which entry/first-render step failed. This tooling change records
that exact step plus fixed route/layer/profile-gate classes and transport counts.
It does not change the route, retry a player action or claim that the underlying
unobserved recovery has been repaired.

The same finite browser operation also counts its own private card deliveries,
foreign private deliveries and opponent card exposure in actual live betting
snapshots. Card faces, raw frames, page text, URLs and credentials are never
retained. Showdown and clockless all-in runout are excluded from the hidden-card
sample. Snapshot samples do not certify every delta/event or universal security.
Missing samples remain zero observations, never passing coverage. Room-specific
live snapshot/delta clock observations retain only the hand UUID and deadline;
they are evidence samples, not a latency qualification or a fabricated clock.

Only the existing recovery witness consumes this observer. No product state,
socket, timer, polling, funding, consent, join or wager is added. The existing
240-second operation and cleanup reserve remain. All report additions are
bounded to the existing three browser contexts and two authorized rooms. A
partial operation remains UNKNOWN regardless of its samples.

The existing recovery test entry imports the new pure observer tests, so the
maintained workflow enforces ownership refusal, missing evidence, sequence gaps,
legal public reveals and secret-free diagnostics. Source tests and actual runtime
observations remain separate. A protected, explicitly invoked changed-input run
is required to diagnose the earlier failure and verify recovery.
