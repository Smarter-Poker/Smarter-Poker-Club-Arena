# Lightning Entry Uses The Approved Console

Replace the generic Lightning entry card and detached table-list panel with one approved Spade Console. Preserve every entry decision, join ownership guard, buy-in handoff, closed/disabled game refusal, device limit, retry, return and remembered-game action. Error and delayed-loading states use the same chassis. Session read failures display an unavailable message rather than a false zero-table count.

Whole-number stakes use the existing table notation: 1/2 and 5/10. Fractional stakes retain their precision, such as 0.25/0.50. Normalize game titles and remembered labels at presentation; do not alter stored game configuration or amounts. A name already containing its stakes does not print them twice.

Validation includes the existing real-route Lightning entry, multi-session and operator-closure tests; a registered law renders the real chassis and verifies all doors and stakes; Chromium renders all five entry/joining/closed/limit/error states at 375px, 393px and desktop width with no horizontal overflow or page errors. Required hooks, protected checks, publication and live proof remain separate release requirements.
