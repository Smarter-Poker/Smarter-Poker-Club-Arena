# Horse Phase 14 implementation and activation design

The owner assigned the missing Phase 14 implementation, current-source pack
qualification, protected delivery and natural proof for the canonical 1,000-horse
cohort. The operation checkpoint remains in the existing task evidence archive;
this document describes the maintained implementation, not a live certificate.

## Source and qualification

The original eighteen da650261 strength operations were retired after Lightning
PR #8045 merged as fbf2a931: its decision source changes all seventeen variant
policy digests. Completed old-source artifacts are retained, never relabelled.
The final integrated policy source must be fixed before its replacement matrices
are measured. Other approved client, engine and database deliveries continue.

## Components and order

1. Build a bounded offline reference producer. Begin with river heads-up cash
   call/fold against an already all-in opponent, enumerating an explicitly
   declared weighted range. Bind the original snapshot, private read frame,
   declared fold/call menu, committed source and prices. Reuse actual pot rights,
   odd-chip allocation and deductions. A result is conditional on its declared
   model and is unsigned/unqualified; it is neither calibrated GTO nor admission.
   Unsupported boards, future decisions, unknown utility and malformed inputs
   remain explicit refusals. Extend supported domains through their own measured
   contracts rather than inventing results for them.
2. Build independent holdout evaluation. Keep selection and validation hands,
   samples and windows disjoint. Require complete probability distributions,
   original-state/reference binding, source identity, qualified producer and
   uncertainty. Measure the actual bounded distribution change after costs,
   preserve every failure and unknown, and emit a versioned qualification whose
   hashes bind the catalog, holdout, policy and trust provenance.
3. Build the separate reference-review/signing service. The producer must never
   have its signing key or qualify itself with a JSON flag. The reviewer must
   validate original source custody and independently recompute the declared
   finite-menu results before signing. The production key belongs in the
   canonical service secret store, outside engine/source/fixtures; consumers
   receive only its pinned public identity. Test keys cannot enter committed
   qualification evidence. Provisioning a signer is not qualification of facts.
   No secret is printed, scraped from an environment file or requested in chat.
4. Implement immutable runtime catalog admission and the corrective owner. The
   live path reads only preloaded, protected, qualified policy data. Keep domain,
   source, legal menu, generation, expiry, original-information-set and maximum
   five-percentage-point movement checks. Do not generalize a retained hand's
   correction to a different information set without an explicitly versioned,
   measured policy representation. Missing matches retain the baseline.
5. Wire worker FAST/DEEP, policy graph, replay provenance, Classic/Lightning
   acceptance and effect commit. A correction must not commit the displaced
   action's plan effects. Recheck authority after queueing, at accepted action
   and at effect application; stale, withdrawn or mismatched authority cannot
   survive in a worker cache. Bind the final execution witness to what the
   controller actually accepted, not merely what the worker proposed.
6. Run meaningful local regressions and exact-head protected CI. Select only
   genuinely qualified packs through their existing authority generations.
   Publish through the existing engine receiver and approved cutover owner.
   Verify sealed containing release, exact served source, natural accepted use,
   effects and replay separately. The supplied canonical cohort and eligibility
   attestations must be verified; review-row counts are not all-phase coverage.

## Invariants

No action-clock network or signing work, no financial probe against active
players, no fixture promotion, no forced universal phase firing, no changing a
losing or incomplete qualification into a pass, and no release watcher or retry
service. Independent producer/reviewer roles and actual automated gates remain
required. All 15 phases and all 1,000 horses stay uncertified until their exact
finite acceptance evidence exists.

## Implemented offline foundation

The river producer, bounded proposal kernel, finite-window holdout measurement
and explicit private CLI are implemented. Focused qualification passed 287 cases
across the existing corrective reviewer, inactive catalog, authority guards and
new modules; server compilation passed. A 1,000-case synthetic regression exposed
the single-journal-record hash ceiling when applied to an entire population.
The measurement now streams ordered, bounded per-hand commitments into its
versioned digest. This regression proves population handling, not live fleet
coverage. Known terminal calls are covered under all nine card-rule variants,
including quartered hi-lo payouts.

These modules neither sign nor promote evidence. The independent signer,
qualified real-source holdout, protected runtime representation, FAST/DEEP and
acceptance/effect wiring remain separate unfinished parts of this assignment.
The coordinating winner-belief read-frame repair must be integrated before
replacement Phase 8 and Phase 10-13 measurements; no replacement matrix has
been dispatched against superseded source.

## Original-state model and independent numerical review

The calculator now derives the hypothetical call's fee quote from original
settings without requiring future accepted-hand or execution records. The
retrospective wrapper still requires their exact binding. A versioned finite
32-combination original-state prior and a shared bounded proposal rule are
implemented; model holdout reconstructs that policy rather than accepting
post-hoc supplied range rows. Its calibration remains explicitly unqualified.

The independent numerical reviewer uses the existing separately implemented
benchmark scorer and contribution layers, and exact integer-rational rounding
for residual cents. It detects a deliberately wrong producer even when the
producer reproduces the same wrong result. The private CLI now exposes model,
model-holdout and independent verify operations alongside produce and holdout.

A real in-memory HandController hand reaches the river, exposes its actual
fold/call/all-in menu, accepts the call and conserves both starting stacks.
This caught the overly narrow two-entry menu guard: the correction prices only
fold/call and leaves the other baseline action families unchanged. Short-stack
calls retain the full controller price while paying only the remaining stack,
and the opponent's uncalled excess is refunded. An actual second board is
refused even if boardCount incorrectly claims one. This is connected local
controller proof, not production worker/acceptance/effect or fleet proof.
