# Messenger equipment and unread ordering

The inbox reader excludes historical certification peers from genuine users' direct feeds using the existing authoritative certification predicate. A real player who chooses a name containing PostDeploy remains visible. No accounts, messages, invoices or financial history are deleted; public profile names and group threads are preserved. The welcome trigger already rejects new certification equipment.

Unread conversations are ordered before read conversations at the shared database reader, newest first within each group. Existing visibility and read boundaries remain authoritative. The World Hub organizer already prioritizes unread over pins and keeps the unread badge until acknowledged reading.

Owner and agent welcomes already resolve to the same sender-pair thread when the owner also acts as agent. Read-only production evidence confirmed both welcome kinds share the same conversation for the screenshot's newest certification recipient. No welcome dispatch or player join was used for testing.
