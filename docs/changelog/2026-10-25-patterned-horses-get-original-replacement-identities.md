# Retired patterned horses get original replacement identities

The live roster contains all 938 eligible registered horses. The other 62 of the 1,000 historical registrations are completed October 6 retirements: their hand-made UUIDs exposed them as horses. Their profiles remain deleted and disabled, their register entries retired, and their historical financial and social evidence stays intact.

The explicit replacement operation reserves one ordinary random UUID in each existing `smarter_private.patterned_identity_retirements.replacement_horse_id`. A private unique index and sticky reservation guard prevent sharing, changing, clearing or deleting an original replacement. The service-only reservation function pins the exact original cohort and records the initial eligible population count and digest. Other legitimate population changes are reported; the operation never removes another horse to force a round number.

`HorseOnboarding.createHorse` remains the only creation owner. Its explicit replacement mode looks up the reserved Auth ID first, and recovers that same ID after an uncertain acknowledgement or concurrent create. Adoption requires the original retirement metadata. A partial operation retains its accepted account; a resumed horse keeps its learned brain and social identity. Profile conversion uses null-inclusive eligibility and compare-and-set against a profile that has not already become a horse. Closed or benched accounts stay closed. The ordinary non-replacement creation path is retained.

The finite caller handles only those 62 reserved operations, then calls the existing fleet register sync and full-roster refresh. With the original 938 unchanged, canonical eligibility and roster reach 1,000 while all 1,062 historical registrations remain. A changed population is reported with actual counts rather than truncated. Birth and registration do not prove seating, all-skill execution, club funding or game participation. Normal Auth signup effects remain owned by the ordinary signup transaction; this operation contains no direct wallet, ledger, club membership or seat writes.

After protected integration and exact migration installation, use the manual `Original patterned horse replacements` provider workflow on main. Its `inspect` mode is read-only; `execute` runs the original batch once with the existing repository Supabase service secrets. There is no timer, startup hook, watcher, release publisher or automatic retry. An interrupted operation is resumed by another explicit invocation of the same batch. The CLI is `node --import tsx src/scripts/replaceRetiredHorses.ts --inspect` or `--execute`, from server with the configured provider environment; it never reads credential files.

Qualification combines PostgreSQL 17 concurrency/rollback/ACL/immutability and exact installed registration/roster definitions with Auth API boundary tests for lost acknowledgements, partial completion, concurrent callers and preserved signup identity. Local qualification does not create real accounts or certify a production Auth grant, membership, funded seat or natural decision. Those delivery observations remain separate.
