# Seated tournament tables reach their existing dealer-admission path

The early capacity admission introduced in PR #8093 reads `tournament_capacity_table_receipts` directly. Its original September 8 migration enabled RLS and revoked every privilege, including service-role reads. No grant accompanied the new reader. The read therefore returned 42501 before admitting the committed table; the later expansion path could eventually start it through its RPC handoff.

Live Nightly 10K table `196af8ef-e53a-49c2-9fa6-29371423bcd6` was committed at 00:20:23 UTC October 27, with seated players and no dealer/hand until 00:45:26. Client heartbeat 404s independently confirm the missing engine. Live catalog checks found no service-role read privilege on any required column; PostgreSQL logs from 00:25–00:40 recorded 651 permission failures on the exact capacity receipt SELECT. Both Nightly events eventually resumed without a process replacement. That later play did not repair the permissions.

The additive migration grants service_role SELECT on exactly table_id, tournament_id, created_at and manager_admitted_at. It preserves RLS, browser denial, private unused columns, raw-write denial and the original acknowledgement RPC. It changes no players, stacks, prize pool, ledger or engine binary and requires no engine restart. No watcher or repair loop is introduced.

The native PostgreSQL fixture executes the actual engine SELECT/filter/order and original acknowledgement function. Before the correction it reproduces permission denied; afterward it proves the table reaches the consumer, browser/unneeded-column/raw-write denial, repeat installation and duplicate acknowledgement. The existing required accounting shard runs it directly. Installation and live readback remain separately recorded in the task checkpoint.
