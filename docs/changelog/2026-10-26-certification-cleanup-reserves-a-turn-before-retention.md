# Certification cleanup reserves a turn before history retention

Browser run 40345982952 passed its browser suites, then exhausted five cleanup attempts with `CERTIFICATION_FIXTURE_GATE_BUSY`. Each attempt tried the platform gate exclusively for 30 seconds. The existing 30-second history-retention schedule held that gate shared for 23–34 seconds per transaction; ordinary purchases used it too. The nonqueueing fixture had no way to reserve a turn, so consecutive retention batches could keep barging ahead of it.

The four existing fixture preparation functions now reserve a transaction-scoped turn on a separate advisory key `(530090,2)` before trying the original platform gate. Only history retention uses the shared counterpart of this new key. An admitted retention batch completes; its successor returns without work while a fixture is waiting or active. The reservation wait has a 32-second lock timeout, allowing the existing 30-second cron statement budget plus headroom. Players never use this key. Maintenance still owns its original gate, and fixtures still only try that gate for the original bounded 600 attempts at 50 milliseconds. Cancellation or rollback releases both transaction locks.

The migration pins all five current function preimages and postimages, proves reverse substitution reproduces every original byte, and preserves their ACLs. Reserved-account identity, protected-club exclusions, activity/history refusals, lease/custody checks, atomic retirement and financial records are unchanged. No cron is added, disabled or rescheduled; no cleanup retry limit is raised. This is a database function change, with no engine or client bundle dependency.

The required accounting CI runs the exact migration against complete production catalog preimages in a disposable PostgreSQL cluster. Concurrent sessions verify retention yields, purchases proceed while cleanup waits, maintenance remains authoritative, all four fixture gate blocks execute, transaction locks release on cancellation, the real 32-second reservation timeout fails closed, and source drift rolls back the whole migration.

The schema fragment declares the new private helper for protected-main-first delivery and makes no installation claim. The six current workflow input fingerprints are refreshed for the added native check only; historical qualification records, financial assertions and execution statuses are preserved.
