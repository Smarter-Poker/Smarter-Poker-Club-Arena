# Horses share accepted public opponent notes

The owner explicitly requested pooling the herd's notes across tables on October 26. The accepted-hand path already reads saved public opponent profiles and broadcasts the completion to every decision shard. Individual observer memory discarded those profiles, leaving a horse without the herd's read when it met that player at another table.

Each worker now keeps a bounded cache of those accepted public profiles. A decision can consume the matching variant, cash/tournament mode and dealt-size bucket for its dealt opponents. The imported counters feed the existing `HorseMind.opponentRead` credibility and decay rules; thresholds, wagers, RNG, financial rules and policy activation gates are unchanged. No new query or background task runs on the turn. The existing producer remains the database reader.

The cache admits only committed hands with bound original observer routing, at most ten validated profiles, matching context and accepted action actors. Newer profile versions replace older ones; repeated hands and older versions cannot add counts. If a newer accepted hand lacks a fresh profile, its actors' stale cached counters are withdrawn so they cannot suppress newer individual learning. Out-of-order older profiles preserve an already newer version. Unknown fields are projected away. Cards, private plans, accepted-actor authority and another horse's individual state never enter the cache. Public counters use a detached exploit map inside each decision, preserving its original issued view and individual plan ownership.

Availability is the original worker receipt time. A queued decision cannot read information received after its cutoff; a regressed clock cannot relabel a new receipt as old. Up to 20,000 profiles and completed-hand dedupe identities are retained, with oldest-first eviction. A restart starts an empty cache, and missing, shed or invalid receipts retain the individual read. This is bounded public aggregate sharing, not a claim of complete historical coverage or winning strength. Saved profiles currently distinguish cash from tournaments, rather than individual tournament formats; they do not cross variants or heads-up/multiway size buckets. Unsupported durable variants retain existing individual evidence.

A version-three journal receipt labels `pooled_public` separately from independent observations and retains the individual-history provenance, pool digest, profile count and original availability. Review reports pooled and independent accepted-action counts separately. Neither kind of provenance grants activation authority. Existing independent provenance assertions remain intact.

Focused verification covers actual worker-to-HorseLogic consumption, a thousand independent horse views consuming the same public digest without sharing private plans, historical cutoff and clock regression, duplicate and older receipts, malformed data, unknown/private-field projection, context isolation, capacity eviction, clear/restart behavior and journal refusal of future evidence. Existing individual history and accepted-hand learning tests remain applicable. Protected checks, engine installation and natural pooled receipts are required before describing this runtime change as live.
