# Explicit synthetic Omaha adversary stress

The full horse-strength assignment needs repeatable tests against opponents that deliberately expose overfolding, overcalling, excessive pressure and overly passive value lines. `server` now provides `npm run horse:omaha-stress -- --variant=plo6 --opponent=raiser --seed=10001 --hands=120 --seats=6 --stack=100`. Four synthetic profiles cover caller, folder, raiser and passive_value. PLO4/5/6, two or six seats and 25/100/200 BB stacks are explicit inputs. No standing schedule or production writer is added. The shared offline driver now passes its explicitly identified human seats into `humanUserIds`, so the real Omaha reference brain exercises the production aggressive-player presumption; horse-only profiles are unchanged.

The command uses the existing physical hand controller, published rake/BBJ pricing, independent settlement and deduction checks, exact legal-action execution, reference policy and isolated per-hand learning sandbox (`fresh_each_hand`, not a long-session learning measurement). It refuses incomplete hands, conservation/card/settlement/deduction errors and qualification holdout seeds before running. Work is bounded to 1,000 complete hands per invocation. The offline launcher pins fake database configuration before importing the simulator, runs full equity samples and records source/lockfile SHA256. An optional output path uses exclusive creation to preserve earlier evidence.

These profiles are deliberately artificial. They have zero observed-human counts and do not alter the committed human population. Every result says `synthetic_development_stress`, `reference_only`, `isHumanPerformanceEvidence=false` and `qualifiesForPromotion=false`. Sample standard error and an explicitly named normal approximation remain descriptive; this command cannot qualify a pack or prove a sustainable win rate. A one-hand sample has no interval. Existing protected qualification and withdrawal rules remain unchanged. Under the October 9 owner amendment, inadequate human calibration is a post-launch measurement limitation, never a launch gate.

Regression coverage includes real whole-hand execution for each PLO variant against every adversary, fixed input/sample validation, holdout refusal, isolated profile state, absence of fabricated observation counts and the actual offline CLI with source binding. This is a diagnostic and evaluation addition to the broader assignment; it is not a claim that every strategy enhancement is complete.
