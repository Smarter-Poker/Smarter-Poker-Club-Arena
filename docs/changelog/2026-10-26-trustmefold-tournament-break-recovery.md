# Tournament break presentation survives a lost end event

Trustmefold's only entered tournament active at 12:49 America/Chicago on October 26 was Lunch Rush (NLH Deep), `5eeaeeb2-575c-4993-97a4-7bafa8f52302`, Table 7 `307c15d7-5723-4319-a86a-b8ea7e9c1ada`. The hand store proves continuous server play: hand 49059067 ended at 17:49:10.915 UTC; hand 49059979 started at 17:49:21.016 UTC; Trustmefold submitted a player-origin fold at 17:49:58.448 UTC. This does not establish a server freeze at the screenshot time. The supplied screenshot was a 1-by-1 pixel file, so its visual state is unavailable.

The Android Chrome client was running `da658520da87af31f62a6c94b220e4636f61d16c`. From 17:53 UTC its diagnostics record failed reads, transport loss and repeated `MasterBus.Critical_channel_no_factory` errors for this tournament. That version still unconditionally unsubscribed the shared tournament channel in `useTableTournament` cleanup. PR #8218 (`59b9c3b899`) already removes that ownership defect and is included in the current public client `7fdb2223b24acf54ce11440531347890fcd61897`. This follow-up preserves that repair.

The connected remaining defect was in `TablePage`'s break event handler and `useTableTournament`'s state: only a live `break_ended` broadcast cleared the overlay, and reconnection refreshed add-ons but never the break itself. A lost end event could leave the full-screen break active over resumed play. The exact 12:49 visual symptom remains unproven; the later network/channel failures are established evidence for the affected recovery path.

`useTableTournament` now reads the persisted break at tournament mount and engine reconnection. The existing tournament-channel SUBSCRIBED callback also refreshes it. An explicit `on_break=false` closes the overlay; a true value restores its actual last-hand phase or absolute countdown. Expiry alone never resumes play. Failed/absent/malformed reads preserve known state. New live events and newer reads invalidate older answers, and table switches/unmount retire their outstanding callbacks. Retained event handlers stop after their owning table effect unmounts. No repair timer, game-state write, financial change or engine replacement is introduced.

Real-time law: normal break presentation remains triggered by `tournament_break`, `tournament_break_started` and `break_ended` discrete events; persisted reads restore missed state only at connection lifecycle edges, with no snapshot diff or new polling.

Validation: the new hook regression failed before implementation (no durable read or recovery API). After implementation the targeted hook/SDK/HUD/result suites and TypeScript are recorded in the task checkpoint. Tests cover missed start/end, last-hand phase, expired-but-still-active break, unknown reads, newer live events, superseded responses, initial tournament discovery, A-to-B-to-A switches and teardown. Publication and live proof are tracked separately in the checkpoint.
