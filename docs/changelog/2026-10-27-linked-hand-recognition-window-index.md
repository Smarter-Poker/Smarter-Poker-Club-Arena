# Linked hand books use the original recognition window

The original weekly hand reducer timed out after 240 seconds in its linked
outcome reader. Its actual plan scanned the complete immutable resolution
relation and verified full proof hashes before restricting the original
outcomes to the two-hour recognition window. The existing time index requires
the outcome's own Union. That Union cannot replace the original resolution's
Union without losing valid linked hands.

The migration adds one nonpartial `recognized_at` btree on the original outcome
table, through the maintained concurrent installer. It changes no function,
source65 pin, recognition predicate, proof hash, accounting math, cache,
admission or payer. The guarded body verifies the exact index catalog and four
original owner definitions and permissions.

The isolated PostgreSQL qualification uses the captured full relation columns
and constraints, exact linked/reducer/witness/read bodies, original hand-reader
and append guards, original boundary and Union semantics, natural planner
selection, full row parity, installer rollback/replay and malformed-catalog
refusal. Unrelated source65 collaborators are controlled only while executing
native hand fixtures; the complete actual source65 definition is then loaded
and checked unchanged across installer replay. Production installation, exact
readback, original window timing and all 84 hand parts remain separate proof.

Local qualification passed 17 native cases, 1,183 law/registry assertions and
TypeScript. The native baseline could use its existing composite time index;
its speed is not reproduction of the production timeout. The real production
plan and timeout establish that defect. The final native plan naturally selects
the new scalar time index and preserves exact original results.
