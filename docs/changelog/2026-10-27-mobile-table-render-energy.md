# Mobile live-table rendering energy

Follow-up reports isolate persistent heating and battery drain to iPhone Safari during live poker. The earlier worker/audio and JavaScript timer repairs remain in place. This change removes three additional continuous rendering costs in the maintained table components:

- The action ring now clips stationary rounded neon ink with native equal-and-opposite transforms. It no longer animates inherited registered properties, recalculates CSS trigonometry or repaints a conic gradient each frame. Its engine-stamped duration, linear clockwise border depletion, time-bank extension, final-five-second pulse and blue color remain. Resize and page/table restoration reacquire the current clock without frame polling.
- The pot's existing eight-second shine translates the same strip through the same positions instead of animating `left`.
- The existing on-turn VIP scan translates a cached strip under a stationary character alpha mask instead of animating the masked background position. Its three-second eligibility delay, seven-second period, speed scaling and state gating remain.

Observed style time changed from 0.474051s to 0.12536s, layout from 0.099609s to zero, and task time from 1.42732s to 0.929712s. These are controlled Chromium component measurements, not full-network gameplay or physical iPhone energy measurements.

Regression coverage exercises the real clock component in WebKit, timing fractions through expiry, unchanged ink position, time-bank extension and resizing; units cover restoration and existing deadline anchors. The existing required CSS Beat browser workflow runs the added component cases. No engine, database, financial, sound or table-layout behavior changes. Physical iPhone temperature and battery improvement remain unmeasured and require field confirmation after publication.
