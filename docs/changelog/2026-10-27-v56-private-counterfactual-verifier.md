# V56 private counterfactual verification

A bounded library can compare an original accepted FAST cash PLO4/PLO5/PLO6 river decision with the private V56-off arm. It first requires the maintained hand reconciler, accepted-action binding, exact-source/runtime replay, solver identity, and matching optional-owner admissions. It changes only the internal compute option in the off arm. Original records and request digests remain unchanged. The off response must pass the maintained receipt/compute/RNG/effects validators, match the original worker envelope, and remain unchanged by the original authoritative action/amount owner plus pot-limit legality validation. Invalid proposals are refused rather than coerced. Results contain hashes, booleans and closed reasons; equal actions are `executed_no_difference`, never causal repair proof.

The original exact-replay API is unchanged by default. An explicit private witness reports only V56's local named counter, distinguishing unavailable capture from captured zero. Parked telemetry is restored even when startup throws. Limits are six explicit cases, 256 records and 8 MiB per case, and 32 MiB per batch. DEEP is unsupported; a requested DEEP feature witness is unavailable because its runtime counter combines FAST and DEEP.

This is verification tooling, not a live poker-strategy change or a production certificate. The private caller must authenticate the journal and bind the executing source identity. Old-source records cannot be replayed as exact on a new source. Replay framework changes alter the Phase 14 kernel composition, requiring a fresh applicable composition/qualification. They do not alter the 17 P8/P10–13 policy closures. Deployment and natural affected-hand evidence remain separate requirements.

Focused real-worker, reconciliation, binding, pin-refusal and restoration controls accompany the change. Synthetic controls are not production captures. No production dispatch, database mutation, activation or solver access is part of this library.
