# Acknowledged Horse public history releases its decoded graph

Every decision-worker client owns a separate main-process public-history cache. With eight clients, the existing 2,048-entry limit applies eight times. An acknowledged packet was no longer sent, but its full decoded hand/action graph remained retained. The original packet still has to survive: a later null or wrong acknowledgement can mean the worker evicted its observer context and needs exactly that original window again.

After an exact acknowledgement, the cache now retains the packet's private JSON representation, digest and original availability cutoff, and releases the decoded graph. A null or wrong acknowledgement restores a fresh transport object from those same bytes without another read. Repeated acknowledgements remain idempotent, history remains available, and acknowledgements remain private to each client. No unacknowledged history, privacy, qualification, seating or strategy behavior changes.

The focused regression failed before the repair and passes afterward, preserving original-cutoff refusal, exact recovery, wrong/null acknowledgements, repeated acknowledgements, transport mutation isolation and one original load. The cache, observer and worker-client suites passed 192 tests. In a finite offline comparison using 193,916-byte synthetic public packets, 512 acknowledged entries retained about 159.35 MB before and 106.53 MB after: approximately 35% less retained heap. Eight independent 128-entry banks retained about 310.92 MB before and 206.03 MB after. One-time acknowledgement serialization measured about 0.26 ms at p95 in that replica; this is not a live UI latency certificate.

This is a measured retention optimization, not proof that these caches caused the historical V8 exhaustion or that HB134 is fixed. The aggregate production packet occupancy and exhausting isolate remain unknown. No heap limit increase, shared acknowledgement, new maintenance exception or production mutation is included. Protected merge, approved engine publication and affected live verification remain required.
