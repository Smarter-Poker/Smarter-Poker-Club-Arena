# Direct Transfers Between Personal Wallets

Agents can open Transfer Between My Wallets directly from the cashier. The existing Send Out form selects their own account, clears roster filters that would hide it, starts on Agent Wallet to Player Wallet, and offers the reverse direction through Send From. It uses the existing durable batch intent, public RPC and ledger transaction; no balance adjustment or new money writer is introduced.

Self recipients no longer offer their selected source as the destination. A source change cannot retain that invalid destination. An agent's own promo float is excluded when their own account is selected; downline claim authority is unchanged. Retained uncertain transfer destinations keep their original identity.

The exact screenshot refusal could not be reproduced in the installed RPCs: both directions succeeded in a single explicitly aborted production transaction, and independent readback found neither test receipt. Mikey's original 100-chip delivery had already been reclaimed by the owner and resent into his player wallet before this task. This change repairs the demonstrated discovery and invalid-choice gaps; it does not claim a newly found server denial.

Regression protection mounts the real trade page for all three agent tiers and both sending directions, including a search that hides the caller. Existing native PostgreSQL qualification checks reverse personal movement, exact replay/concurrent retries, conservation, journal rollback, insufficient funds, downline claims and promo restrictions. The maintained native forward-send gate now checks every agent tier, cent precision and unchanged total balance. Delivery and live evidence remain in CHECKPOINT-own-wallet-01a1837e.md.
