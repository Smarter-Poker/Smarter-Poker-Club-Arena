# Weekly payout ownership reaches every release certificate

The existing F06-only admission could admit an engine cutover while a weekly payout owned the gameplay pause: it interpreted `readyForRestart=false` as only the listed preparation blocker. The host transaction now reads durable weekly ownership before acquiring fresh health for normal, F06 and legacy-checkpoint admission. A non-null owner refuses all three paths. Null process health also needs that durable proof; it cannot hide an owner committed since the last engine refresh. Reading health after the bounded RPC preserves the original remaining-time reserve. Existing countdown, durability, physical-hand and cutover-reserve checks remain required.

An older engine does not publish `weeklyPayout`. The existing pinned database adapter now supplies read-only ownership authority for both older engines and engines publishing a null owner. It calls `fn_weekly_accounting_payout_pause_state(NULL,NULL)`, whose original database query excludes expired and released owners. Only an explicit null boundary in the maintained response allows admission. Missing RPC, failed reads, malformed responses and non-null owners refuse. The response body and private ownership token are never printed. This mode does not acknowledge, advance, retry or pay a weekly round.

Compatibility prerequisite: install the qualified `20261028162126_weekly_payout_runs_under_its_owned_game_pause.sql` through protected main before activating controls that need the old-health fallback. An unavailable RPC is UNKNOWN, never evidence of inactivity. This change adds no installer, publisher, scheduler, engine restart or financial exception.

The maintained root law executes the actual shell functions and Python adapter with synthetic HTTP inputs. It covers normal/F06/legacy, announced/draining, ready, paying, old health, stale null health, explicit inactivity, malformed data, read failure and RPC-before-fresh-health ordering. A synthetic budget-consumption case proves all three paths refuse a fresh remaining budget below the unchanged reserve, without sleeping or adding a clock override.
