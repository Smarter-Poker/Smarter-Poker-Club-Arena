# Bound first-day fixed SNG horse legacy import

The installed planner's first-day budget import joined all tournament players before filtering each board's earliest paid horse to the Chicago day. Production EXPLAIN showed a sequential scan of 2.82 million roster rows; eligible registering satellite boards existed, but no day plans had persisted. The original caller exception was not recovered, so this is evidence of a pathological query plan rather than proof of a specific historical RPC error.

The new migration replaces only that import query in the private planner. It materializes structurally fixed 6/9-handed satellite boards first, retains the full canonical fixed-board predicate, and finds each board's earliest horse registration through the existing tournament roster index. The Chicago day filter remains after MIN, preserving prior-day first entries, null timestamp fallback, all roster statuses and completed-board history. Prior paid boards still consume the daily budget; no budget, wait, financial writer, trigger or engine behavior changes.

The read-only candidate SELECT completed in 2.117 seconds under a transaction-local 8-second timeout and found 50 pre-policy paid boards for the current Chicago day. The exact old SELECT was explained without execution. No production planner, registration, claim or DDL probe was called. The migration pins the installed source preimage and exact replacement postimage and preserves permissions; it can use the ordinary protected-main applier without a new roster-trigger lock.

The existing required satellite accounting qualification installs this new migration, checks ownership/ACL/config preservation and replay refusal, then exercises the actual paid guard and union race. Additional isolated history fixtures cover earliest-before-today, null registration date, completed/eliminated history, human-only exclusion, day-plan persistence and exact old/new SELECT parity. Existing financial assertions are retained.
