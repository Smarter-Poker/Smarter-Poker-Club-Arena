# Account preference completeness

Every active filter and presentation preference belongs to its account and context. Selections automatically save without TTL; mount/default hydration never overwrites a selection. Logout flushes the original deferred requests before revoking its session, with a bounded wait and retained intent if the network is unavailable. Browser/device permission grants and transaction drafts retain their existing authority.

The existing profile settings, table settings, cosmetics, lobby filter/view owners and Stats workspace remain authoritative. Roster workspace now uses the same account preference table while retaining explicit URL overrides. Stats workspace writes only selected columns under existing authenticated RLS. No new schema or engine contract is required.

Prior live proof from PR #8355 and migration 20261027173138 remains valid for volume/reload/reconnect, cosmetics cold reload/cross-device/isolation, and live-table reconnect. New maintained lifecycle cases cover visible settings, category filters, advanced seats/heading order, table switches, roster workspace and Stats layout/privacy across UI logout and auth-only empty-cache device contexts. Execution and publication results are recorded separately in the task evidence.
