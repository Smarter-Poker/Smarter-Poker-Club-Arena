# Shared history retention admission budget

The main process owns eight independent own-public-history caches. Their former 2048-entry bounds could retain roughly 4 GiB of encoded windows in aggregate before object overhead. ACK serialization reduced decoded retention but did not impose an aggregate capacity bound.

The existing one-bank envelope (2048 times the maintained 256 KiB window bound, 512 MiB) now bounds encoded packet retention and pending reservations across all clients. Each pending load reserves a maximum packet including its digest and availability metadata before loading. Completion charges the exact encoded packet bytes; failure/eviction releases the reservation. Aggregate pressure evicts by existing FIFO order across clients; a late completion cannot resurrect an evicted original. Per-client entry bounds remain.

Admission also reads the current main isolate's actual V8 available heap and heap limit. A twofold representation allowance rounds upward from the retained replica's measured ~1.68x decoded packet expansion; reserve covers the existing sixteen concurrent loads plus two synchronous transport/ACK representations. This allowance is an estimate, not exact decoded heap accounting, a guaranteed upper bound for every object layout, or a whole-process OOM guarantee. No worker heap limit, heap increase, forced GC, timer, disk cache or new monitor is used. Missing/headroom-exhausted samples refuse new loads with the existing failure cooldown. The existing status boundary exposes only aggregate numeric reservation usage and its bound.

ACK state and payloads stay private to each client. Exact ACK releases the decoded graph; null/wrong ACK replays the same retained original packet without reloading or advancing its cutoff. Only legitimate count/aggregate FIFO eviction can remove that original. No cards, opponent-private information or shared ACK authority was added.

Two real-component capacity regressions fail against the unchanged cache. Focused cache/client/lane/budget behavior covers eight banks, pending duplicate reads, late completion, FIFO release, invalid/unavailable loads and cooldown, wrong/null ACK, per-client ACK isolation and actual main-isolate sampling. Historical HB134 allocation cause and production OOM closure remain unknown; this repairs the demonstrated aggregate retention risk. Delivery and live verification remain with the root agent.

Terminal client termination explicitly disposes its own cache and releases all coordinator callbacks/claims. FIFO work drains before normal STOPPED; startup cancellation and terminal failure also release. Late pending completion cannot resurrect a disposed entry. Same-client null-ACK recovery never disposes the cache. Window validation and reservation now share the single maintained window-size constant.

The fleet reader now credits only the exact zero/null/accepted-record agreement for an intended, originally bound action. Contradictory amounts remain unknown; no action, price, journal body, old ledger or profitability claim changes. Both actual writer-to-reader regressions fail before the fix.
