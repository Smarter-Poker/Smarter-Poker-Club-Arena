# Original accepted all-in execution inspection

The private natural turn census preserves coerced execution and missing captures,
but its closed output cannot explain original selected versus accepted wager
geometry. Extend the existing protected read-only inspector with v6
`accepted_all_in_execution`, using the current image's existing canonical journal
SDK. No engine replacement, strategy, roster or financial mutation is required.

Selectors retain the exact original source, hand, lease, actor, seat and full-list
ordinal, optional decision hash, six-case limit and 8192-byte input bound. Original
hashes, actor/street anchors, producer-local ordering, the committed controller
binding and complete hand reconciliation precede observed execution facts. A
missing or ambiguous pair remains UNKNOWN with bounded counts from this read;
zero counts never prove records never existed. The preflop missing-pair case is
independent of a positive river normalization case.

Only closed selected/captured/expected/accepted action and amount fields, stack
and bet, fixed enums, hashes and guards escape. No cards, raw records, names or
free-text reasons escape. Normalization classification is derived geometry, not
an original controller explanation or a verdict on poker correctness. The
original normalization reason remains null. The current source fence stays in
place: after the original image retires it cannot be relabelled as a later one.

The existing bounded Node child and Python sanitizer own transport and output.
All prior selector versions retain their original behavior. Qualification and
live inspection remain separate from source delivery.

Captured worker choice and final selected choice are distinct when an original
qualified authority was withdrawn before acceptance. The installed reconciler
rebuilds that allowed transition. Explicit comparison flags preserve the two
choices; `normalizationComparison: selected_vs_accepted` prevents a later
controller normalization label explaining an earlier authority withdrawal.

UNKNOWN reports retain the actual SDK whole-hand reconciliation status and
closed gap counts, explicitly scoped to the whole original hand. Binder reason
counts use only this target's original actor/seat/ordinal anchor. Request lifecycle
counts require the original target request, its validated digest and exact
producer/turn join; another actor's lifecycle never becomes target evidence.
Unrecognized SDK reasons become an `otherCount`, never raw text. Supported
variants in this diagnostic are NLH and PLO4/PLO5/PLO6; no other domain is claimed.
