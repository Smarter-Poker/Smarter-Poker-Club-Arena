# Prepare publication without holding the production transaction

The previous UI measurement reached protected merge in 10m55s and the origin in 22m42s. Six minutes were spent behind a previous publication before admission could start. The production lock covered read-only admission, client tests, and artifact preparation as well as production writes.

The existing publisher now prepares outside that lock. One reusable-workflow caller retains the identical non-cancelling production key across the complete transaction: retained-runtime verification/receipt, origin transfer and atomic activation, rollback, both-origin verification, optional OTA, and the existing private-record operations. The called workflow has no event trigger of its own and every job refuses an untrusted workflow/ref/event/repository caller. Existing job commands, secret scopes, timeouts, and source identity remain pinned; only preparation results are passed as immutable inputs. Old and new publishers use the same global key during adoption.

The selection base previously followed the actual bundle revision even after a successful retained-runtime run had qualified newer non-UI source. A later simple UI change therefore requalified that earlier backlog. It may now use a newer retained verification revision only after validating the original live bundle at both origins, immutable artifacts and receipts, complete actual execution of four client shards, exact successful retention/verdict proof, source inputs, and ancestry to the publication target. Unknown evidence preserves the original conservative base. Later unqualified financial changes still select full coverage. Lookup is bounded to ten successful runs and a twenty-second optional evidence budget.

The three browser shards installed by #8582 remain unchanged. Required protection, financial qualification, production compare-and-swap, append-only assets, credential isolation, and the single publication route remain. No SQL or engine operation is involved. A representative UI delivery and live timing are recorded separately in the task evidence; this source change alone does not claim a speed target.
