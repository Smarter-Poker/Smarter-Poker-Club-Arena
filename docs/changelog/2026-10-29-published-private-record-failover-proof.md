# Published private record client failover proof

The independent gateway's direct WebSocket check does not prove the published
application switches transports. The existing post-deploy workflow now has one
explicit `run-private-record-client-proof` route. It accepts only exact client and
gateway SHAs and the owning gateway publisher run ID. It requires the successful
protected gateway activation, authenticated delivery and cleanup steps, plus their
actual token-free functional artifact, before creating a reserved account.

One Chromium case loads the real published member workspace. It interrupts only
that browser context's engine `/ws/channel`, observes the independent gateway's
real READY and changed messages, changes only its own free profile avatar, and
requires the real member-detail response and visible image. Genuine Supabase
join/leave and received-frame observations must prove that the reserved topic has
no active paid subscription or matching paid signal during that window. It restores the
engine channel, requires genuine primary READY, closed fallback sockets before a
second own-record update, and no fallback signals during that update,
then retires the reserved zero-balance account through the existing guarded owner.
Both client origins, gateway revision and enabled paid source are checked before
and after. There are no fabricated frames, served-script replacements, engine
restarts, native distribution changes or source switches.

Invocation is through the existing `post-deploy-e2e.yml` repository-dispatch route
with exactly `{client_sha, gateway_sha, gateway_run_id}`. Normal publication jobs
are unchanged. This source does not enable the currently empty fallback build
input. An invoked case whose published client has no fallback fails rather than
reporting a skip or transport certificate.

The final receipt is limited to the modern published web client and always says
`paidRetirementQualified: false`. It does not establish cached/native adoption,
a complete subscriber census, universal playability or dollar savings. Source
qualification and an actual successful hosted production run remain separate.
