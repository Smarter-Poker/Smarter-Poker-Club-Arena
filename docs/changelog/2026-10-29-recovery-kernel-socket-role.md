# Bound the current inspector listener to a container process role

The protected TCP-only observation established a genuine current loopback listener, without identifying which process holds its socket. Pending observation v5 adds only inspectorOwner: main, other_container_process or unknown. This is a current kernel role projection, not original inspector provenance or authority to attach, signal or close a process.

The helper joins one fixed-port LISTEN inode in the current network namespace to FD links from bounded PID-only Docker container membership. Two complete matching snapshots bind membership, process start times, network namespaces, listener inode and one observed member owner. Multiple listeners, shared or unmapped descriptors, permission failures, races and bounds remain unknown. It reads no command lines or environments and exports no PIDs, IPs, inodes or private paths. Both snapshots share one 16,384-FD cap; membership is capped at 256, fixed network files at 128KiB, and the existing eight-second supplemental envelope covers TCP, kernel metadata and before/after container/image/process/healthy-source binding. The original 30-second transport, 4KiB output and request/unit rechecks remain unchanged.

Kernel role reads run only after genuine TCP listening. Optional kernel failures preserve TCP evidence when its independent identity rechecks succeed; expired or changed binding erases any positive role. Original intent-bound inspector authorization, phase arguments and endpoint/main-PID/source checks remain unchanged.

Regression coverage retains all 77 existing cases and adds parser, privacy, shared-budget, race and binding tests. Three Linux-only cases use owned parent/child processes, real sockets and real proc metadata for main/child ownership, shared descriptors and disappearing/replaced listeners. Only fixed private test port and Docker-membership boundary are substituted. Mac skips are explicit and are not Linux proof; the connected required law forbids skipped cases on Linux. Actual container integration and any permitted subsequent operation remain the sole production owner's work through the protected route.
