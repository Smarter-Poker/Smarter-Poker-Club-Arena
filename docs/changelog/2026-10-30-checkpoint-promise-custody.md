# Retain the one checkpoint Promise until its outcome is read

The legacy Inspector transport previously used a direct `Runtime.callFunctionOn(awaitPromise: true)` to invoke the async checkpoint guard. A real isolated Node 22.23.3 reproduction returns CDP `-32000: Promise was collected` when an otherwise unrooted pending Promise is collected. The maintained transport then reports a nonretryable protocol refusal even though the guard has begun. This reproduces a concrete transport defect; the discarded response from production run 41071578166 does not establish that it suffered this particular error.

The transport now invokes the same guard once, receives its Promise handle in the existing owned `legacy-checkpoint` object group, validates that handle, and awaits it with `Runtime.awaitPromise`. A synchronous rejection observer prevents an immediate rejection from becoming unhandled before the second request; the original Promise is returned unchanged, so the await still reports its actual rejection. Both requests share the existing absolute work deadline. The existing cleanup releases the group and closes the owned Inspector. No guard replay, global cache, deadline extension, production garbage collection, or change to retained guard `7acf0cb7778fcbbcf382f55a6a5ebd2ae90068af3497c199c1c711db50fa5c32` is introduced.

The existing native transport fixture exercises collection after the real guard enters, an unresolved Promise that must remain nonretryable/unknown, and a Promise that settles once after collection. The same subprocess verifies one guard invocation, one Promise await, zero CDP errors, the original target still alive, closed Inspector and normal target exit. Existing timeout and protocol-error assertions follow the actual await request rather than the invocation request. Production deployment and the original 15 hands/128 funded seats remain separate acceptance requirements; these isolated results do not certify their recovery or resolve the historical unknown outcome.
