# Retain the original guard result before cleanup can lose the reply

The original legacy checkpoint client previously printed its guard result only after Inspector cleanup. A client killed at the absolute deadline could therefore discard a result it had already received. The c05 attempt returned no final result; its internal stage and effects remain unknown, so this change does not explain or recover that historical outcome.

The same invocation now emits one typed, bounded guard-result observation before cleanup. Its host collector compares the exact original fsynced intent, validates the run/control/source/instance and intent digest, writes an exclusive mode-0600 receipt keyed by the exact intent digest with file/directory fsync, then prints only that retained sanitized observation to the existing failure journal. It cannot authorize release, retry, deferral or Inspector closure. A proven non-acting deferral may create another distinct intent under the same run key; both receipts survive, while the same intent cannot overwrite its receipt. Final stdout remains the original final-result protocol; only verified final cleanup can establish closure. Collector failure fails the attempt without bypassing native cleanup. Both native work and host collection remain within the same absolute forty seconds, including the existing five-second cleanup reserve.

A real isolated Inspector fixture returns a guard result containing an injected private field, stalls the original cleanup request, and kills only its controller. Before the change no receipt survived; afterward exactly one sanitized result survives with cleanup explicitly unverified, retry forbidden, one guard call and no claimed closure. This repairs result retention, not the underlying timeout or live frozen-tournament recovery.

The connected startup fixture now preserves the physical newline when extracting the original Docker child launch. On hosted Linux, discarding that newline turned the continued pipeline backslash into a fifth synthetic argument at shell EOF. Real Bash now consumes the original continuation; all nine neutrality/startup checks and the exact four-argument assertion remain intact. The hosted failing case is the before evidence; local macOS Bash 3.2 already passed the old form, so no local before-failure is claimed. Production pipeline and runtime bytes are unchanged by this fixture correction.
