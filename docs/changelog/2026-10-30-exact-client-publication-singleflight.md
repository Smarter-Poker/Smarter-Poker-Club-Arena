# Exact client publication preparation

Two normal publications selected protected target `85f5119d9bf88af34869cf629eedae509ba6b3b7` and each requested the same full sixteen client shards and build. Their different published baselines both selected the full suite. Runner assignment delays amplified the duplicate requests.

The existing publisher resolves the exact target, then one non-cancelling GitHub concurrency group for that repository and target owns its complete client preparation and existing production transaction. Different targets retain parallel preparation. A workflow-call-only helper groups the existing jobs; it introduces no event entry, second publisher, schedule, watcher or retry loop.

After acquiring that target group, a duplicate may stand down only when both public URLs already serve the exact target and the original protected publisher is terminal-success. The proof binds its complete unique same-run/attempt/head four- or sixteen-shard matrix, actual successful test steps, successful immutable build/seal, original artifact digests and creation bounds, recorded selection inputs and original successful publication receipt. Missing, failed, in-flight, conflicting, expired or unreadable proof preserves complete qualification. No foreign dist is installed: each actual publication retains its own run identity and unchanged provenance checks.

The original late global production lock, transaction steps, credentials, rollback, origin checks, complete-backlog selection, financial policy check and private gateway routes remain enforced. Immutable producer readers retain historical four- and sixteen-shard support and recognize only the exact new nested caller. Existing workflow-reading contracts follow the moved jobs with the same assertions. The new helper is a conservative runtime/build input.

This is private source preparation, not evidence of protected merge, hosting or live delivery. The paid runner change in PR #8735 is independently owned; its nineteen routes must be preserved during final integration. No SQL, engine operation or financial record is changed here.

The standdown proof conservatively requires every original 4/16 publisher shard to have succeeded. An original publication using the existing exact-PR-tree test skip does not qualify for this new standdown and retains full qualification. This change addresses the demonstrated duplicate full sixteen-shard target; it does not claim to eliminate every possible repeated preparation.
