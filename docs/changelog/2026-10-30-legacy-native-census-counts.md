# Legacy Native Census Counts On Refusal

A legacy checkpoint refused with `retained_lightning_host_census_unproven` before attempting or completing any native stop. Its receipt did not say how many concrete native objects the existing census had found. The transport now retains only bounded counts from the five native array descriptors already returned by its existing projection: game servers, table engines, tournament managers, Lightning workers and Lightning hosts.

A count requires native object/array/Array metadata and an exact `Array(N)` description within the existing projection's limits. Missing or malformed metadata remains null; it never becomes zero. Counts appear only alongside failure receipts. No extra Inspector request, guard call, custody decision, retry, deadline, cleanup step or success receipt changes. The retained-original guard remains byte-identical.

The existing isolated native Inspector fixture checks real projected group sizes, real empty arrays and malformed metadata while requiring the original refusal, nonretryability, one guard call, same-process survival and verified cleanup. Counts diagnose the refused census; they neither prove host retirement nor establish the earlier production refusal's cause.
