# Opponent Notes And Throwable Favorites

Opponent avatar clicks recorded a notes target but opened only throwables, leaving the notes editor unreachable. The picker now exposes Notes for that displayed opponent; when reactions are disabled the avatar opens Notes directly. The private editor uses the existing owner-scoped player_notes rows and unique pair upsert. A centered, scrollable dialog restores its missing wrapper, traps keyboard focus, offers failed-load retry, blocks repeated saves, preserves failed drafts, and permits clearing the text. Existing tags and their purchase rules remain unchanged.

Favorites opens first and shows ten items ranked by the authenticated player's committed lifetime throw usage. Global popularity fills remaining positions; a new player gets the platform's ten most-used items. A bounded read-only RPC returns catalog IDs only, never another player's identity or usage records. Party and Emoji share Reactions; Food, Sports and VIP retain their contents and all 80 item identities, effects and charging rules survive.

Verification includes component account-isolation, failed-load/save, repeated-action and category tests; native PostgreSQL ranking/privacy fixtures; and mobile browser save/reopen readback. The maintained production gameplay journey additionally verifies the real opponent menu, global defaults, saved-note edit/clear/reopen and RLS isolation using reserved temporary accounts without buying in or throwing. Installation/publication and actual hosted results are recorded in the task checkpoint; source tests alone do not establish live delivery.
