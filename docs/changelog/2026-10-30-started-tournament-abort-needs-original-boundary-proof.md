# Started tournament refunds require an explicit original boundary

An operator-requested stop of an already started tournament cannot use the ordinary cancellation path. The new service-authenticated `/admin/tournament-abort-boundary` endpoint reads the persisted abort operation before touching its exact current manager and original table engines. The endpoint does not pay or cancel a tournament.

Every original dealer parks behind its existing explicit closeout fence. A pending accepted startup original is allowed to restore before this gate can arm. Accepted hand work and manager lifecycle/elimination callbacks join before the manager callback fence is applied. The exact manager generation keeps its existing heartbeat while its original child engines stop and persist their stopped bank custody. A positive proof reads the private writer sets, original continuation state, table lifecycle and exact physically stopped engine identities before the explicit database acknowledgement. A floor-state read, an elapsed timeout, a settled hand permit and a teardown diagnostic cannot mint this proof.

Accepted private movement promises join to a fixed point before any roster is retained. The persisted table roster is read again after that join; a changed graph returns pending before physical side effects. Duplicate HTTP requests join the same original operation. An interrupted response leaves the manager, original roster and closeout fences retained, including partially completed original child stops. Discovery cannot replace that current abort owner. A lost lease still fences it normally. Only a same-operation read of the immutable fully settled receipt and actual CANCELLED tournament status releases the owner through the existing exact-owner stop path. This final retirement reuses the already completed original child stops and persisted bank receipts, without a new write behind the cancellation seal. A false stop or unknown lease release remains unconfirmed; only the same original operation and immutable receipt generation can retry that retirement. `runtime_retired` is returned only after the exact manager slot and its original lease release are both clear.

This engine capability requires protected engine activation before use. The separate database operation owns cohort validation, entry and fresh-hand admission fences, final serialized custody/obligation checks, original-charge refunds and immutable receipts. Ordinary started-tournament cancellation guards remain unchanged.

Focused regression checks exercise duplicate requests, accepted-hand and manager-tail waits, pending/unknown outcomes, missing original coverage, exact service authentication, and real-engine refusal of bank, snapshot, continuation and settlement writers.
