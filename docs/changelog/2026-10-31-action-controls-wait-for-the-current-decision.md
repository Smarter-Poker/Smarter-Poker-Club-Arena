# Action controls wait for the current decision

An authoritative retained snapshot can show the current actor while deliberately withholding its action capability. The client previously offered controls that its own safe submission guard would refuse. Rendering, keyboard input and submission now share that readiness predicate. The ordinary turn clock continues, and only a fresh authoritative ready frame restores controls. No previous token is retained or reused, no refused wager is replayed, and the existing Lightning and fold safeguards remain.

The existing retained-input publication in engine fix8679 restores readiness after the original retention completes. This client change uses existing state fields and adds no HTTP recovery route or engine dependency for its safe refusal behavior. It hardens a reproduced UI contract; it does not identify the exact local predicate behind historical incident75969.
