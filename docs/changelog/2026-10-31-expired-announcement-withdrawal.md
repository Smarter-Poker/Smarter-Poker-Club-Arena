# An expired announcement has its own cancellation outcome

The ordinary withdrawal signals the original transaction and requires its genuine exit-130 failure receipt. The pinned bd11 generation instead returns exit 75 from announcement-only recovery before recording that failure, retaining its request and allowing the original systemd unit to return. A changed invocation after the October 31 withdrawal establishes that the original invocation changed; the exact original recovery log remains unavailable, so that observed transition alone is not a complete execution trace.

The existing withdrawal route gains an explicit `cancel_expired_announcement` mode restricted to the qualified bd11 control bytes. It binds the original request, source hashes, announcement and fixed window, positive completed fifteen-step v3 thaw, released Lightning journal, unchanged desired container and instance, absent checkpoint/runtime/seal ownership, original process and cgroup, and loaded stop directives. No engine service, runtime restore, money write, new release or false exit-130 receipt is available.

A durable cancellation intent precedes persistent masks for only the exact release/intake/path instances. A durable stop-issued record precedes one stop of the release unit. Unknown acknowledgements permit observation only. Positive same-instance quiescence after an interrupted intent can complete without any stop; a changed serving instance remains refused. Actual unit exit/status and empty cgroup evidence own the new typed cancellation receipt. Retirement preserves original announcement/window and released-hold history, and continues through its own durable records after partial cleanup.

Focused native cases cover ordinary withdrawal, complete thaw counts, foreign/runtime/unknown custody, loaded unit hooks and propagation, incomplete masks, crash boundaries, unknown stop, positive quiescence without a stop, and partial retirement. A unique throwaway Linux systemd unit qualifies actual mask/reload/stop semantics and always retires its own fixture. macOS reports that platform case as skipped; required Linux CI must execute it successfully before protected merge. This source does not prove a production cancellation or engine deployment.
