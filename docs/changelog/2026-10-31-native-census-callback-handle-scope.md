# Bound census callback handle lifetimes

The ABI-pinned V8 QueryObjects implementation does not introduce a HandleScope around its second-pass predicate callbacks. The callback now gives its context and prototype traversal Local handles a per-visit scope. V8 still promotes matching originals after the predicate returns; the exhaustive owner census, proxy/context/topology refusals, output limits, 8x process reserve and existing deadlines remain unchanged.

The existing native build compiles a disposable instrumented copy of the actual callback and measures live HandleScope handles across a small retained deep-chain fixture. The old callback fails with109644 extra handles across9831 visits; the scoped callback passes with9830, leaving only upstream per-object growth. The shipped addon and diagnostics receive no test counters. Temporary proof artifacts are removed. Existing two-case original-EED qualification now traverses an external loopback CDP client into the marked collector, its nested Inspector session and the actual native addon before calling the unchanged EED guard. Existing native boundary cases remain enforced.

The active CPP source digest and its scale descriptor checks bind the changed bytes. Historical runtime/guard and previous qualification receipts are unchanged. This corrects demonstrated handle lifetime growth; it does not establish the phase/cardinality of the failed production attempt, promise that full GC can be cancelled, or guarantee completion on every real heap. No production read, Inspector invocation, release, restart or retry is part of this source change.
