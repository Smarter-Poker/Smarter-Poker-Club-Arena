# Original recovery control receipts contain public operational fields

The explicit original tournament control helper validated raw canonical replies but returned those objects into its Actions artifact. Those replies can include per-player refund basis, rosters, seats, and ledger references. A single return boundary now projects explicitly typed public operation and runtime tuples, state/generation/hash fields, and selected aggregate financial totals. Raw responses remain transient for the existing strict validation and outcome decisions.

Canonical, settlement, and runtime summaries carry a SHA256 digest labelled as a serialized response digest, not economic validation or a canonical money hash. Unknown, partial, lost-acknowledgement, and successful outcomes use the same allowlist. Health and request summaries also discard future fields. Exact preparation tuple behavior, one-action limits, readback, and no-retry behavior remain intact.

Focused synthetic transport cases retain the original thirteen cases and add private canaries across preparation/read, abort read, settlement, already-settled, ACK, runtime retirement, lost ACK, canonical refusal, and later health failure. This local follow-up performs no production control, SQL, refund, or release operation. Protected delivery remains pending the parent control PR and normal checks.
