# Confirm tournament auto-seat openings in the current page

TournamentAutoSeat could mark a destination handled before the parent page actually opened it. A full local table dock or a response from another page could then suppress the retry. Pending reads and popups also needed to belong to the committed account and session.

The watcher now attaches a local opening attempt to each request. MultiTablePage acknowledges that exact attempt only after its seated tab commits, or reports its local table cap. Correlated requests and acknowledgments stay within the current page; ordinary seating events retain cross-tab behavior. Unconfirmed attempts remain retryable while the scoped seat query still confirms eligibility, including after the initial discovery freshness window. Account changes, replacement auth sessions, unmounts and superseded reads invalidate prior work. Cap refusal preserves a visible explanation and the urgent blind-off context.

Validation:88 checks passed across seven normal project test files with zero failures or skips. They cover actual parent commits, two bus endpoints, table limits, stale responses, identity changes, StrictMode, suspended renders, retry age, ordinary seating and owned storage cleanup. Four exact source postimages from independently reviewed commit edab263cd833aa9d5b632b4c4991898ed519e20a were integrated against matching protected-main preimages. Formatting and whitespace checks passed. Full client compilation belongs to dependency-complete CI; this Mac retains missing native/RevenueCat dependencies without installing new copies. Actual tournament movement, the next accepted hand, publication and served behavior remain separate requirements.
