## What the proposal now records, and where

**Ledger: `decision.plo4Policy.inputs`** (`plo4-input-binding-v1`). Built inside `evaluatePlo4LivePolicy` from the same values the proposal consumed, assembled only after every canonical check passes (a refused proposal records `null` and its named reason), deep-frozen and copied so that no array or object of the request, the equity owner or the read view is aliased. It is assembled inside the timed region, so the existing 4 ms work check governs it.

The receipt's `equity` field now holds a frozen copy of the sample actually consumed, or `null`; it no longer echoes whatever the caller passed (see defect 2).

**Actor and scope isolation.** A postflop sample whose provenance does not name exactly this decision's contesting opponents (a folded seat, a missing opponent, a player from another table), whose labels claim calibration or solver input, whose scoped row is outside the decision scope, or whose window is not the merge of its rows is not consumed: the status is `rejected_population` and the proposal prices without it, as with no sample.

**Read frame.** The worker sets `plo4Policy.readFrameSha256` to the private read frame it captured for the decision (fast path) or the retained frame (second look), the same binding Phase 7 uses.

**Witness: `phase10Inputs`** on the execution witness: `version` `horse-phase10-input-binding-v1`, `inputSha256` (canonical sorted-key SHA-256 of the binding, the same commitment function as the Phase 7 evidence), `readFrameSha256`, `rangeStatus`. Frozen; later changes to the returned receipt do not reach it. `null` for a refused proposal; absent on retained legacy witnesses.

**Journal.** The decision record already carries the whole decision, so the binding and read-frame digest are retained with it (about 2.25 KB for a postflop receipt with two opponents, under the 512 KB record bound). The reviewer recomputes the witness from the journaled decision and refuses a different `phase10Inputs` (`input_mismatch`) or a read frame that is not the bound one (`read_frame_unavailable`).

**Worker boundary.** `horseDecisionReceiptIsValid` now checks the binding's shape, labels and internal consistency (eligible receipts carry a valid binding, refused ones `null`; `range.status` agrees with the street, the approximation status and the provenance). A receipt without the field, as retained before this change, claims no binding and stays readable.

**Telemetry.** One counter family, `phase10_range_<status>`, counts only; no binding content leaves the private receipt.

## Defects found and fixed

1. **A valid nine-plus-handed PLO4 census was named as unavailable state.** Tournament PLO4 tables seat up to the deck limit of 11 (`TournamentManagerBase`, `maxSeatsTheDeckAllows`), while the pack declares 2 to 8 dealt seats. The seat-count test sat inside the canonical-state check, so such a decision refused as `canonical_state_unavailable` and the registry reported ownership outcome `unavailable` rather than `outside_domain`. Fixed at the owner: after the canonical checks pass, a census above the pack's maximum refuses as `seat_count_outside_pack`, which the registry now lists as outside the domain. Decisions are unchanged (the baseline was and is retained); only the name and the ownership outcome change.
2. **The receipt echoed the caller's equity object.** `receipt.equity` was set to the evidence argument by reference whether or not it was consumed. A malformed sample (for example NaN) was therefore recorded as evidence while the proposal correctly ignored it, a NaN in a receipt would make the journal's JSON encoder refuse the whole decision record, and a later mutation of the evidence object changed the recorded receipt. Fixed: the receipt holds a frozen copy of the validated, consumed sample, or `null`. On the live path the equity pass creates a fresh object per decision, so no live decision changed; this was a receipt defect, not a strategy defect.

No other behavior changed. An equity sample is now refused only when its attached provenance contradicts the decision's own contesting population or labels; the live caller builds the provenance from the same opponents the policy uses, so the live proposal is unchanged.
