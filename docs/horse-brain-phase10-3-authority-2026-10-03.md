## What already existed

**How HorseLogic invokes the pack.** `HorsePolicyRegistry` maps `plo4` to the `phase10` owner. In `HorseLogic.decideInternal` the graph node `variant_policy` calls `evaluatePlo4LivePolicy(player, gs, decision, phase10EquityEvidence, opts.phase10Plo4 ?? 'shadow')` after `reference_legality` and before `tournament_utility` (Phase 7). `variant_utility_guard` then returns a tournament candidate to the reference when Phase 7 did not evaluate it, writes `finalAction`, and attaches the receipt as `decision.plo4Policy`.

**The pack's authority today: shadow only, in cash and in tournaments.** The live worker never set `phase10Plo4`, so it defaulted to `shadow`, and `assertEnvelope` refuses a caller's `phase10Plo4: 'candidate'` or `phase10EvidenceMode`. Candidate mode was reachable only offline (`Plo4PolicyProgram`, `Plo4PolicyLeague`). The pack has never driven a live action.

**How the Phase 8 path selects and refuses** ([P8.3 record](horse-brain-phase8-3-qualified-authority-2026-10-01.md)). A committed constant, `PHASE8_PROTECTED_RELEASE_SELECTION = null`, is admitted by `admitHorseQualifiedAuthority` against a committed evidence file. The worker holds one `HorseQualifiedAuthorityHolder`, admitted at start; `phase8Admission` derives candidate mode from it when each request runs. The main scheduler's gate (`HorsePhase8AuthorityGate`) admits the same selection, mirrors worker receipts and answers the acceptance-time question in `ServerTableEngineTurns` and before effect commits. The witness binds the authority and the journal reviewer recomputes it.

## The selection rule

The selection is committed at a protected code release (`HorsePhase10AuthoritySelection`: exact 40-hex `sourceSha`, `packVersion`, `contractVersion`, 64-hex `contractDigest`, `domain`, `qualificationPath` under `docs/evidence/phase10/`, `qualificationSha256`, positive `approvalGeneration`, `issuedAt`, optional `expiresAt` and `withdrawn`). There is no runtime issuer. `admitHorsePhase10QualifiedAuthority` refuses, in this order:

1. no selection: `unselected`;
2. a malformed selection, a path outside `docs/evidence/phase10/` or with traversal, a bad digest, generation or date: `invalid_selection`;
3. a committed withdrawal: `withdrawn` (sticky; only a greater approval generation renews it);
4. a pack version other than the running `plo4-policy-round1-v3`, or any domain other than `plo4-cash-single-board-after-rake-horse-population`: `continuation_mismatch`;
5. a selection for any digest other than the running `plo4StrengthContractDigest()`: `contract_digest_mismatch` (an explicitly absent running digest: `contract_unavailable`);
6. an expired selection: `expired`;
7. a missing qualification file: `missing_evidence`; any other read error: `unreadable_evidence` (transient, a refresh failure, never a withdrawal);
8. bytes that do not hash to `qualificationSha256`: `hash_mismatch`;
9. not JSON, or not `horse-phase10-qualification-v1`: `evidence_mismatch`;
10. `qualified` is not `true`, `mode` is not `contract`, or `objectives.cash.qualified` is not `true`: `not_qualified` (a development assembly always writes `qualified: false`);
11. the file's `contractDigest` differs from the running digest or the selection: `contract_digest_mismatch`;
12. the file's `sourceSha` differs from the selection: `source_mismatch`;
13. the file's pack version or domain differs: `continuation_mismatch`;
14. another contract version, a malformed `policyDigest`, `evidencePath` or `evidenceSha256`: `evidence_mismatch`;
15. the strength record the file names is missing or does not hash to its `evidenceSha256`: `missing_evidence` or `hash_mismatch`.

Only then is a frozen `HorseQualifiedAuthority` admitted (`phase: 'phase10'`, the pack version as `continuationVersion`, the file's `policyDigest`, the `contractDigest`, and an `authorityKey` over all of them). `selectedHorsePhase10Authority` returns it, or `null` for every other outcome.

**Mode.** `horsePhase10AdmittedMode` gives `off` when the caller turned the pack off, `shadow` for any decision that is not `cash`, `candidate` only when the worker's own verdict for its receipt is `usable`, and `shadow` otherwise. It is evaluated when each request runs, FAST or DEEP.

**Acceptance.** An applied PLO4 receipt is accepted by the table only when `liveHorsePhase10Authority.check(receipt.authority)` is `usable` in the same synchronous turn as `performAction`, and plan effects only after the same check. Any other verdict (`withdrawn`, `stale_generation`, `restarted`, `refresh_failed`, `refused`, `unselected`, `mismatched`, `expired`, `missing_receipt`) executes the shadow baseline, re-selects the witness to it so the exact accepted-wager check holds, and records `withdrawn_before_acceptance` with the verdict. A controller refusal or coercion of a selected proposal withdraws Phase 10 authority for this engine process.

## Phase 7 tournament ownership

The P10.2 contract can grant only the cash objective; it refuses the tournament objective by name. P10.3 enforces that three times:

- **Worker rule.** A tournament decision is never given candidate mode, whatever the authority says. "tournament decisions keep Phase 7 ownership even when the pack would be selected" runs one worker with usable test-fixture authority: the cash request is selected, the tournament request runs in shadow, and its action, Phase 7 receipt and Phase 6 attribution equal those of a worker with no authority at all.
- **Owner level.** `Plo4Phase10Selection.test.ts`: "a %s tournament decision under usable Phase 10 authority is Phase 7’s decision" (royal flush and non-nut flush SNG spots, where Phase 7 evaluates): the action equals the pack-off reference and Phase 7's `selectedAction`, and the receipt is `phase7_evaluated` and not selected. "even the offline candidate control cannot make the pack own a tournament decision": Phase 7 still selects the executed action.
- **Boundary.** `horsePhase10SelectionIsValid` refuses an applied receipt whose `utilityOwner` is not `cash`, so a tournament selection cannot cross the worker boundary even if forged.

## Witness and journal

`phase10Authority` on the execution witness carries `continuationVersion` (the pack version), `mode`, `selection`, the worker `authority` receipt, the main scheduler's `verdict`, `candidate` (the selected proposal) and `reference` (the shadow baseline). The accepted action is the witness's own `acceptedActions` and `executedAction`. It is present for every P10.3 PLO4 receipt, shadow ones included, and absent for retained receipts. The reviewer rebuilds the witness from the journaled decision and refuses a different proposal, baseline or worker authority, a selection that moved other than `selected` to `controller_accepted` or `withdrawn_before_acceptance`, a controller acceptance without a usable verdict and an intended execution, a withdrawal without an unusable verdict, and a dropped binding.

## Defects and findings

1. **Fixed (latent, offline-only until authority exists): a legalizer-rewritten candidate was still reported as applied.** In candidate mode, `HorseLogic` legalized the pack's decision and kept `applied: true` even when the legalizer changed the action or amount, so the receipt named a proposal the table would not execute. Under real authority this would have executed a size the pack never proposed under the pack's name. Now such a candidate is refused (`selectionRefusal: 'illegal_candidate'`) and the reference retained. No live decision changed: candidate mode was never live.
2. **Finding on #5969 (not fixed here).** The P10.2 record says the three tournament reasons are always in the verdict's `reasons`. `summarizePlo4Strength` keeps them only in `tournament.reasons`, so the qualification file's top-level `reasons` holds cash reasons only. P10.3 does not read `reasons`, so admission is unaffected, but the record and the code should agree.
3. **Limit: the P10.2 `policyDigest` cannot be recomputed by the running engine.** The assembler hashes four source files at the runs' head with `git show`; the engine image has no `.git`. P10.3 binds the digest into the authority key, and at runtime binds the source SHA, the pack version and the contract digest. A selecting release must be cut at a source whose four policy files are unchanged from `sourceSha`, checked at that protected release.
4. **Observation, unchanged.** In an offline tournament candidate run, where Phase 7 replaces the proposal, the receipt keeps `applied: true` (league semantics). P10.3's `selection` reports that case as `shadow_change`, not `selected`.

## Limits stated plainly

- A selecting release must ship `docs/evidence/phase10/` (the qualification file and the strength record it names) in the engine image. The image is built from `server/`; without the files, admission is `missing_evidence` and play stays shadow.
- Phase 10 has no live safety sentinel of its own. Its withdrawal sources are the committed `withdrawn` record, a controller refusal or coercion, a worker exit and refresh failure. As in Phase 8, a local generation proves what this process admitted; no instantaneous global withdrawal is claimed.
