# Horse Brain Phase 10 first-round backfill

The September 11 parity audit superseded the original offline starter definition. Acceptance is governed by [the common first-round playbook](./horse-brain-round1-playbook.md). This file describes the current source, not a claim of release completion.

The versioned PLO4 pack is an explicit heuristic baseline, with independent offline equity evidence and no solver-calibration or winning-strength claim. It covers normal single-board PLO4, 2–8 seats, positive stacks through 250BB, all streets, fixed-percentage rake up to 10%, antes through 1BB and the canonical single 2BB straddle. Unsupported board/bomb-pot contexts remain Phase 13 boundaries with explicit receipts.

Preflop has dealer-relative hero/aggressor positions, continuous depth/rake/ante inputs and RFI, limp, isolation, defense, overcall, squeeze, three/four/five-bet, reshove and call-off nodes. The streamed atlas tests the shared decision kernel over 1,071,840 first-round coordinates, five quality levels and two call prices, as well as continuous one-chip boundaries. These are heuristic entry bars, never calibrated equity percentages. Postflop uses exact-card straight/flush/blocker/set/next-card facts and the existing bounded, public-line-conditioned horse equity where available, with value/check/pressure, bet/raise-facing, dominated-draw, call-off and bluff-catcher decisions. Side-pot prices use only eligible chips and configured rake.

`HorseLogic.decideInternal` calls `evaluatePlo4LivePolicy` after the legacy proposal and before Phase 7. The default is complete shadow evaluation. For tournaments the PLO4 proposal is passed through the existing Phase 7 utility calculator in a bounded counterfactual; Phase 7 remains the sole tournament utility owner. The offline candidate route uses the same owner. The live worker rejects candidate and offline clock-control overrides. `ServerTableEngineTurns` records the final authoritative intended/coerced/fallback/not-executed result and retires superseded or expired receipts. Phase 10 has seen/eligible/fired/reason/street/utility/change/execution telemetry contracts.

The old asynchronous adapter is now an independent reference adapter for this same policy, not a separate partial strategy. Its default per-opponent range construction uses public action lines and hides private cards. The oracle remains offline; no solver, filesystem or network work is on the decision clock.

The CLI fixes `EQUITY_GOVERNOR=off` before dynamic engine imports. The league also requires the instantiated governor to be disabled with effective scale 1, records requested/effective equity work and loaded runtime-store identity/counts, and uses fixed-work policy evaluation for reproducibility. Live governance remains intact. Candidate and baseline receive identical shuffled cards, hero seat and button; hero position rotates independently across the button. Evidence explicitly states whether all relative positions have been exercised. Small smoke runs are not strength promotion, and unhydrated runtime stores are recorded as such.

Required verification includes the audit's governor and seat-rotation regressions, independent card/payout cases, the numeric atlas, all-street cash/tournament behavior, short-stack and 8-seat legality, real worker serialization, authoritative execution/fallback/retirement, no-private-card use, bounded time, fixed profile/seed replay and the combined server suite. Publication and natural receipts must be attached to the closeout before marking this phase complete.
