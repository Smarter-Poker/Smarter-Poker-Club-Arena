## What the proposal now records, and where

**Receipt: `decision.omahaVariantPolicy.inputs`** (`omaha-variant-input-binding-v1`). Built inside `evaluateOmahaVariantPolicy` from the values the proposal consumed, assembled only after every canonical check passes (a refused proposal records `null` and its named reason), frozen and copied so no array or object of the request, the sampler or the caller is aliased. It is assembled inside the timed region, so the existing 4 ms work check governs it. The census, positions, geometry and depth have exactly the meaning of the Phase 10 binding v2; the variant-specific parts are below.

| Field group     | Contents                                                                                                                                                                                                                                                                                                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pack`          | `version`, `holes`, `splitPot`, `source` (`explicit_variant_heuristic`), `calibratedConfidence: null`, `seats` [2, the ceiling for the table's mode], `seatCapOwner` (`cash_table_seating`: `maxSeatsForVariant`; `tournament_deck_capacity`: `min(10, maxSeatsFor)`), `maxStackBB` 250, `maxAnteBB` 1, `maxRakePercent` 10                                                 |
| `approximation` | `status` (`explicit_variant_heuristic`, or `..._with_uncalibrated_range_sample` when a sample was consumed), `solverInput: false`, `handShape` (`score`, `highScore`, `lowScore` for PLO8 only, `kind: heuristic_entry_score`, `probability: false`)                                                                                                                        |
| `census`        | As P10.1 v2: dealer seat, hero seat, dealt seats, the engine's posted `blindSeats`, contesting, acting, folded, away and all-in seats                                                                                                                                                                                                                                       |
| `positions`     | Hero position and offset, role, aggressor position and seat, straddle flag. Positions come from the posted blind seats (`plo4CanonicalPosition`), never from the button alone                                                                                                                                                                                               |
| `geometry`      | Pot-limit geometry the wager sizing reads (`potLimitRaiseTo` = current bet + pot + call, `stackRaiseTo`, `wagerCap`), chip unit, ante, rake schedule with the dealt count, and postflop contestable pot, eligible pot, charged rake, net pot, call price and SPR                                                                                                            |
| `depth`         | Effective, hero and deepest-opponent cover in BB                                                                                                                                                                                                                                                                                                                            |
| `board`         | Street, cards, paired, flush board, `lowPossible` (PLO8 postflop only) and the receipt's own feature list                                                                                                                                                                                                                                                                   |
| `range`         | `status` (the Phase 10 vocabulary: `not_consumed_preflop`, `unavailable`, `rejected_malformed`, `rejected_population`, `consumed_unattributed`, `consumed`), the consumed sample's equity split (high, low, total), samples, standard error, 99% bounds, scoop, quarter-or-less and sixth-or-less probabilities, pot count, the decision equity ceiling, and the provenance |

**Range provenance** (`omaha-variant-range-provenance-v1`), produced by the live sampler with the sample it describes: `source: variant_public_line_sequential_prior`, `calibration: uncalibrated`, `solverInput: false`, `reads: public_action_line_only` (the sampler conditions each dealt opponent on that opponent's public raise and call counts; HorseMind statistics are not consumed, so no read frame is bound), the prior (`attemptsPerSeat: 3`, `finalAttempt: uniform_escape`, the dealt-opponent draws inside completed samples and how many of them the uniform escape accepted), the deck (`single_deck_excluding_hero_and_board`, the dealt opponents that occupy it, folded seats included), the work (requested samples, completed samples, budget exhausted) and the contesting opponents scored, with seat and the public counts read. A draw in an iteration cut short by the budget is not counted, so `seatDraws` always equals completed samples times dealt opponents.

**Population check.** A sample whose provenance names a population other than this decision's contesting opponents (seat and user), whose deck is not occupied by every other dealt seat, or whose work is not the sample's own is refused like a malformed one: `invalid_equity_evidence`, range status `rejected_population`, no equity consumed. The live caller builds both from the same seats, so no live proposal changes.

**Witness: `phase11Inputs`** on the execution witness: `version` `horse-phase11-input-binding-v1`, `variant`, `inputSha256` (canonical sorted-key SHA-256, the same commitment function as Phase 7 and Phase 10), `rangeStatus`. Frozen. Present only for a decision with a Phase 11 receipt that carries the field (`null` for a refused proposal); absent on retained witnesses and for every other variant, so no existing witness changes shape.

**Journal.** The decision record already carries the receipt, so the binding is retained with it. The reviewer recomputes the witness from the journaled decision and refuses a different or missing `phase11Inputs` (`input_mismatch`).

**Worker boundary.** `horseDecisionReceiptIsValid` checks the binding's shape, labels and internal consistency through `omahaVariantReceiptBindingIsValid`: an eligible receipt carries a valid binding of its own variant and pack version, a refused one `null`; positions must be the canonical positions of the recorded button and posted blinds; pot-limit, stack and wager-cap arithmetic must hold; the range status must agree with the street, the approximation status and the provenance. A retained receipt without the field claims no binding and stays readable. The P10 audit F8 rule applies: in `client.ts` a shadow-only receipt (shadow, not applied) that fails the strict validator is dropped with its ownership record and counted as `phase11_shadow_receipt_binding_dropped`; the decision keeps its action and the worker stays up. An applied receipt still fails closed.

**Telemetry.** `phase11_range_<status>` counts only; no binding content leaves the private receipt. Registered in `HorseDataLedger` as the receipt family `phase11_range_*` (ratio of `phase11_eligible`, minimum 0.99), with `phase11_shadow_receipt_binding_dropped`.

## Defects found and fixed

All four were reproduced on unmodified main with the probe archived beside this record (`evidence/phase11/p11-1-defects-main.log`, `evidence/phase11/p11-1-defects-branch.log`): real `HandController` hands seated and posted from the engine's own `deadButtonPositions`, then evaluated by the policy on main and on the branch.

1. **Tournament dead button refused as unavailable state.** The Phase 10 closure record observed that `OmahaVariantLivePolicy` kept its own dealt-dealer check. On a tournament table of three or more the engine plays TDA Rule 30 and the button can be an empty seat; the policy required the dealer to be dealt, so every such decision refused as `canonical_state_unavailable`. On main, all six preflop decisions of the production dead-button shape (dealt 1, 2, 4, 6, 7, 8; dealer 5 empty) refused for PLO5, PLO6 and PLO8. Fixed with the Phase 10 rule (`plo4DealerSeatIsValid`): an empty dealer is valid only at a tournament table of three or more, and positions count from the posted blinds. An empty dealer on a cash table is still `canonical_state_unavailable`.
2. **Occupied button with a dead small blind mislabelled.** When last hand's big blind busts and the button stays seated, the small blind is dead and only the big blind posts. The dealer-offset formula (`plo4Position`) called the big-blind poster `small_blind` and the first to act `big_blind`. On main, for the engine hand (button 2, big blind 4 posting alone, action order 5, 1, 2, 4), seat 5 was labelled `big_blind` and seat 4 `small_blind` in all three packs; those labels chose the shadow preflop entry bars. Fixed: positions are derived from the posted blind seats (`plo4CanonicalPosition`); seat 5 is now `early` and seat 4 `big_blind`.
3. **A valid census above the pack ceiling named unavailable.** The seat-count check sat inside the canonical-state check, so a PLO6 cash table with seven dealt, a PLO6 tournament table with eight and a PLO5 cash table with eight refused as `canonical_state_unavailable`, ownership `unavailable`. Fixed at the owner, after the canonical checks: `seat_count_outside_pack`, which the registry already lists as outside the domain.
4. **The receipt echoed the caller's equity object.** `receipt.equity` was initialised to the evidence argument by reference, so a preflop or refused proposal recorded evidence it never consumed, and a consumed sample was held by reference. On main, a preflop receipt given evidence returned the caller's object (`true` in the probe for all three packs). Fixed: the receipt holds a frozen copy of the validated, consumed sample, or `null`. The live sampler creates a fresh object per decision, so no live decision changed.

**A new named refusal, not a defect fix:** `blind_seats_unavailable`, when the state carries no posted blind seats (a legacy snapshot), exactly as Phase 10. The live builder has carried them since #5999 (`ServerTableEngineTurns`: `blindSeats: handControllerRef.getBlindSeatsSnapshot?.()`).

**What did not change.** With an occupied button and a live small blind the canonical positions equal the old offset labels: the test checks all 28,150 seat, button and dealt-subset combinations of a ten-seat table. Cash decisions, entry bars, sampling, pricing and wager sizing are unchanged (the wager now reads the recorded `wagerCap`, the same minimum it computed inline). Every Phase 11 proposal remains shadow, so no live action changes.
