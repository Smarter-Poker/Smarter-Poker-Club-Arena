Horse Brain only. ## The selection rule

The selection is committed at a protected code release (`HorsePhase12AuthoritySelection`: `phase: 'phase12'`, `variant`, exact 40-hex `sourceSha`, `packVersion`, `contractVersion`, 64-hex `contractDigest`, `domain`, `qualificationPath` and `completionPath` under `docs/evidence/phase12/`, their sha256, positive `approvalGeneration`, `issuedAt`, optional `expiresAt` and `withdrawn`). There is no runtime issuer. `admitHorsePhase12QualifiedAuthority(variant, …)` refuses, in this order:

1. no selection: `unselected`, before any evidence file or policy source is read;
2. a malformed selection (an unknown or Phase 11 variant, another phase, a path outside `docs/evidence/phase12/` or with traversal, a completion path without its sha256 or equal to the qualification path, a bad digest, generation or date): `invalid_selection`;
3. a committed withdrawal: `withdrawn` (sticky; only a greater approval generation renews it);
4. a selection whose variant, pack version or domain is not the running pack's (`<variant>-cash-single-board-after-rake-horse-population`): `continuation_mismatch`;
5. no running contract digest: `contract_unavailable`; a selection for any other digest: `contract_digest_mismatch`;
6. a running policy digest that cannot be computed: `policy_digest_unavailable`;
7. an expired selection: `expired`;
8. a missing qualification file: `missing_evidence`; any other read error: `unreadable_evidence` (transient, a refresh failure, never a withdrawal);
9. bytes that do not hash to `qualificationSha256`: `hash_mismatch`;
10. not JSON, not `horse-phase12-qualification-v1`, not exactly the assembler's sixteen keys, or an `objectives` section that is not exactly `{ cash: { qualified, status, regressionMarginBbPer100 }, tournament }`: `evidence_mismatch`;
11. `qualified` is not `true`, `mode` is not `contract`, `objectives.cash.qualified` is not `true`, `objectives.cash.status` is not `measured`, or `reasons` names any failure: `not_qualified` (a development assembly always writes `qualified: false`);
12. the file's `contractDigest` differs from the running digest or the selection: `contract_digest_mismatch`;
13. the file's `policyDigestDefinition` is not `horse-phase12-policy-digest-v1` or its `policyDigest` is not `horsePhase12PolicyDigest(variant)` recomputed from the running code: `policy_digest_mismatch`. The digest hashes the variant and its pack version, so a Short Deck file can never satisfy FLO8;
14. the file's `sourceSha` differs from the selection: `source_mismatch`;
15. the file's variant, pack version or domain differs: `continuation_mismatch`;
16. another contract version, a cash margin other than the contract's for the pack (−10 bb/100 no limit, −4 bb/100 fixed limit), a tournament objective claimed qualified, an `admissionAlsoRequires` other than the contract's own, or a malformed `evidencePath` or `evidenceSha256`: `evidence_mismatch`;
17. the strength record it names is missing or does not hash to `evidenceSha256`: `missing_evidence` or `hash_mismatch`;
18. the completion record (next section): `completion_evidence_missing`, `unreadable_evidence` (transient), `completion_hash_mismatch`, `completion_evidence_mismatch`, `completion_release_mismatch`, `completion_window_invalid`, `completion_below_floor`.

Only then is a frozen `HorseQualifiedAuthority` admitted (`phase: 'phase12'`, the variant, the pack version as `continuationVersion` and `packId`, the running policy digest, the contract digest, both evidence paths and hashes, and an `authorityKey` over all of them plus the completion definition and floor). `selectedHorsePhase12Authority(variant, admission)` returns it only for that variant, or `null`.

**Mode.** `horsePhase12AdmittedMode` gives `off` when the caller turned the packs off; `shadow` for any decision that is not `cash`, whose variant is not a Phase 12 pack, or whose variant is not the pack of the holder that produced the verdict; `candidate` only when that pack's own worker verdict is `usable`. It is evaluated when each request runs, FAST or DEEP.

**Acceptance.** An applied Phase 12 receipt is accepted by the table only when `liveHorsePhase12Authorities[receipt.variant].check(receipt.authority)` is `usable` in the same synchronous turn as `performAction` (a receipt of a non-pack variant is `mismatched`), and plan effects only after the same check. Any other verdict executes the shadow baseline, re-selects the witness to it so the exact accepted-wager check holds, and records `withdrawn_before_acceptance` with the verdict. A controller refusal or coercion of a selected proposal withdraws that pack's authority for this engine process; the other packs and every Phase 8, 10 and 11 gate are untouched.

## The natural completion requirement and its floor

The P12.2 contract measured each pack on a fixed policy clock with the equity governor off, so its fallback never fired and every sample was complete and full (`liveConditions.differences[policy_clock]`, `softwareValidity.perShard.fixedWork`). It made admission depend on natural evidence: "P12.3 must state and meet its own floor for that share before admitting the pack … (Pineapple discard receipts counted apart from betting receipts)". P12.3 meets that with a committed record per pack and a floor in code.

**The record** (`horse-phase12-completion-v1`, exact keys): `schema`, `definition` (`horse-phase12-completion-definition-v1`), `variant`, `packVersion`, `releaseSha` (40 hex), `policyDigestDefinition`, `policyDigest` (that release's `horsePhase12PolicyDigest(variant)`), `gameMode: 'cash'`, `window: { from, to, releaseUnchanged, source }`, and `streets.{preflop,flop,turn,river}` each `{ eligible, completed, workBudget, samplerBudgetExhausted, sampleUnavailable, governorReduced }` with `eligible = completed + workBudget + samplerBudgetExhausted + sampleUnavailable + governorReduced`. Admission binds the record to the running policy through `policyDigest`, not through `releaseSha`.

**What it counts** (`horsePhase12CompletionOutcome`, `horsePhase12CompletionCounts`, pure functions over journaled `remainingVariantPolicy` receipts). Population: natural cash betting decisions of the pack's variant and version. Not counted: tournament decisions (they never admit candidate mode) and every Pineapple discard (its receipt street is `pineapple_discard`, never a betting street; the extractor also counts journaled `discard_decision` records apart by name and never prints them). Eligible: the receipt is `eligible`. Each eligible decision counts under the first outcome that applies:

| Outcome                  | Read from the receipt                                                                                                            | Why it is not the measured policy                                                             |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `workBudget`             | `reason: 'work_budget'` (the policy passed `liveBudgetMs`, 4 ms, and fell back to the reference)                                 | It executed the reference                                                                     |
| `samplerBudgetExhausted` | a consumed live sample with `inputs.range.provenance.work.budgetExhausted` (the 2.5 ms sampling deadline cut it)                 | It priced fewer samples than it requested                                                     |
| `sampleUnavailable`      | postflop, and no consumed sample of the sampler's own (`unavailable`, `rejected_*`, `consumed_unattributed`, or unreadable work) | The matrix never priced a postflop proposal without one                                       |
| `governorReduced`        | postflop, a complete consumed sample whose `requestedSamples` is below `HORSE_PHASE12_FULL_SAMPLES` (32)                         | The equity governor shrank the request under load; the matrix ran with the governor off at 32 |
| `completed`              | otherwise (preflop never samples)                                                                                                |                                                                                               |

The fourth row is the correction the Phase 11 post-merge audit asked for: Phase 11's definition counted a sample the governor had reduced but that finished what it asked for as completed. The full count is the sampler's own: the sampler's request is now `remainingVariantRequestedSamples(scale)`, and `remainingVariantRequestedSamples(1)` is `REMAINING_VARIANT_DOMAIN.defaultSamples`, both pinned by test, so the two cannot drift apart.

**What admission requires of it**: the selection names it and its sha256 (`completion_evidence_missing` otherwise or if the file does not exist; `completion_hash_mismatch` for other bytes); it is well formed with counts that add up (`completion_evidence_mismatch`; a Phase 11 record, which lacks `governorReduced`, is refused here); it was measured on the running pack's policy (`completion_release_mismatch`); its window is a real interval of exact ISO timestamps, the release was unchanged throughout, and the window ended no later than the selection was issued (`completion_window_invalid`); and every street clears the floor (`completion_below_floor`).

**The floor: 0.95 per street, on the 99% lower confidence bound** (`HORSE_PHASE12_COMPLETION_FLOOR`), with the P11.3 justification, also in the code:

- _Why a floor at all._ A decision that falls back executes the reference, so a hand can mix candidate and reference streets in a line neither arm of the matrix played, and a truncated or reduced sample prices a different proposal.
- _Why 0.95._ No calibrated cost of such a line exists in source (the same reason the P12.2 contract has no effect-size floor), so the floor bounds the unmeasured share rather than its cost: at least 19 of every 20 eligible decisions on every street must be the measured policy. A stated bound, not a fitted number; a different one is a reviewed code change and is bound into every authority key.
- _Why per street._ Sampling runs postflop; a pooled share would let a completing preflop hide a failing river.
- _Why a lower bound._ The Wilson score lower bound at the P12.2 interval's own z (`REMAINING_VARIANT_STRENGTH_CONTRACT.interval.z`, Φ⁻¹(0.995) = 2.5758…): a street whose true share is below 0.95 passes with probability at most 0.5%, and even an all-complete street needs 127 eligible decisions (`n / (n + z²) ≥ 0.95`). Tested: 127 all-complete passes, 126 does not; 100 non-completing in 2,000 is refused whichever outcome it is, 50 in 2,000 is admitted.

**The reader.** Stage 1, `server/scripts/phase12-completion-extract.py` (same argv and outputs as Phase 11's: `<from> <to> <release-sha40> <variant>`), runs read-only on the engine host over closed archive segments only, verifying each segment's sha256 name, and prints one line per window decision of one pack and release with its journaled `body.decision.remainingVariantPolicy`; it names every exclusion on stderr (`excluded_release_other`, `excluded_multiboard`, `excluded_discard_decision`, `segment_digest_mismatch`, `segment_retired_during_scan`). Stage 2, `server/src/scripts/phase12CompletionRecord.ts`, counts with `horsePhase12CompletionCounts` and computes the release's digest from `git show <release>:server/<file>` over `HORSE_PHASE12_POLICY_SOURCE_FILES`, never from the checkout it runs in; it refuses by name: `unknown_variant`, `invalid_release`, `invalid_window`, `release_unchanged_not_proven`, `release_sources_unavailable`, `malformed_extract_line`, `decision_outside_window`, `no_records`. Both stages are tested on real policy receipts (below); neither has read a host journal yet.

## One pack never admits another

- **Admission.** The same Short Deck selection and files admitted as Pineapple, FLH or FLO8 are `continuation_mismatch`; a Short Deck qualification under a FLO8 selection is `policy_digest_mismatch`; an FLH completion record under a FLO8 selection is `completion_release_mismatch`; a Phase 11 admission is never a Phase 12 authority.
- **Holders.** A holder of each pack is `usable` only for its own pack's admission; any other Phase 12 pack's admission, a Phase 12 admission in a PLO8 holder, and a Phase 11 admission in a Phase 12 holder are all `mismatched`.
- **Gates.** A withdrawal, a refresh failure and a worker restart at three pack gates leave the fourth `usable`; a controller refusal withdraws only that pack (`HorseDecisionEffectCommit.test.ts`); a usable Short Deck authority stamped on a FLO8 receipt is refused at the FLO8 gate and the baseline executes; no Phase 11 gate accepts a Phase 12 receipt (`client.test.ts`).
- **Worker.** With only Short Deck selected, Pineapple, FLH and FLO8 decisions run in shadow, and their receipts cannot borrow the Short Deck receipt at the worker boundary; a Phase 12 selection leaves every Phase 11 holder `unselected`.

## Phase 7 tournament ownership

The P12.2 contract can grant only the cash objective; it refuses the tournament objective by name per pack, and Crazy Pineapple has no tournament format. P12.3 enforces that three times:

- **Worker rule.** "a %s %s tournament decision with %i seats keeps Phase 7 ownership even when the pack would be selected" (Short Deck flop, FLH turn, FLO8 flop, each a spot where the proposal differs) runs one worker with usable test-fixture authority: the request runs in shadow and its action, Phase 7 receipt and Phase 6 attribution equal those of a worker with no authority. A Pineapple tournament decision under usable Pineapple authority stays `pineapple_tournament_unapproved`.
- **Owner level.** `remainingVariants/RemainingVariantPhase12Selection.test.ts`: "a %s %s tournament decision under usable Phase 12 authority is Phase 7's decision" on four SNG spots where Phase 7 evaluates and the proposal differs.
- **Boundary.** `horsePhase12SelectionIsValid` refuses an applied receipt whose `utilityOwner` is not `cash`, checked on the receipt HorseLogic actually produces offline, and refuses another Phase 12 pack's or a Phase 11 pack's authority.

## The illegal-candidate guard under live admission

P12.2 added the P10.3 guard for the offline candidate. P12.3 keeps it on the live path: in `RemainingVariantPhase12Selection.test.ts` the mode the worker admits from usable cash authority, on the real policy clock with no evidence control, is applied to a forged off-grid wager for all four packs; the receipt is `applied: false`, `selection: 'shadow_change'`, `selectionRefusal: 'illegal_candidate'`, the reference is executed, and the boundary accepts it only as what it is (relabelling it `selected` is refused).

## Witness and journal

`phase12Authority` on the execution witness has the Phase 8 binding shape: `continuationVersion` (the deciding pack's version), `mode`, `selection`, the worker `authority` receipt, the main scheduler's `verdict`, `candidate` (the proposal) and `reference` (the shadow baseline). It is present for every P12.3 Phase 12 receipt, shadow ones included, and absent on retained receipts (no `selection`) and on every other variant, so no existing witness changes shape. The reviewer rebuilds it from the journaled decision and refuses a different proposal, baseline, pack version or worker authority, a selection that moved other than `selected` to `controller_accepted` or `withdrawn_before_acceptance`, a controller acceptance without a usable verdict and an intended execution, a withdrawal without an unusable verdict, a dropped binding, and a binding moved to the Phase 10 or Phase 11 slot.

## Defects and findings

1. **Fixed (integration, before any held-out run): the P12.2 selection-guard test expected natural refusals.** On the combined branch P12.1's legal form leaves no natural `illegal_candidate` refusal; the test now pins zero natural refusals and the forged off-grid case, and the P12.2 record and changelog say the cents/whole-dollar defect is fixed by P12.1 (commit `4fe703f8`).
2. **Fixed (latent, offline only until authority exists): an applied Phase 12 receipt had no rule at the worker boundary.** `horseDecisionReceiptIsValid` checked only the P12.1 input binding; now `horsePhase12SelectionIsValid` refuses an applied receipt without usable authority for its own pack, a tournament one, or one claiming acceptance.
3. **Definition correction carried from Phase 11's audit: a governor-reduced sample is not completed.** Phase 11's completion definition counted it as completed; Phase 12's counts it as `governorReduced`, and the full count is tied to the sampler's own request.
4. **Consequence to record: P12.3 changes three hashed policy files** (`HorseLogic.ts`, `RemainingVariantLivePolicy.ts`, `RemainingVariantSampler.ts`), so `horsePhase12PolicyDigest` moves for every pack (now `short_deck f8a1677f…`, `pineapple 1f596e83…`, `flh a9432765…`, `flo8 e1180093…`). No decision changes (the receipt fields are metadata; the sampler request is the same number), but a P12.2 matrix assembled before this merges would be refused `policy_digest_mismatch`. The held-out matrices must run on a source that contains P12.3.
5. **Stricter than the contract's wording, by choice.** The contract names only the `work_budget` fallback; the record also counts sampler truncation, a missing sample and a governor-reduced sample as not completed, for the reasons above.

## Limits stated plainly

- A selecting release must ship `docs/evidence/phase12/` (the qualification file, the strength record it names and the completion record) in the engine image; without them admission is `missing_evidence` or `completion_evidence_missing` and play stays shadow.
- The completion record is produced from a shadow (or earlier) release whose policy digest equals the running one; a release that changes only this authority module, the worker or the table turn code keeps the digest, which is intended.
- Natural completion is implemented but unverified: the reader has run only on temporary segments in tests, never on the host journal, and no window has been predeclared. The live sampler's governor scale and 2.5 ms deadline decide how much of a natural window counts; nothing here measures that yet.
- Phase 12 has no live safety sentinel of its own. Its withdrawal sources are the committed `withdrawn` record, a controller refusal or coercion, a worker exit and refresh failure.
