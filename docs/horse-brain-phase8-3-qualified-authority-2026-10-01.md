# Horse Brain Phase 8.3: Qualified Authority Consumer and Withdrawal (S4)

Horse Brain only. This record covers P8.3 of `docs/horse-brain-phases6-15-completion-plan-2026-09-17.md`: the shared S4 consumer that lets a qualified candidate policy change real play, and the withdrawal path that stops it. It uses the maintained gate vocabulary: verified now, historical only, implemented but unverified, defective, unavailable external input, not applicable with reason.

**Activation stays off.** `PHASE8_PROTECTED_RELEASE_SELECTION` is `null` in this change, so every live decision remains in shadow exactly as before. P8.2 qualification does not exist yet. Activation happens only when the owner commits the P8.2 evidence under `docs/evidence/phase8/`, sets the selection to that file and its sha256, and ships it through a protected merge and engine release.

## Authority Contract

One generation-bound path, reusable by Phases 10 to 13. Owner: `server/src/engine/HorseQualifiedAuthority.ts`.

| Element         | Contract                                                                                                                                                                                                                                                                                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Selection       | `HorseQualifiedAuthoritySelection`, a committed constant edited only at a protected code release: exact 40-hex `sourceSha`, `continuationVersion`, `packId`, `domain`, `evidencePath` under `docs/evidence/phase8/`, `evidenceSha256`, positive `approvalGeneration`, `issuedAt`, optional `expiresAt`, optional committed `withdrawn` record. |
| Admitted record | `HorseQualifiedAuthority`, frozen. Adds `policyDigest` (sha256 of the running `PHASE8_POLICY` and `CONTINUATION_POLICY` boundaries) and `authorityKey` (sha256 over every identity field).                                                                                                                                                     |
| Evidence file   | JSON with `schema: "horse-phase8-qualification-v1"`, `qualified: true`, and `sourceSha`, `continuationVersion`, `packId`, `domain`, `policyDigest` equal to the selection and the running code. P8.2 must emit these fields.                                                                                                                   |
| Refusals        | `unselected`, `invalid_selection` (path outside the directory, traversal, malformed digest, bad generation or dates), `missing_evidence` (ENOENT), `unreadable_evidence` (any other read error, transient), `hash_mismatch`, `evidence_mismatch`, `continuation_mismatch` (version, domain or policy digest), `expired`.                       |
| No issuer       | There is no runtime approval issuer. Nothing reads a request, IPC message, environment variable or database row to obtain authority. The worker still rejects caller `phase8Postflop: 'candidate'`.                                                                                                                                            |

The only implemented domain is `nlh-single-board-tournament-postflop` with continuation `horse-tournament-postflop-round1-v4`.

## States

Each process has two holders (`HorseQualifiedAuthorityHolder`): the decision worker's and the main scheduler's gate (`HorsePhase8AuthorityGate`, singleton `liveHorsePhase8Authority`). Each has a random epoch and a monotonic local generation that increments on every state change.

| State            | Entered by                                                                                      | Leaves by                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `unselected`     | no committed selection                                                                          | a later admitted selection                                                                         |
| `usable`         | an admitted selection                                                                           | refresh failure, refusal, withdrawal                                                               |
| `refresh_failed` | a transient read failure while usable                                                           | a successful refresh of the same approval (`refresh_restored`, new generation, earlier work stale) |
| `refused`        | a non-transient refusal                                                                         | a later admitted selection                                                                         |
| `withdrawn`      | explicit withdrawal (committed `withdrawn`, safety sentinel, worker report, controller refusal) | only an admission with a greater approval generation (`renewed`)                                   |

A transient refresh failure is never a withdrawal and never a renewal; re-admitting the withdrawn approval generation is not a renewal. Acceptance-time verdicts (`HorseAuthorityVerdict`): `usable`, `unselected`, `refused`, `refresh_failed`, `withdrawn`, `restarted` (unknown or exited worker epoch), `stale_generation` (worker or main generation moved since the work was admitted or returned), `mismatched` (key, continuation version or receipt state), `expired`, `missing_receipt`.

Ledger selection outcomes (`Phase8Selection` on `HorseTournamentPostflopLedger.selection` and on the witness): `none`, `shadow_change` (a counterfactual, never applied or counted as applied), `selected` (worker selection under usable authority), `controller_accepted`, `withdrawn_before_acceptance`.

| Journal reconciliation of the binding and of a withdrawal                                                                                                           | `services/horseDecisionJournal/review.ts` `phase8BindingMatches` and the witness comparison                                                                                                          |

Already returned work cannot evade withdrawal: queued requests admit authority when they run; DEEP think-time work admits afresh; a FAST or DEEP answer waiting out think time is rechecked at acceptance against the worker generation that admitted it and the main generation current when it was returned; pending effects retire with the witness; Phase 8 keeps no cross-decision policy cache (its continuation reuse is per evaluation). When authority is not usable at acceptance, the table executes the ledger's reference (the decision Phase 8 received, which shadow executes), the witness is re-selected to that reference so the exact accepted-wager check still holds, and the ledger records `withdrawn_before_acceptance` with the verdict.

## Defect Found and Fixed

`horseDecisionReceiptIsValid` required the Phase 7 receipt's `selectedAction` to equal the final action. An applied Phase 8 candidate keeps the Phase 7 receipt (which names the action Phase 8 received), so the first live candidate would have been refused as an invalid policy receipt and failed the worker. The validator now compares Phase 7 against the Phase 8 baseline when, and only when, an authority-backed candidate is applied. Pinned by `HorsePhase8Replay.test.ts` on the four production review lines.

## Limits Stated Plainly

- A local generation is a cache generation. A withdrawal reaches the main gate when the worker's next result arrives or when the main process withdraws itself. No instantaneous global withdrawal is claimed, and none follows from this design.
- A local withdrawal (safety sentinel, controller refusal, worker report) lasts for the engine process and survives worker replacement inside it. It does not survive an engine process restart; the durable withdrawal is the committed `withdrawn` record at a protected release.
- The engine image is built from `server/` and does not contain `docs/`. A selecting release must ship the declared evidence file in the image; without it admission is refused as `missing_evidence` and play stays shadow.
