# Committed observation snapshot acquisition

The Phase 14 reader acquires one bounded PostgreSQL statement snapshot of a single actor's retained, committed hand-history roster rows. It queries the canonical roster containment index, rather than treating the asynchronously populated player index as completeness authority. A 513th hand, more than 20,000 total actions or 8 MiB of raw action JSON, a hand over 1 MiB or 4,096 actions, or a malformed hand refuses the whole snapshot. It does not quietly truncate data. Requests cover at most six hours within the latest day. The currently deployed retention routine has a one-day minimum and a seven-day setting; this reader does not change that policy or promise historical retention.

The function is STABLE, SECURITY INVOKER, and executable only by the service role (plus its owner). It adds no trigger, index, scheduled job or data writes. It returns original action ordinals while omitting top-level private fields, showdown and outcomes. The existing qualifier reduces returned records to validated public features before any observations leave the service. Unknown fields inside persisted public-node objects are never forwarded by the qualifier. The service keeps rejection counts, uses an exact source digest, validates ordered microsecond timestamps and hand IDs, limits qualified observations, and makes one request with a five-second client deadline. That client deadline is not a separate database cancellation guarantee.

A snapshot is complete only for retained committed roster rows visible to that statement. It is not an observation-time watermark: unfinished hands and commits that occur after the snapshot belong to later reads. Missing capture metadata remains visible as rejection counts. The reader deliberately does not manufacture the scoped model's complete-window boolean. Future integration must define that model population and retain exact durable receipts; repeated acquisition does not itself establish a persistent deduplication ledger.

Local compilation and 100 focused tests passed: 34 reader cases and 66 qualifier cases. The first run's failures were an unsupported test matcher and a parameterized test that spread the row array; both were fixed. Existing PostgreSQL 17.11 ran the migration against a new isolated synthetic table. Native checks verified service-only execution, invalid/null/future/stale requests, 512 timestamp ties and overflow refusal, exact microsecond boundaries, per-hand/total payload budgets, and malformed payload refusal. A second connection committed a hand during the STABLE statement: the in-flight read retained one row, and the next read returned two. Three actual completed controller hands then flowed through the actual function, actual reader and actual qualifier, yielding 12 actor observations and identical retry evidence. A final audit removed null-field expansion from sparse object projection and added the total-action bound. Native PostgreSQL then accepted 20,000 sparse actions without object expansion and refused 20,001. The projection copies present allowlisted keys, so nested explicit nulls needed by public wager rights remain intact. Shutdown and removal of the temporary cluster were verified.

The repeatable native probe is scripts/ci/probes/horse-committed-snapshot-native.mjs. Build the server first, set HORSE_PROOF_PG_BIN to an existing PostgreSQL bin directory, and pass a new evidence output filename. It does not install dependencies or access production. Its transport is parameterized native SQL, not the native PostgREST gateway or the full application schema. Source and compiled hashes are recorded in its evidence.

This component is not called by the live engine yet. Acquisition and qualification must run in an isolated background worker, outside the main and decision workers. Durable scoped persistence, replay receipts, counterfactual net-utility proposals, independent held-out/shadow evaluation, activation/rollback and natural full-pipeline evidence remain unfinished. No adaptive action or promotion is enabled by this change.
