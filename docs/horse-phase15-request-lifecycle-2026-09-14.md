# Private Horse request lifecycle capture

The private journal now records validated fast, deep, and Pineapple discard requests together with finite terminal outcomes: success, refusal, cancellation, expiry, or exception. Previously, cancellation skipped decision capture, enqueue expiry used the same cancellation signal as abort, and a deep-read refusal or uncaught computation exception could leave no private request record.

The worker captures immutable original request bytes only after its canonical envelope validation passes. The lifecycle record also requires the existing hand/turn attribution, a digest of the complete request, and a valid private record envelope. Invalid snapshots, private opponent cards, missing attribution, invalid deep parameters, and mismatched retirement identities do not become attributed lifecycle evidence. Source release remains null when unknown; no historical runtime pin is fabricated.

Posted cancellation now retains its finite cause. An expired request waiting in the worker FIFO becomes `expired`; an authority abort becomes `cancelled`. If synchronous computation has already finished, its real success record remains intact, and the existing execution-witness retirement handles the caller's abandoned result. Cancellation is not interpreted as a second computation outcome.

For an actual client job retired before dispatch, the client sends a private `OBSERVE_REQUEST_RETIREMENT` FIFO job containing its original request. The worker revalidates the original snapshot and attribution without invoking a policy, rejects a mismatched envelope or still-pending original request, and records origin `client_not_dispatched`. This is retrospective capture of the client's observed queue retirement, not evidence that the worker began computation or that capture existed at the original enqueue time. The private channel and actual client queue callback supply that provenance; this does not independently authenticate arbitrary database-owner or process-owner assertions.

The audit-only queue is limited to 64 pending retirement captures and 4 MiB of encoded original requests. Existing record, publisher, batch, disk-retention, and reader limits remain unchanged: 512 KiB per record, 64 publisher records / 4 MiB, 16 records per transaction, 100,000 retained records / 64 MiB logical storage, and 256 records / 8 MiB per hand read. Pressure or failed capture emits the existing finite capture/queue counters. No observer failure grants permission to execute an expired action. No new public table field, private-card output, exception text in lifecycle records, filesystem work in HorseLogic, database scheduler, or policy activation was added.

The existing private reader now reports `requestedRequests`, `terminalRequests`, and `requestLifecycleVerified`, plus finite missing/conflict/mismatch gap reasons. It checks one requested record and one terminal record per producer/turn, exact request digest, hand and turn identity, source agreement, record order, and terminal/result consistency. Success needs the matching captured output; cancellation, expiry, and refusal cannot hide a computed result. A caught `brain_exception` fallback remains an exception outcome even when the worker returned its legal fallback action. An output and subsequent execution must follow the request and terminal order.

New decision and discard captures carry `lifecycleVersion: 1`, so a missing lifecycle pair is an explicit gap. Legacy records retain their previous structural reconciliation behavior but cannot acquire `requestLifecycleVerified: true` without the required retained pairs. This flag covers retained request/result joins. It does not establish complete source population, accepted execution, full replay, GTO correctness, or learning authorization. Existing accepted-hand and execution checks still apply separately.

Verification passed 398 focused tests across nine files in 6.09 seconds. Twenty-one new tests cover actual client pre-dispatch abort/expiry through the real worker validator and production publisher, native SQLite transactions, and read-only review; posted abort/expiry; real reference policy completion; deep refusal; uncaught and caught-brain exceptions; Pineapple discard completion/retirement; invalid inputs; capture failure; bounded client retirement pressure; and missing, conflicting, mismatched-source/producer, and invented terminal evidence. The journal transport in these new tests is an in-process adapter to the actual store. It does not prove a deployed writer thread, native host qualification, or fresh-process complete replay. The server's final integrated compile and full-suite evidence are owned by the coordinating task.

Remaining capture gaps include a client/process/host crash before the retirement callback or worker validation, startup failure, shutdown before admission, a killed synchronous computation, volatile publisher queues lost before disk acknowledgement, capacity refusal, and unavailable storage. An unmatched persisted requested record is reported as missing its terminal; a request that never reached the spool cannot be reconstructed. Complete daily acquisition, missing-population reconciliation, retention/export ownership, full historical runtime packs and clocks, crash/restart replay, qualified native delivery, and natural execution evidence remain open. The journal configuration is not activated by this change.
