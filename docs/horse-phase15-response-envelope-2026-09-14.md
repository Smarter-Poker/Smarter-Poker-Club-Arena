# Horse Brain Phase15: validate replies before queue completion

The decision client previously retired a status response before checking its solver identity. If validation then failed, the terminal failure drained the remaining queue but could no longer reject the removed status promise. It also accepted malformed compute times, governor readings, fast-result sampling states and discard indices. A non-object worker message could throw before the failure handler.

The client now validates these fields while it still owns the active FIFO entry. Invalid responses fail the existing worker-integrity boundary, reject outstanding work, and do not increment completed work or construct an execution witness. Complete finite governor readings are required at readiness and status refresh. Stale readings remain explicitly stale. Fast results retain the complete unsigned32-bit range; zero computation time is valid. Discard indices must be integer0,1or2 before reaching the table's separate lifecycle and card-state checks. Worker scheduling, production budgets, policy choices and existing legal fallback ownership are unchanged.
