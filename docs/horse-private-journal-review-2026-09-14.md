# Private retained-hand Horse journal review

The durable journal now has an explicit read-only consumer. The compiled `server/dist/scripts/horseJournalReview.js` command reads one private retained hand and reconciles the original captured decision, private read frame, terminal execution witness and accepted hand/action. It emits aggregate counts, finite gap reasons and a digest of the inspected record manifest. It does not emit cards, profiles, read values, raw hand/actor identities or database error details.

Invoke it with the native Node executable, the absolute private journal directory and the SHA256 of the canonical `table UUID:hand number:lease generation` coordinate. Arguments do not accept a remote service or choose a write operation. Exit0 means the retained records reconciled; exit2 means incomplete evidence, exit3 means unavailable evidence and exit64 means invalid arguments. Exit0 does not establish complete capture, replay, GTO correctness or learning authorization; those four fields remain explicitly false.

The reader opens an existing database with native read-only and query-only access. It cannot create a missing directory/database, initialize a schema, append a record, delete evidence or activate a policy. Reads retain the existing256-record/8MiB transaction bounds and verify stored sizes and every record digest before using any payload. A missing or unreadable spool is unavailable, never an empty successful population. Synchronous local reading belongs in this offline command, not the action-clock worker.

The reconciliation checks the full snapshot key, exact millisecond/request/turn identity, producer and source consistency, original read-frame integrity and scope, random-state bounds, deep-request random-state agreement, original selected action, policy graph/ownership, expected controller amount, actual terminal controller fields, full accepted-history prefix and accepted producer hand/action identity. Accepted-hand retries may change transport request IDs but must preserve the accepted payload. Conflicting hand identities, action payloads, multiple decision claims or mixed worker producers remain gaps. Exact record replay does not double-count an action.

Every retained accepted `horse_policy` action must have exactly one matching decision and execution receipt. Extra unexecuted decisions need an explicit terminal retirement. Missing decisions, missing execution receipts, invalid original reads, unmatched actions, fallback lineage and unknown action origins are reported explicitly. The consumer does not infer historical Horse membership from today's profile flag, infer absent hands from an empty local spool or choose a winner among contradictory records.

Verification covers native read-only access with byte-for-byte unchanged storage, missing storage without creation, nine variant labels, fast/deep identity, coerced wagers, explicit retirements, exact replay, conflicts, mixed producers, missing records, altered evidence and bounded/private command output. The variant cases prove the common evidence contract; they do not certify strategy quality or each variant's complete production domain.

A fresh compiled command also consumed the three records retained by the previous actual Horse-worker/private-writer native proof. It matched the original reference decision and accepted action, exited0 and left the database bytes unchanged. That hand's execution acceptance was synthetic. This is a real local journal consumer with bounded synthetic evidence, not natural production proof.

Still required: authoritative daily population and missing-hand acquisition, restart retries and export/retention ownership, fallback/discard coverage, complete runtime packs/effective work/clocks and full replay, the automatic cross-host daily-review consumer, causal alternatives and protected holdout/activation/rollback, qualified native storage/runtime/load, publication and natural execution. This read-only command does not close those gates. The committed-over10BB daily audit remains GTO-unverified.
