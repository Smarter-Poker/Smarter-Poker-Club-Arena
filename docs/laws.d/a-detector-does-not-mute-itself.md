# tests/a-detector-does-not-mute-itself.law.test.ts

`check-main-is-green.mjs` exists because CLAUDE.md 10.83 promises somebody is told when a workflow is red on `main` and nothing is watching it, and until 2026-09-30 it suppressed any red workflow named by an open issue carrying the `main-health-reader` label and the per-workflow marker from `workflowAlarmMarker` - both of which only this detector writes. Its own alarm step copies its whole log into the durable issue, the log prints a marker for every red workflow, and the next hourly run read those markers back as proof somebody else had it in hand: a closed loop needing no human. Issue #4332 carried markers for ten workflows and muted all of them, including `Applied Migrations Are Recorded` at 50 consecutive failures over at least 29.9 days with no green run in the window, while the job `Nothing is silently red on main` reported success. This law pins that the marker is a receipt and never a mute switch - a `tracked` workflow is reported and still alarms, differing from `SILENT` only in the word - that the narrow 10.83 exemption for an audit whose red IS its own alarm is declared in `SELF_ALARMING_WORKFLOWS` with a reason, a date and the label of the issue that workflow itself files (never `MAIN_HEALTH_READER_LABEL`), that a declared workflow which has stopped speaking is not exempt, that the registry is empty because none of the ten qualified, that age escalates rather than mutes (oldest-first report, an annotation naming the worst failure and its duration so a chronic alarm's wording still moves), and that the reader remains `production-integrity-audit.yml`'s `main_is_green` job carrying the detector's exit code into the job conclusion. Extended 2026-10-03 with the mirror image, which the 2026-09-30 fix left standing one level up (CLAUDE.md 10.86 rule 4): the detector reads every active workflow including the one it runs inside, so its own exit code decided its own next input and green was unreachable by arithmetic - run 37098827354 reported `Production Integrity Audit - 112 consecutive failed verdict(s) over at least 21.5 days, no green run in the window` from a job inside that workflow, and would have gone on doing so with the whole estate green. `SELF_ALARMING_WORKFLOWS` can never reach it (an entry names the label of the issue THAT workflow files, never `MAIN_HEALTH_READER_LABEL`, and the main-health issue is this workflow's only write path), and a wholesale exemption would hide the nine production readers beside it. So the law now also pins that only the circular part is removed: the workflow `GITHUB_WORKFLOW` names - never a hardcoded title - classifies as `RED_STATE.SELF_REFERENTIAL` and stops alarming only when every failing job in its latest verdict is `MAIN_HEALTH_JOB_NAME`, proved from the Actions jobs API rather than inferred from any issue, label or marker; any other failing job alarms unchanged; an unreadable or empty job list alarms (10.86 rule 2); and a self-referential red is still printed, still carries its marker into the durable issue, still raises a run annotation naming its age, and can never close the alarm because the all-green sentence the close step greps for is printed only when nothing at all is red.
