# tests/a-detector-does-not-mute-itself.law.test.ts

`check-main-is-green.mjs` exists because CLAUDE.md 10.83 promises somebody is told when a workflow is red on `main` and nothing is watching it, and until 2026-09-30 it suppressed any red workflow named by an open issue carrying the `main-health-reader` label and the per-workflow marker from `workflowAlarmMarker` - both of which only this detector writes. Its own alarm step copies its whole log into the durable issue, the log prints a marker for every red workflow, and the next hourly run read those markers back as proof somebody else had it in hand: a closed loop needing no human. Issue #4332 carried markers for ten workflows and muted all of them, including `Applied Migrations Are Recorded` at 50 consecutive failures over at least 29.9 days with no green run in the window, while the job `Nothing is silently red on main` reported success. This law pins that the marker is a receipt and never a mute switch - a `tracked` workflow is reported and still alarms, differing from `SILENT` only in the word - that the narrow 10.83 exemption for an audit whose red IS its own alarm is declared in `SELF_ALARMING_WORKFLOWS` with a reason, a date and the label of the issue that workflow itself files (never `MAIN_HEALTH_READER_LABEL`), that a declared workflow which has stopped speaking is not exempt, that the registry is empty because none of the ten qualified, that age escalates rather than mutes (oldest-first report, an annotation naming the worst failure and its duration so a chronic alarm's wording still moves), and that the reader remains `production-integrity-audit.yml`'s `main_is_green` job carrying the detector's exit code into the job conclusion.
