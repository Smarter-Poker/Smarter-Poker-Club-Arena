# tests/a-finished-event-keeps-no-dead-lease.law.test.ts

`reap_dead_engine_leases` removes a lease on a COMPLETED or CANCELLED event once its heartbeat is more than 60 seconds old (twelve missed renewals, twice the 30-second takeover window), whatever age cutoff the caller passes, besides every lease past that cutoff; the row is deleted only exactly as the loop locked it (same `heartbeat_at`), and only when `f06_lease_has_pending_custody` reports no pending custody, which is still counted as retained. The 600-second floor on the caller's cutoff, the table-lease loop and every RUNNING or REGISTERING event's lease are unchanged. Every engine runs the reaper at boot and hourly, so a restart clears the leases its predecessor left on finished events at once. Measured cause: 2026-10-03, the 19:07 restart left lease rows on COMPLETED events aa27c94f and e52435d6 whose holder died before releasing them, and nine such rows stood more than 60 s stale after the 21:00 database restart, removable before only by the one-hour cutoff.
