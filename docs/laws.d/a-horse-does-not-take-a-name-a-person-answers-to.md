# tests/a-horse-does-not-take-a-name-a-person-answers-to.law.test.ts

The borrowed-name rule of 2026-08-23 ("MARCUS CHEN IS A HORSE. IM DAN BEKAVAC ON SOCIAL AND KINGFISH IN THE CLUB ARENA") was enforced only against the person's row, so writing a HORSE with a name a person already uses reached the same forbidden state from the other side and was permitted in full on production 2026-09-24. The law pins that `fn_reject_horse_name_on_human` keeps both directions: a person written with a horse name still loses only the name, a horse written with a person name is refused rather than silently nulled (a null horse name is refilled by `ensureHorseComplete` at the next boot and would collide again for ever), the three conjuncts that keep the refusal from firing on legitimate writes stay (only people are counted, a profile does not collide with itself, a blank name is not a collision), no trigger on the hot `profiles` table is created, dropped or reordered, and whichever migration defines the function LAST is still the two-sided one.
