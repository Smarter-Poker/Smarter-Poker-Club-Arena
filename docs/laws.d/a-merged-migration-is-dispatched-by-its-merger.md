# tests/a-merged-migration-is-dispatched-by-its-merger.law.test.ts

The actor that performs a protected merge also dispatches the migrations that merge added: `agent-autopilot.yml` reacts to the native `closed` event of a same-repository PR it merged itself (autopilot App, same freshly minted token) and sends one `apply-merged-migration` repository_dispatch per added `supabase/migrations/*.sql`, in filename order, `dry_run` false, never retried. `-- @install-window: daily-maintenance` files are skipped by the applier's own classifier and named in the summary as queued for the daily window route. Inside the :50-:03 UTC window or the daily 04:00 Chicago break the job waits once, bounded (22 minutes), before sending anything; beyond the bound it sends nothing, names every file in the summary and on the PR, and fails. `apply-merged-migration.yml` stays dispatch-only.
