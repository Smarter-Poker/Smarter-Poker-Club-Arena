# server/src/engine/aSlowDatabaseNeverKillsATable.law.test.ts

Dan, 2026-10-17, on the ClubArenaEngineKillStorm alert ("74 engine kills in 15min"): "THIS CAN NEVER HAPPEN". The law pins both causes found in production. A Postgres statement timeout (57014) is a transient database error, and every boot read that refuses to guess (table row, hand number, crash snapshot, parked time banks) is retried in place under its own loop-phase name, so a slow database second never kills a table (2026-10-17 12:57Z: 74 kills on 42 tables, the crash-snapshot read cancelled on the 8 s timeout 57 times). And a table's restart backoff is a failure streak that survives the replacement reaching ready and ends only when a replacement has stayed up two minutes, capped at 30 s and jittered, in both GameServer (cash) and TournamentManager, so a sick table is retried less often instead of rebuilt every 250 ms (2026-10-13: 35 tables, ~1,100 kills a minute for 37 minutes). A healthy table's first death is still replaced at once, and no restart path ever cancels a game.
