# tests/an-operational-alert-sender-addresses-the-fleet.law.test.ts

Every SQL function that records a Production Alerts event through `fn_record_operational_alert()` proves, at each call on every path of its control flow, that `payload.target_task_id` is the fleet id, both as the latest body of each function and in every migration on its own (the rule is `tests/helpers/operational-sender-addressing.mjs`, its cases `tests/an-operational-alert-sender-addresses-the-fleet.decisions.test.ts`, and its one reviewed assumption is pinned); only the md5-pinned superseded history (the #5428 body) and verified recordings are exempt from the second reading.
