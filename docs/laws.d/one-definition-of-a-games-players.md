# tests/one-definition-of-a-games-players.law.test.ts

One definition of a game's players and tables (2026-09-06): three read paths answered "how many players and tables are in this cash game" with three different predicates, and `get_club_home` disagreed with itself - its player count filtered neither `is_deleted` nor `status` while its table count filtered `status`, so a seat on a table the same function did not count as a table was still counted as a player, which is the shape of Dan's "50 players, one sitting" complaint. `fn_cash_cluster_census` is authoritative because `fn_cash_cluster_tick` decides the game's shape from it. Migration 20260906163151 gives `get_club_home` (both subqueries) and `fn_cash_game_lobby` the census predicate verbatim - `coalesce(is_deleted,false)=false AND status IN ('waiting','running','active') AND lifecycle <> 'closed'` - and asserts on apply that every enabled game's table count equals `fn_cash_cluster_census`. This law pins the predicate in all three places so a future re-emission cannot drop one.
