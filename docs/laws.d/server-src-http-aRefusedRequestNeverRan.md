# server/src/http/aRefusedRequestNeverRan.law.test.ts

A refused request never ran (Realtime Phase 3 audit, 2026-09-05): `GameServerAPI.engineFetch` replays every engine call once on a 401 after refreshing the session, and nineteen endpoints ride on that retry including `/addchips`, `/rabbit-hunt`, `/insurance`, `/post-bb` and `/action`, so the retry is safe for exactly one reason - a 401 from this engine means the request was refused before anything happened. Nothing pinned that; it was a sentence in a comment in the browser about the shape of twenty-one call sites in the server, and the day a handler returns 401 after doing work the browser silently does that work twice, on routes that move real chips. Every 401 in every handler must now precede any engine lookup, database call or mutation, must be the answer to a credential check rather than to business logic, and the client must retry a 401 exactly once and retry nothing else.
