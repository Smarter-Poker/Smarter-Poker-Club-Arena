# server/src/http/theSameActionAppliesOnce.law.test.ts

The same action applies once (Realtime Phase 3, 2026-09-05): `POST /action` moves real chips and is retried on two paths - a 429 ladder at 300/450/700ms whose delays are chosen to clear the engine's own 250ms window, and a 401-refresh retry inside `engineFetch` - so the one mechanism that would have collapsed a duplicate is deliberately stepped over and nothing in the request said "same intent". The client now stamps one key per intent, generated once per `submitAction` and carried by every attempt including the 401 retry, in the BODY because a custom header would fail CORS preflight against the engine's origin; a repeat never reaches the engine and gets the first answer back, a rejection is an answer and is remembered, a refusal (401 / 404 / 429) never is so the retry stays free to run, one key carrying two different actions is refused with 409 rather than replayed, an absent key is legal and behaves exactly as before for bundles served from the origin's additive pool, the lookup sits above the rate limiter so a replay is never told to slow down, a synchronous original reservation survives the durability await so simultaneous copies join one action, a successful answer waits for durable private state, and an unknown write answer stays explicitly pending rather than authorizing another mutation, and the memory is bounded by a TTL and a hard ceiling.
