# server/src/lightning/ANewPlayersFirstLightningHandIsTheBigBlind.law.test.ts

Dan 2026-10-24, verbatim: "NEW PLAYERS SHOULD ALWAYS BE BB FIRST." A Lightning pool slot that has never been the big blind (`lightning_pool_slot.last_bb_at IS NULL`) is a newcomer, and a newcomer who is not one of the pass's big blinds is held by `fn_lightning_match_plan` (migration 20261024195059) and by its TypeScript port `LightningMatcherModel`, even when holding costs the pass a hand, with the big blinds re-taken after each hold until nothing changes; the only exception is a hold that would leave the pass no hand at all, so a pool of only newcomers still deals. The rule is not a tunable: `fn_lightning_config` and `lightningMatcherParams` report `big_blind` whatever a ruleset says and list anything else as invalid. The law pins the behaviour on the model (two newcomers, a hold that costs a hand, a newcomer pushed out of the big-blind set, an all-newcomer pool, and 400 random pools with five or more prior big blinds in which no newcomer is ever dealt off the big blind), the md5-guarded SQL loop, the `last_bb_at` key in the plan and the snapshot, and the absence of any horse distinction (CLAUDE.md 10.5).
