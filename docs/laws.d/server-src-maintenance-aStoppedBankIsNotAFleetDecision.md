# server/src/maintenance/aStoppedBankIsNotAFleetDecision.law.test.ts

`unparkedTables()` bounds every F06 blocker class through `f06PreparationHoldsGate` (#4909, extended 2026-09-21) but the stopped-custody test beside them had no bound, so a per-table fact this process cannot clear made a fleet-wide decision for ever: production went 137 -> 154 -> 187 `stopped_bank_custody_unconfirmed` over ten hours on 2026-09-25/26, monotonic, `readyForRestart: false`, with the census cost charged against the release's 15000ms admission window so the window narrowed hourly and the engine could not be replaced by the release carrying its own fix. It could never clear because `hasUnretiredStoppedTimeBankCustody()` requires `this.terminal` and then compares `acknowledgedTimeBankPark`, which is set only when `when === 'parked'` - a call site inside the dealing loop that a terminal engine does not have (267,741 tournament park rows carry a null `time_bank_snapshot` against 8,016 with banks). The law pins that the custody test STAYS above the `if (!engine.isRunning()) continue` skip, because moving it below would make it unreachable for the terminal engines it exists to catch and pass over a player's time bank in silence; that it is bounded by `STOPPED_CUSTODY_GATE_MS` so past the bound it stops deciding for every other table while still being named, counted and published (`stopped_bank_custody_stuck`, zero-seeded on /metrics); that the census publishes the engine's own `unwritten`/`unreadable` answer instead of the conflated name #5255 retired, with any unreadable or out-of-class answer failing closed to `unreadable`; that `cards_in_air` is never bounded; that a replacement engine never inherits its predecessor's clock; and that no bank or custody reason may ever enter `legacy-engine-checkpoint-guard.mjs`'s `restartHeldOnlyByProvenUnresolvableCustody` allow-list, which admits the two F06 names and nothing else.
