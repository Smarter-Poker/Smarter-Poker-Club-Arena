# server/src/maintenance/aStoppedBankPastItsBoundIsNamedAndStillRefuses.law.test.ts

The stopped-custody test in `unparkedTables()` had no bound, so on 778075b4 `stopped_bank_custody_unconfirmed` answered "not yet" for ever (137 -> 154 -> 187 tables over ten hours, 2026-09-25/26). The root cause is #5255's announcement-path write, which lets a terminal engine persist the custody it holds at every break; what outlives `STOPPED_CUSTODY_GATE_MS` is a write that keeps failing, which #5255 defines as a bank still at stake. The law pins that the custody test stays above the `if (!engine.isRunning()) continue` skip and pushes the table BEFORE the bound is consulted; that past the bound the table is reported under the distinct never-name `stopped_bank_custody_stuck` and STILL counts in `unparkedTables` and still refuses (`UNPARKED_REASON_BOUNDS.neverHoldsGate: true`), because the only per-table release guard runs for four pinned predecessors and an ordinary cutover reads no reasons; that the census publishes the engine's own `unwritten`/`unreadable` answer instead of the conflated name #5255 retired, failing closed to `unreadable`; that `cards_in_air` is never bounded; that a replacement engine never inherits its predecessor's clock; and that no bank or custody reason may ever enter the release allow-lists.
