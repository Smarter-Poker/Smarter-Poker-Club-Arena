# server/src/tournament/aRefusedFinishIsNotAStalledOne.law.test.ts

A tournament whose finish the database definitively refused owns its next ask: it holds a pending wake at the refusal's own backed-off delay (finishRetryDelayMs, up to fifteen minutes). The decided-event recoveries in GameServer (STALLED DECIDED-BUT-RUNNING on every discovery pass, and the seat-first finish sweep) are for a finish that never ran; they now skip a manager whose refused retry is not yet due, and requestDecidedEliminationSweep refuses the wake itself, because the scheduler keeps the earliest wake and a zero-delay recovery wake pulled the backoff forward on every pass. On 2026-10-07 that re-asked four Spins (87f6d0ee, 9d4067ab, a19b10fe, a6ae23f9) about every 10.6 s each for a day. Once the retry is due the recovery may wake it again, so a lost retry is still found.
