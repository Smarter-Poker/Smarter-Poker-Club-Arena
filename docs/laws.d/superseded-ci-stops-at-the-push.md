# tests/superseded-ci-stops-at-the-push.law.test.ts

A pull request push replaces its old head, and the CI run for that old head is cancelled when the event arrives, not after the new run waits 25-45 minutes for a runner: `ci-supersede.yml` joins `ci.yml`'s group for the replaced head (`before` on a synchronize, the head on a close) with cancel-in-progress and runs no job, so the cancellation needs no runner, no permission and no code. The law pins that its group renders to exactly `ci.yml`'s `ci-<number>-<sha>`, that `ci.yml` itself still cannot cancel the current head, that `ci.yml`'s heavy jobs are gated on `!cancelled()` so a cancelled run actually stops while every required aggregate keeps `always()` and reports a cancelled run red rather than skipped-as-green, that every other pull request workflow cancels its superseded run per PR (only `money-trigger-recovery.yml` is exempt) and no production writer ever cancels, and that a docs-only pull request runs no heavy suite while the ungated repository checks still run.
