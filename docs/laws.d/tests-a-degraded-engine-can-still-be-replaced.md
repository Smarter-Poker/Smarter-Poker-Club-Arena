# tests/a-degraded-engine-can-still-be-replaced.law.test.ts

A deploy read that asks what the engine is (its restart certificate or its version) takes the /health body whatever the HTTP code. /health answers 503 with the same body whenever the engine is not routing-ready. From 06:58 UTC on 2026-09-11 the equity pool was 'failed', and run 34571396262 read every answer through `curl -sf` as "/health unreadable" and let a complete readyForRestart certificate go by at 07:55. The host's locked re-check had the same `-f`. The law pins that the dedupe, break gate, locked host re-check, seal-commit re-check and Verdict never read /health with `-f`, and that only the post-cutover Verify and ROLLBACK verification keep it, deliberately. It also runs the real drain-gate script against a 503 stub carrying a complete certificate: it must accept on the first poll, and on the old file it logs "unreadable" until killed.
