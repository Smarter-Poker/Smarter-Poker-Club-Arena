# tests/a-degraded-engine-can-still-be-replaced.law.test.ts

The root-owned Hetzner release transaction accepts a complete maintenance certificate carried by either HTTP 200 or 503. It performs that check before and again after acquiring the engine mutation lock, and it still requires a running engine, a durable counting-down break, `readyForRestart`, zero unparked tables, and enough recovery time before any release is prepared. The already-sealed source and its rollback recovery may likewise use only a fully transferred 200 or 503 body, with exact SHA, running state, liveness, process identity, and local/public agreement. Before any cutover, rollback readiness additionally proves an unchanged container generation and a fresh database leader.

No new candidate inherits that exception. Candidate, pre-commit, final local, and final public checks explicitly require HTTP 200 plus the exact identity predicates; independent publication certification remains routing-ready and fail-closed. A 503 source can be replaced, but a 503 candidate cannot be reported shipped. The executable response matrices live in `tests/unit/engineReleaseMaintenanceCertificate.test.ts`; the law test pins the production ownership, ordering, executable transaction-to-prepare path, and separation without duplicating the matrix.
