# tests/a-guard-has-a-reader.law.test.ts

This repo runs its own `scripts/ci/check-main-is-green.mjs` from the scheduled production-integrity audit on `ubuntu-latest`. The detector enumerates every active workflow and reads a separate completed-`main` run window for each, so a noisy workflow cannot evict a low-frequency red workflow from one global window. A PR-only workflow with zero completed main runs is not applicable; a nonempty run history with no readable verdict is `COULD NOT TELL`, never green. A red workflow is considered already watched only when an open issue has the exact `main-health-reader` label and its exact machine marker; matching prose is not authority. The audit similarly creates, edits, or closes only its fixed-title issue carrying its immutable owner marker and label. The alarm path reads the label first and creates it only when absent; the green path never creates a label merely to search for an issue. It preserves the script's real `PIPESTATUS[0]` verdict and closes the issue only after every applicable workflow has a green latest verdict. The audit has no release, repair, or production-mutation authority.
