# tests/a-reload-cannot-fix-a-sign-in.law.test.ts

A reload cannot fix a sign-in (Realtime Phase 3, 2026-09-05): TablePage's twenty-second auto-reload failsafe returns before reloading when the engine refused the socket for auth, because a fresh page presents the same token to the same refusal and loops every two minutes while discarding the felt, the overlays and any armed pre-action; the auth cause is remembered from the 4401 close, the `auth:` reason and the auth_failed status (which the client only passes through in milliseconds on its way to 'reconnecting') and is cleared only by a socket that actually opens; the suppression is announced in both directions, to the player as a sign-in problem rather than a lost connection and to the server as `reload_suppressed`, which is a symptom report and never inflates the per-user reconnect count the alert reads; the throttled reload survives for the wedged-socket case it was written for; and the predicate inlined into TablePage to keep sessionRevoked out of the entry chunk is executed from source and proved identical to the exported one on every close code.
