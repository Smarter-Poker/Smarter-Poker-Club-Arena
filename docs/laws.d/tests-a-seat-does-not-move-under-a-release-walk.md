# tests/a-seat-does-not-move-under-a-release-walk.law.test.ts

The legacy engine checkpoint refuses a release as `engine_state_changed` when a table's CUSTODY signature moves between two observations, and #5215 kept the roster in that signature (each seat's user, occupancy, seat number and stack) on the argument that the Postgres freeze guard refuses every seat write during a break. It does not: `fn_refuse_while_frozen` returns early for the service role, which is exactly what the engine presents, and the signature reads `engine.seatedPlayers` in memory rather than any row. This law pins what actually holds a seat still for the length of the walk, the ENGINE's half of the freeze, so that neither gate can be removed while the checkpoint still depends on it: a top-up refuses on the first line of `addChips`, before the seat lookup and before any debit, and the wait-for-players sweep meets the pause gate at the top of its loop before `adoptSeatRoster` replaces the roster. It also pins the dependency itself, so that if the checkpoint ever stops pinning the stack this law is re-argued rather than quietly kept.
