# tests/a-top-up-is-charged-once.law.test.ts

A top-up is charged once (Realtime Phase 3 audit, 2026-09-05): `/addchips` is the one paid engine route where a repeat is indistinguishable from a genuine second request, because every other paid route is idempotent by hand state and topping up twice is something a player may legitimately do; the Cashier audit (2026-08-27, P0-1) gave it an `opId` and the engine keys the debit on `opId || randomUUID()`, so a caller that sends nothing silently gets no de-duplication at all, and the window that costs money is not a double tap or a 401 retry but a debit that committed while the response was lost. Every caller now mints a key, holds it across retries, keys it by amount so a retry for the same shortfall is the same purchase, and releases it only once the chips have actually moved; the `opId` is declared at every hop of the prop chain, because `TableModalsLayer` typed it away and the key survived only by the accident of forwarding the function object rather than wrapping it; and the transport-failure path still refuses to tell a player their wallet was not charged.
