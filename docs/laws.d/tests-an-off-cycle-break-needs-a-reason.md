# tests/an-off-cycle-break-needs-a-reason.law.test.ts

An engine release asks for an off-cycle "Deployment Recovery" window only with a reason (an urgent commit trailer, a degraded or wedged serving engine, or no scheduled break before its own deadline; since the owner's 2026-10-04 ruling a failed release that has not shipped and a scheduled break that shipped nothing are NOT reasons, and the seal answers them `unavailable`), never while a release of a newer engine SHA is live on the host, never while the serving engine reports stopped-bank custody the certificate refuses in every break, and the seal grants at most one per rolling hour across every release; the policy changes only when a release asks for a break, never the certificate, the admission ladder, the rollback reserve or the locked read, and a release that waits for the scheduled break always has at least one whole hour of them before its certificate deadline.
