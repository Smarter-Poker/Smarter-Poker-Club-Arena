# tests/every-refusal-has-a-runbook.law.test.ts

Every way a table can refuse you is written down (Realtime Phase 6, 2026-09-06): the 2026-09-03 outage ran twenty-two hours partly because nobody knew what to look at - the engine was writing a pre-handshake HTTP 401, the browser reported it as close 1006, which is indistinguishable from a dropped link, and nothing anywhere said what a refusal from this platform looks like. `docs/runbooks/tables-say-reconnecting.md` is the page for the next person, and a runbook rots the moment the code moves past it, so this law scans every `CLOSE_* = 4xxx` the engine and the client declare and requires each one to appear in that page - add a close code without documenting it and CI goes red, which is the point, because the undocumented code is the one nobody has seen before at 3am. It additionally pins the three sentences the runbook exists to deliver and that a summary would drop: that 1006 is AMBIGUOUS (the fact that made the outage invisible), that a green deploy run is not a deployment (the workflow reports success with the cutover skipped, so the image tag on the running container is the only proof), and that a probe with no recent rows means silence rather than health. Finally it checks the runbook is linked from the programme document and that every relative link in it resolves, because a 3am page that lands on a broken link is a page with no runbook.
