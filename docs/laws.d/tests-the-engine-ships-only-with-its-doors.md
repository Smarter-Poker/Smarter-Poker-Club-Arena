# tests/the-engine-ships-only-with-its-doors.law.test.ts

The deploy refuses to hand a build to the durable Hetzner intake when it calls a database function production does not have. Before that handoff, scripts/ci/check-engine-doors-exist.mjs reads production's pg_proc for every `.rpc('<name>')` in server/src and every literal an `...rpcName` variable can hold. For targets without original-continuation prerequisites it preserves the existing unreadable/rollback warning policy. A target calling a continuation RPC additionally requires the exact installed histories for migrations20261028233353 and20261029004521: matching target filename slug, single-statement shape and SQL MD5 derived from immutable target bytes. Missing, changed or unreadable history refuses that target before host intake; neither an allowlist nor a rollback flag waives this new prerequisite. This does not pin a later compatible abort-function body, and the owning installer still verifies actual postimage and ACL. On 2026-09-10 (fn_move_tournament_player) and 2026-09-11 (fn_ca_reprice_unpaid_tournament_place) a schema-manifest fragment declared a function before its migration was applied, so the phantom-reference gate believed it and the engine shipped calling a door that did not exist. The law pins the extractor (both incidents' call sites found, comments ignored), the end-to-end script against a production that lacks the reprice door (exit 1, door named), the warn-only paths, and the step's place before the durable intake.
