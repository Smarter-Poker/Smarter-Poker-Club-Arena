# tests/the-engine-ships-only-with-its-doors.law.test.ts

The deploy refuses to hand a build to the durable Hetzner intake when it calls a database function production does not have. Before that handoff, scripts/ci/check-engine-doors-exist.mjs reads production's pg_proc for every `.rpc('<name>')` in server/src and every literal an `...rpcName` variable can hold. It warns, rather than blocks, on an unreadable database or a rollback. On 2026-09-10 (fn_move_tournament_player) and 2026-09-11 (fn_ca_reprice_unpaid_tournament_place) a schema-manifest fragment declared a function before its migration was applied, so the phantom-reference gate believed it and the engine shipped calling a door that did not exist. The law pins the extractor (both incidents' call sites found, comments ignored), the end-to-end script against a production that lacks the reprice door (exit 1, door named), the warn-only paths, and the step's place before the durable intake.
