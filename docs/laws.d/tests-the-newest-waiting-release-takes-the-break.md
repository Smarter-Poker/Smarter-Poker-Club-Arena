# tests/the-newest-waiting-release-takes-the-break.law.test.ts

When several built releases wait at the same restart certificate, the newest one takes the break. On 2026-09-27 the oldest of three admitted releases won the engine-lock race twice: 4946473b at the 15:55Z hourly break, then 6b6eabb1 in the 16:06Z window that c8cbe6e6 had announced. Each window shipped the least code it could have. This law runs the real `newer_release_awaiting_certificate` against a disposable Git history and unit states. An older target stands aside only for a newer target that contains it, has a live unit, and has a marker naming exactly its durable request SHA. The law also runs the real certificate queue: the older target takes no lock while the newer one waits, and it keeps the unchanged 260000/245000 ladder once the newer one leaves. Every reserve stays where it was, and the marker is written only after the image build and cleared on entry and on every exit. Finally it runs the real `maintenance_certificate`: a shut certificate inside the admissible window is named on stderr with time left, reasons and `handsInFlightTotal`, while verdicts and exit codes stay unchanged. This is what the 2026-09-26 "0-92s left" diagnosis lacked.
