# tests/there-is-one-server-clock.law.test.ts

There is one server clock (Realtime Phase 5, 2026-09-06): for one day this app had TWO functions called `serverNow()` in two modules with OPPOSITE SIGNS - `utils/serverClock` (2026-08-18, `Date.now() - offset`) and `lib/serverClock` (2026-09-05, `Date.now() + offset`) - same name, same meaning, inverted arithmetic, so whichever module a file happened to import decided which clock it got, both compiled, both returned a plausible number, and one wrong import path would have turned a three-second-fast phone into a three-second-slow one and doubled the error on the turn ring. They also differed in quality with the wrong one better fed: the latency-corrected estimator (Cristian's algorithm, added after a 2026-08-28 finding that the countdown showed time the player did not have) was fed only by snapshots and drove the TURN CLOCK, while the rough one that ignores latency on purpose was fed by every EVENT and PING frame. They are one now; the law pins that exactly one module defines `serverNow`, that the deleted one is gone and unimported, that every consumer and both feeds reach the survivor, and that the estimator still converges on the lowest-latency sample rather than the average.
