# tests/the-flip-has-a-hand.law.test.ts

Nine diamond rules carried flip_after dates on which they would stop logging and
start refusing, and NOTHING anywhere called fn_ca_diamond_rule_flip - zero cron
jobs, zero functions, no application caller. The dates would have passed
unremarked for ever while every instrument built to make the transition safe
reported on a transition that could not occur; the safety apparatus is what hid
it, because everyone checked whether the flip was safe and nobody checked whether
it was connected. fn_ca_diamond_rule_flip_due now arms on a daily tick, passing
the three existing gates plus a fourth - the forecast must report zero
would-refuse SINCE the rule's configuration last changed - and reports every rule
it cannot arm rather than skipping it. The forecast learns that epoch, both
configuration tables stamp updated_at so the epoch is real, and
fn_ca_diamond_health gives one call over twelve areas because there are 28
reporting functions and nobody reads most of them.
