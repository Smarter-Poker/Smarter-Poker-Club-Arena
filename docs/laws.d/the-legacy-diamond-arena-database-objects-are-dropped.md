# tests/the-legacy-diamond-arena-database-objects-are-dropped.law.test.ts

Migration 20261004214251 drops the four legacy Diamond Arena database objects that Phase 12 of the Poker Arena Diamond build programme found exclusive and inert: `fn_arena_deposit` and `fn_arena_withdraw` (the chip-backed manual doors custody had already reduced to a refusal), `diamond_arena_events` (0 rows) and `profiles.diamond_arena_preferences` (no row held a value). It also removes the two doors' names from `fn_guard_profile_privileged_columns`, so a function created under either name later cannot inherit an admission to `profiles.diamonds`. The law pins how it was done and that it stays done: one transaction; the guard edited in place from its live text under a preimage md5 and compared byte for byte with the intended postimage, never re-typed; the two preference functions edited the same way; drops with no CASCADE and no IF EXISTS; no DROP TRIGGER or DROP POLICY; profiles and auth.users locked together under a 250 ms lock timeout before the emptiness that justifies the drop is read; the register rows and the Diamond journal kept as evidence; a live proof declared for every end state; and no later migration recreating a door, the table or the column, or naming a door to the wallet guard (CLAUDE.md 2, 10.11, 10.86).
