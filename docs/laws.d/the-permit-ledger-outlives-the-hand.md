# tests/the-permit-ledger-outlives-the-hand.law.test.ts

`smarter_private.f06_hand_permits` is never pruned, because eight days after a hand is dealt the permit is the ONLY surviving witness that its hand number was used: `public.sp_prune_hand_history` deletes both of the other two (`hand_atomic_commits` and `hand_history`) at `hand_history_retention_policy.horse_retention_days`, while `public.fn_f06_begin_hand` still refuses a re-used hand number on the strength of any one of the three. The law pins that nothing in the migrations, the engine, the client or the scripts DELETEs or TRUNCATEs the ledger, that every migration defining the retention job keeps pruning the two prunable witnesses and never names the permits, that `f06_one_hand` stays a UNIQUE index on `(table_id) WHERE state = 'reserved'` so the OPEN set is capped at one per table, and that `F06_CHANGED_HAND_OUTCOME` keeps an `accepted` permit immutable, which is what makes 1.14M rows a terminal receipt ledger rather than a leak.
