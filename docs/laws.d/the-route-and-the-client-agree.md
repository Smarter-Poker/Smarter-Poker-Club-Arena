# tests/the-route-and-the-client-agree.law.test.ts

The Postgres side of the diamond wallet and the client that reads it are pinned against each other rather than each on its own: the exact column list of every `diamond_transactions` select against the columns its mapper reads (a column read but not selected is a blank figure, one selected but never read is dead weight on a money query), `player_line` held as the PostgREST computed column it is rather than a stored one, the key set each of `fn_diamond_wallet_summary`, `fn_diamond_flow_by_kind`, `fn_diamond_arena_reconciliation` and `fn_diamond_lifetime_totals` builds against the keys `DiamondService` destructures in both directions, and every bucket `fn_diamond_kind_bucket` can emit against a panel that is forbidden to enumerate buckets of its own, so a bucket added in SQL reaches the player without a client change.
