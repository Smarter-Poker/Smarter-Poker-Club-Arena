# tests/the-write-path-keeps-only-the-indexes-it-reads.law.test.ts

Every index on a hot write table costs a WAL record per row version and, after each checkpoint, a full-page image; on 2026-10-03 the database wrote 1.31 TB of WAL in 4.4 days with ~28 backends waiting on WALWrite at peak. Migration 20261003031000 therefore keeps on the write path only indexes that something reads or that enforce something: it drops three agent_commissions indexes that were strict prefixes of another index with the same predicate (club_id, user_id, the unsettled partial), three zero-scan ca_horse_fleet_state indexes whose last_action_at key made every seat touch a non-HOT update, the zero-scan horse_mind_pairs updated_at index and the zero-scan all-in partial on ca_hand_facts, and replaces the two club_member_daily_stats covering indexes that carried hands_played and biggest_pot_won (0 of 11.3M per-hand updates were HOT) with the same keys without them. It never drops a unique, primary-key or constraint index, refuses unless every covering index is valid with its exact definition, and changes no function, grant or schedule. New indexes are built CONCURRENTLY before the transaction and the drops were run as DROP INDEX CONCURRENTLY outside it; an index added to a hot table later must name the reader that needs it.
