## Enhancements And Optimizations Separate From Launch Blockers

These are proposed improvements, not confirmed missing core features or automatic launch requirements:

1. Expose the newly installed calibration-window setter in the existing operator UI with validated range, reason, request identity and the database's idle/drained refusal behavior. Today the authenticated setup script and database control support it, but the UI action union/form has no `set_shadow_window` action.
2. Add an explicitly invoked pilot qualification report that collates existing readiness, roster, comparisons, latency, replay and drain evidence. It must preserve UNKNOWN and use existing supported doors; it must not become a watcher, scheduler or automatic release mechanism.
3. Improve low-liquidity onboarding and operator explanations using measured threshold/queue behavior, without lowering thresholds or misrepresenting a non-playing pool as healthy.
4. Tune matching, first-hand rendering, reservations and telemetry storage only where real workload measurements establish a bottleneck; preserve financial, security and fairness limits.
5. Consider a future matcher upgrade only as separately reviewed work after candidate evidence qualifies. The current m1 matcher is the launch path; replacing it is not a prerequisite created by this register.
