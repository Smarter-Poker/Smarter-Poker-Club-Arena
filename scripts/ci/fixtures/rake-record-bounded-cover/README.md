# Bounded tournament rake physical evidence

The existing full weekly quality query spent47–87 seconds reading243k rake-record heap rows with roughly79k physical reads. These migrations add physical support only. They do not change the original quality function, fingerprint, financial inputs, payouts, source65 seals, or GEN.

Install the private helper first, then each concurrent index separately through Apply Merged Migration after protected merge. Each CCI needs the existing complete12-minute admission runway and fresh external snapshot preflight; do not start two600-second builds on one12-minute allowance. The applier owns exact history, resumes a valid prefix and refuses an invalid prefix. Any invalid-prefix recovery requires its separately qualified explicit operation; there is no automatic repair. Never replay an installed file, drop a live prefix, or use a workstation publisher. A valid existing prefix can resume; an invalid or wrong same-name prefix is refused.

The fast index covers all17 fingerprint inputs only when exact decompressed JSONB size and binary/text lengths prove its tuple is below the guarded PG17/8192/MAXALIGN8 B-tree limit. Its complementary key-only index preserves every oversized or unusual valid row. Each length component is BIGINT before addition. SQL NULL contributes zero; JSON null is a JSON value. `returned_uncalled` is JSONB and `global_hand_id` is BIGINT. See `tuple-bound.md` for the2384-byte bound.

The helper is invoker, immutable, strict and parallel-safe, with fixed pg_catalog search path. It narrowly measures PG17 empty-path JSONB extraction after deTOAST, rather than claiming arbitrary physical pg_column_size immutable. PUBLIC, anon and authenticated cannot execute it; postgres and the existing service_role writer can. No PostgREST public API is introduced.

The maintained native test executes actual helper migration and both CCI bodies against a private PG17 cluster. It derives all20 types/defaults from the frozen actual catalog, reproduces8 constraints,19 prior indexes and39 trigger identities. Financial trigger bodies and maintenance/source65 collaborators are explicitly inert fixture adapters; only native expected catalog payload/OIDs are substituted. Production guards preserve all34 actual definitions/raw metadata plus ACL/RLS/columns/constraints/indexes/triggers. The test checks decompressed/compressed/external/scalar/NULL JSON, boundary arithmetic, permissions, fallback bag, natural index paths, writer maintenance and valid/invalid recovery. It does not certify financial bodies, production build duration/selectivity, whole weekly Scope capacity or future Monday completion.

Actual500-row feasibility observed all500 fast-eligible; that bounded sample is not a population estimate. Production index installation, exact readback, natural consumer adoption and full affected-flow capacity/quality remain separate required evidence. The query consumer is deliberately unchanged in this PR.
