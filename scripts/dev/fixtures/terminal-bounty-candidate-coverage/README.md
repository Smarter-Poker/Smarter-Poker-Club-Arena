# Terminal bounty candidate coverage

Run `bash scripts/dev/probe-terminal-bounty-candidate-coverage-pg17.sh` with
an existing PostgreSQL17 installation. The runner creates its own temporary
cluster on a private Unix socket with TCP disabled, then removes the cluster.
The required accounting job supplies its existing PostgreSQL17 binaries.

The fixture captures current ordinary and mystery terminal roots, actual
accepted-hand and marker readers, original locks, and the actual claim/collector
definitions through the R34/R35/R37 fixture chain. It first reproduces the old
finalizer assigning the entire pool despite an accepted unpaid knockout. It
then applies the exact guarded R38 migration.

Cases include ordinary/PKO/mystery before and after activation, all candidate
workflow labels, unknown or malformed accepted evidence, exact generation key
mismatches, real local settled markers, pending/incomplete markers, champion
own-head and mystery inventory close, immutable replay after mutable rows
change, and missing-head refusal before reserved award work. A complete database
anti-join finds a missing generation after10,001 recorded rows. This is an
existence search over the full event, with one refusal witness; there is no
truncated successful client page or arbitrary history-size refusal.

Concurrent sessions use the actual settlement lane locks: a finalizer waiting
for a claimant sees its committed exact marker and pays7.50remaining after
the2.50bounty, then five simultaneous replays produce no extra payment. The
runner also verifies migration replay, body/metadata drift refusal and seven
original-role access denials.

The wallet is the inherited documented pool-bounded stand-in. It normalizes
the test residual category to the production bounty category and counts payer
calls. These tests are not full provider, Diamond custody, real rebuy purchase,
legal dealer hand or whole top-level terminal transaction qualification. The
unchanged parent terminal authority raises on a false bounty result; source
regression tests cover that contract, while its complete native journey remains
separately tracked. No production row, payer, provider or historical adjustment
is used here. Prior terminal receipts remain immutable.
