# Horse League inherited process priority: hosted scoped controls

This finite source fixture is invoked by the existing Node22 Linux server test
`HorseLeagueProcessPriority.integration.test.ts`. It does not use a native
provider catalog, runner VM, scheduler, production credential or release path.

Status: source proposal only; no execution is claimed. Its pass status is
`SCOPED_CONTROLS_PASSED_LIMITS_REMAIN`, not full CPU incident resolution,
hydrated-corpus qualification, Horse Brain policy promotion or publication.

The test binds checkout revision, the five changed runtime sources, three direct
test sources, current Node executable and `/usr/bin/nice` bytes. It uses the same
installed tsx API already used by server worker tests. The current source process
factory is exercised directly; no replacement worker factory is used for its
PID/READY, seeded work or priority proof. Runtime image equivalence is a separate
original-provider qualification step, not implied by a hosted source-loader test.

The original leader-only operation is reproduced in an isolated fixture, without
importing old application dependencies or retired external telemetry. Required
supported controls preserve the earlier candidate's kernel/IPC/cleanup assertions,
add direct-versus-child seeded result comparison and prove the parent priority is
unchanged. A real independent unprivileged priority-raise attempt is followed by
candidate bootstrap refusal when Linux returns EPERM/EACCES. This is explicitly
not fault injection of GNU nice's positive adjustment. If privileges allow that
attempt, the result is CONTROL_UNAVAILABLE with its limitation retained; it is
never reported as a passed denial.

All other required controls fail if missing, inconclusive or unsuccessful: actual
child PID and all observed nice19 threads before/after work, CPU tick change, new
libuv identity, GC observation, advanced IPC, direct-entry refusal, spawn failure,
unexpected exit, shared shutdown join, resistant TERM followed by actual KILL
exit, and confirmed cleanup. Unknown termination remains failure. The fixture
process group is separate from the test runner and is cleaned finitely on failure;
production launch options remain non-detached.

The child fixture uses fixed public inputs, no real financial or user rows,
hydration disabled, and loopback noncredentials. The wrapper passes a minimal
environment containing no provider credentials. No production network call is
part of these controls. Network denial is not established merely by environment
sanitization; application-side loader checks remain disabled and the direct
matchup is offline. Root must retain any network-isolation limitation explicitly.

Remaining limits are emitted in every result: full identified solver hydration,
negative-parent/racing-parent kernel controls, real positive-adjustment denial,
all60s/30s/250ms runtime deadline boundaries,32-thread supported-runtime shape and
pinned-engine image/live verification. No threshold, deadline, budget, policy or
schedule is changed. Existing eight runtime/test inputs remain intact apart from
