## Implemented schedule source

`spin-expiry-business-races.py` opens one observer and two persistent psql backends.
Each command has an unpredictable exact acknowledgement marker. Verbose SQL errors
are retained, not interpreted from process exit alone. There is one20second outer
schedule deadline and one separately bounded5second cleanup attempt. Each scenario
transaction sets8second statement,4second lock and12second idle-in-transaction
limits. The actual server deadlock_timeout must be positive and below4seconds;
it is observed, never changed. These are fixture limits, not production changes.

The exact current `atomic_cancel_tournament(uuid,uuid)` definition has its own
`SET statement_timeout='120s'` function configuration. Setting the session limit
to8seconds does **not** establish that every nested operation is bounded by it.
Actual PostgreSQL17 timeout behavior through that function configuration needs
protected qualification. The20second runner deadline and client exit are not
backend cancellation proof; the protected owner must enforce and independently
observe the original whole-allocation deadline and terminal state. No function
configuration is changed here to make the test appear bounded.

**R1 preimage negative control.** Session B takes the actual G→B helper and retains
its transaction. A calls the real expiry(1). The observer must see A waiting on an
advisory lock blocked by B. B then requests the exact parent `FOR UPDATE`. The
runner requires an observed two-backend blocking cycle **and** a real deadlock
diagnostic. A's existing catch may turn its deadlock into a failed counter; B may
instead be the victim. Unrelated SQL errors do not qualify the control. Both
transactions roll back; selected business state and exact pinned authorities
must match the preimage capture. A missing cycle/diagnostic is inconclusive/failure.

**R1 candidate order and actual rollback cancellation.** Same schedule and actual
expiry call. While A waits on G, B must acquire the exact parent and A must still
be pending. B rolls back. A must then return exactly one expiry for the fixture,
zero failures/skips and actual `ok:true`. The real deferred constraints are forced
before A rolls back. This exercises real cancellation/refund authority and its
deferred guards without committing them; the estimate field is not a payment
oracle. Every selected row must restore exactly. It proves the first candidate's
G/B-before-parent relationship, not multi-candidate `created_at` ordering.

**R5 candidate outer global timeout.** B retains G/B until A actually receives
55P03 from `fn_ca_lock_settlement_lane_global`. The only subsequent SQL error
allowed is the expected aborted-transaction constraint command25P02; no JSON
expiry result is allowed. Then B rolls back. This checks the new outer-acquisition
timeout placement and selected-state rollback, not an identical old catch policy.

Each session retains at most8MiB of combined output, after which qualification
fails with cleanup attempted. The selected-row comparison excludes sequence
allocation and unlisted relations; PostgreSQL sequence advancement is not rolled
back by business ROLLBACK. The owner must retain and assess those differences in
the complete allocation rather than infer whole-estate equality from this subset.

All schedules retain exact fixture observation, original outputs, lock samples,
selected before/after rows, dependency bytes and input hashes. Local client exits
are followed by a fresh server observation that original backend PIDs and their
locks are absent. That final observer's exit/whole database disappearance needs
independent protected-owner evidence. An unsuccessful cleanup is failure, not a
server-cancellation claim. Runtime evidence has `full_business_qualification:false`
even if the narrow schedule completes; no original alert is resolved here.

Each original client's terminal exit is an independent prerequisite. Any client
cleanup error keeps `clients_verified:false` and prevents overall cleanup success,
even if the fresh database observation subsequently finds no backend or lock.
The final verifier's own unobserved exit also prevents success. Protected negative
controls must cover client-exit failure plus clean server state and the converse.

Database JSON decimal numbers are parsed with `Decimal`, never binary floats;
integers remain integers. Evidence serializes each decimal as the explicit tagged
value `{"$decimal":"<exact decimal text>"}` without rounding. This evidence-only
representation is not written back to the database. Original session transcripts
retain the database's JSON wire text. Unknown non-JSON numeric constants refuse
parsing. Protected qualification must include large-magnitude/sub-cent unequal
numeric controls and verify the evidence tag preserves the original decimal.

## Qualification still required and broader historical gaps

- **Committed cancellation and replay:** the maintained
  `spin-expiry-committed-refund.py` implements this separate final candidate case;
  it still requires an actual successful hosted run. The authentic fixture must
  create and commit genuine entries, then actual cancellation must commit once.
  A separate request replays the stored exact cancellation receipt. Verify exact
  entitlement/tranche/obligation/journal/wallet deltas and no duplicate refund,
  not just `expired` or its estimate. Outer ROLLBACK cannot prove this. Cleanup
  must dispose/restore the whole allocation, never delete immutable money rows.
- **Paid final-seat/draw interleaving:** requires the current authenticated entry,
  live session, request-hook/lease-generation and real draw owner integration.
  Schedule a genuine final purchase while expiry has already scanned its earlier
  candidate, retain actual operation/lock and commit boundaries, then require a
  busy skip or fresh full/drawn refusal with no refund. An already-drawn fixture
  is not that race. This runner does not claim to implement that missing setup.
- **All-booked and busy-candidate contention:** requires genuine booked partial
  boards and actual holder schedules. Quantify the additional G/B contention and
  skipped counts. The one-undrawn-board guard intentionally cannot qualify this.
- **Multi-candidate rollback after a later outer error:** R5 retains its valid
  first-acquisition timeout schedule. A later timeout on the same G/B keys is
  not a reachable contention schedule after this sweep already acquired them:
  `fn_ca_lock_settlement_lane_global` uses transaction advisory locks, acquired
  outside the per-cancellation exception block and retained by the outer
  transaction. Reacquiring those same keys is reentrant, including after a
  caught cancellation failure or a skipped candidate.
  A separate source-supported qualification proposal requires two genuinely
  funded, naturally aged boards with unambiguous created_at ordering and an
  explicit test-owned lock-only holder on the second board's open table row.
  After the first cancellation succeeds provisionally, the second cancellation
  must actually time out on that row inside the catch; the subsequent
  `fn_sync_seat_first_player_count` outside the catch must be observed attempting
  the same retained table lock and escaping with its own timeout. Only that
  observed path plus exact restoration of both boards' financial state proves
  this later outer-error rollback. It requires a separately admitted schedule,
  timeout/resource bounds and full cleanup; a lock-only holder is fixture
  contention, not a canonical financial writer. Alternatively, an explicit
  caller error after real expiry and before COMMIT is a valid narrower control
  for transaction rollback, but does not prove a mid-loop outer-function error.
  Neither later-error control is implemented or qualified by this runner.
- **Full provider closure, financial failure injection, global-lane business
  concurrency, catalog concurrent-drift serialization and whole cleanup** remain
  unverified requirements of the historical broader frozen B plan. The current
  finite release scope is stated in `spin-expiry-lock-order.md`; a narrow hosted
  positive result cannot claim these broader controls passed. No historical
  provider result fills a missing current observation.
