# Diamond accepted-hand jackpot qualification

Run `python3 tests/sql/run-diamond-jackpot-integration.py` with PostgreSQL 17.
`PG_BIN` or `--bindir` selects binaries, never a database URL. The runner creates
an owned private cluster under the checkout parent, binds only a private Unix
socket, confirms `inet_server_addr() IS NULL`, and removes it in `finally`.
`--prepare-only` is diagnostic setup and explicitly produces no verdict.
`--keep` is for manual diagnosis and requires stopping/removing that owned
cluster afterward. The existing SQL acceptance workflow owns CI execution.

Adjacent catalog captures retain exact production function preimages, column
types, generated columns, uniqueness and accepted-hand execution privileges.
The original and repaired twelve-argument wrapper, lease fence, custody/lot
settler, ledger allocator, wallet credit and notification writers run as real
SQL. No financial writer is replaced. Optional accepted roster enrichment may
report unavailable in this focused fixture, as its maintained wrapper allows;
this harness does not certify that separate roster feature or full estate RLS.

The synthetic profiles have explicit initial baseline mint rows. Every new
seat is funded through the maintained reservation writer. The funded Mini
bank is built by eighty-six real accepted player drops; no bank, wallet or
ledger repair is used. This is isolated qualification, never a live financial
probe, production certificate or release action.

Cases reproduce the old accepted-hand refusal, install the exact migration,
and prove compatible/off behavior, scheduled whole drops, invalid price and
board/flop boundaries, atomic Main and Mini credits, exact rounding, horse
inclusion, reserve floor, replay equality, notification preferences, late
failure rollback, registered-supply conservation, reader authentication and
shown-card privacy. Installed migration replay must refuse its preimage. The current published
active cash rake answers also qualify a combined 2,000 rake / 300 drop hand,
500 accrual per payer, exact 150/75/75 bank allocation, and a payout hand with
the same rake. Late failure compares accrual, journal, credit keys, lot
reservations, bank residues and registry rows as well as the accepted state.
